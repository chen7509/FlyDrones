# Future current-byte request contract (not an admitted request)

`request-template.json` and `admission-template.json` deliberately refuse dispatch. The old once plan's 45 bindings remain null. No current Linux tool/library/ABI or measured-data fact has been filled in by software tests.

Production CLI is `python -m tools.benchmark.native_offset_once --execute-once --stage build|run --request <absolute> --sha256 <requestSHA> --review <absolute> --review-sha256 <reviewSHA>`. This syntax was not executed. There is no arbitrary argv, output, retry or fallback option. It uses the fixed existing repository and `results/native-offset-once-attempt-v1/{build,run}`. Stage directory creation precedes firstfacts; a refused stage also cannot repoll under another request name. Consumed means the dispatch boundary was claimed, not proof that a compiler/target actually executed. Removing/renaming those records is not an authorized retry.

The request binds explicit path/resolved/bytes/SHA256 records from the same current files. Current-source, build-input closure and NO_ROS library receipts must be nonempty and hash-bound. The 143 upstream paths must match the frozen prior subtree manifest and the library receipt's source list. Build input groups are tools/system_headers/cmake_modules/link_implicit/libraries/packages. Toolchain, packages, ABI and closure documents are inputs to the applicable review, not cryptographic source authentication or proof merely because their JSON passes. The coordinator's own imported Python dependencies are also part of the external current closure requirement; local explicit entry pins do not establish the entire Python environment or FFI closure.

Build emits the fixed CMake17/O2/parallel1 adapter recipe in one original budget. It records actual steps and cleanup, CMake trace/cache, compile command/system depfiles/object, link/response files and partial outputs. Response expansion is bounded (depth4/65536 tokens), output inventory512 entries/64MiB, individual stable file pin64MiB. Exceeding these conservative limits refuses completeness; it does not enlarge the original runtime/file budgets. Generated CMake files are postbuild observations, not proof of every byte at its earlier read instant. Trace lists executed CMake modules; it is not a syscall read trace of every implicit compiler/linker input. Such implicit inputs still require the predeclared current tool/header/link closure and review; build `complete` is record consistency only.

Run is a separate invocation with a separate stage/request/review binding. It requires complete build receipt, the exact newly produced binary, successful inside/host build completion and observed scope release. A failed/expired/unknown build stage cannot be made successful by an exit0 producer receipt. It also requires the actual production execution/runtime/wire/Agent/reference/gauge declarations, all transitive managed calibration files, a nonzero exact artifact offset and current measured calibration/noise and ELF/Python/SDK receipt declarations. The latter new document schemas are `native-offset-measured-input-v1`, `native-offset-current-elf-closure-v1`, and `native-offset-current-python-sdk-closure-v1`; these must be populated from actual measurements/current artifacts and reviewed, never test fixtures. Current source/ELF/library manifests are not synthesized from historical hashes.
