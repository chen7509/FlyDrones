# PX4 SITL 视觉失效门控验证（2026-09-26）

## 结论

在这组 PX4/Gazebo SITL 试验里，单机和五机的 0 号机遭遇 400 ms 视觉里程计断流时，自主控制器均在视觉帧超过 250 ms 后停止发送新的速度目标、请求降落，PX4 ULog 随后记录到 AUTO_LAND，机体最终落地。**这证明了特定仿真断流下的命令门控和降落时间序列，不证明真实 VIO、实飞安全或降落请求与 PX4 状态转换的因果关系**；试验没有采集 MAVLink `COMMAND_ACK`。

五机可靠性仍未达标。首轮无故障基线中，所有五机的视觉转发曾出现约 287 ms 的共同墙钟停顿，四机被门控，只有 1/5 完成任务；该轮转发器退出异常，严格验收失败。修复转发器退出后，同配置复测 5/5 完成且日志正常收尾；随后四轮时钟、进程和线程诊断基线分别为 5/5、4/5、5/5、4/5，详见 `docs/VIO_RUNTIME_PAUSE_DIAGNOSIS.md`。五机断流轮次中，故障机如预期中止任务并落地；其余四机只有 2/4 完成，未完成的 1、4 号机没有视觉健康失败记录，均因任务超时而落地。因此不能把这轮称为“整队通过”，也不能从单轮推断队友超时由故障机引起。所有失败轮次均保留。

## 固定配置与判定

- 控制器提交：单机三轮和首轮五机基线为 `53e3410904bcc14aec5817d27891076b079fc80c`；修复转发器退出后的五机两轮为 `50f4ff275ded299038e52340031cc400c9747967`。两提交的飞行控制逻辑相同，后者只增加 Gazebo 订阅停止时的回调屏蔽和退订。各轮 `trial-manifest.json` 另有控制器、转发器和入口脚本的 SHA-256。
- PX4 源码提交 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`；同一 Gazebo Sim 8 世界，世界文件 SHA-256 `da3e81c10a7d848671c1045f9da267eca65fd312793231dd99a038f55824e8ad`；同一策略检查点 SHA-256 `3c723587bfdbd15a8dc5976edc13d284b713dc081005b2dac04692c7d1b4accb`。试验期间未训练或修改策略权重。
- 同一 `x500_depth_fly` 机体、PX4 EKF2 和底层姿态/电机控制；自主策略输出速度和航向目标。五机各有独立 PX4 实例和本地策略进程，使用同一五树世界。0 号机在任务开始约 5 s 后关闭 EKF2 GNSS 融合，其他机保持 GNSS；故障仅作用于 0 号机。
- 门控要求 PX4 本地位置、姿态、估计状态及视觉流新鲜；在起飞前、阻塞式起飞之后、每次规划前和发送速度目标前复查。视觉元数据须有递增序号和源时间戳；墙钟样本年龄及传输延迟上限均为 250 ms。发送前还检查规划使用的状态、深度帧是否已经过期。失败后不再发送自主速度目标，并向 PX4 请求降落。250 ms 是本试验的配置阈值，不是从这些结果反推的实飞安全阈值。
- `mission_accepted` 是到达/集合/降落等任务条件；`operational_continuity_pass` 还要求视觉、几何和清理证据。断流门控轮次预期中止任务，不能用运行入口退出码 0 代替任务完成。几何仅按 Gazebo 真值机体中心与树干表面距离判定，不是碰撞认证。

## 冻结配置后的轮次

| 轮次 | 任务完成 | 落地 | 关键证据 | 严格整轮任务 |
|---|---:|---:|---|---|
| 单机无扰动 | 1/1 | 1/1 | 视觉持续、无门控；转发正常收尾 | 通过 |
| 单机 120 ms 延迟 | 1/1 | 1/1 | 实测转发延迟中位数约 121 ms；无门控 | 通过 |
| 单机 400 ms 断流 | 0/1 | 1/1 | 视觉源流最大间隔 420 ms；帧龄 269 ms 时门控，之后无速度目标；AUTO_LAND 在约 15 ms 仿真时间后出现 | 任务中止；故障机门控时间序列成立 |
| 五机无扰动首轮 | 1/5 | 5/5 | 共同转发停顿触发四机门控；转发器未正常收尾 | **失败，保留** |
| 五机无扰动复测 | 5/5 | 5/5 | 转发正常收尾；0 号机 GNSS 关闭后视觉融合连续，未见惯性推算 | 通过一次；未证明稳定成功率 |
| 五机 400 ms 断流 | 2/5 | 5/5 | 0 号机帧龄 251 ms 门控，之后无速度目标；AUTO_LAND 在约 22 ms 仿真时间后出现；1、4 号机任务超时 | **整队未通过**；故障机门控时间序列成立 |

五机断流轮次的 0 号机最后一次自主速度目标在门控前约 51 ms 墙钟时间发出；所有已发送目标在发送时对应的转发帧龄不超过 200 ms。断流注入丢弃 20 帧，转发流最大源时间间隔 420 ms。PX4 ULog 仍记录到约 0.032 s 的惯性推算：门控是尽量在输入过旧后停止命令，不能声称估计器从未退化。五机故障轮次中心间最小距离为 1.668 m、机体中心到树干表面最小距离为 0.545 m，均只是几何代理。

五机基线复测和断流轮次的仿真速度分别约为墙钟的 0.897 和 0.954 倍；0 号机规划器 p95 分别为 16.76 和 14.69 ms。这些数值不包含完整相机成像、真实 VIO、总线、PX4 到电机或机载计算板的端到端延迟。AUTO_LAND 的 15/22 ms 来自仿真时间与 ULog 对齐，并非真实硬件反应时间。

## 证据边界与后续门槛

视觉输入是 **Gazebo 真值里程计经故障转发**，不是深度相机图像与 IMU 算出的 VIO。PX4 当前 Gazebo 桥接器在收到位姿时给 uORB 采样重新打时间戳；即使转发器保留 Gazebo 原始时间戳，EKF2 未必据此计算真实测量年龄。因此本轮专门在自主层用元数据监控墙钟年龄，但这不等于 PX4 融合了正确的原始时间。相机模糊、光照、标定漂移、VIO 跟踪丢失、计算板调度和真实通信延迟均未覆盖。

门控执行后的降落请求和 ULog AUTO_LAND 转换有时间相关性，未采集命令确认；`fault_vehicle_verified_fail_closed_response` 因而仍为 `false`，报告只采用更窄的 `fault_vehicle_gate_land_sequence_observed`。落地、任务完成、连续视觉融合和物理安全是四个不同结论。

下一阶段应先修正和重复五机无故障基线的共享转发停顿，并在多个固定种子下量化成功率；把真实相机+IMU VIO、原始采样时间和 PX4 估计器控制状态接入同一门控，采集命令确认，再重复单机及五机组合故障。只有五机基线和失效处理稳定后，才适合扩大到 20/100 机或进行硬件在环测试。

## 可复核数据

小型每轮 `trial-manifest.json`、`stress-summary.json`、故障配置和大型原始文件哈希见 `docs/results/vio-safety-gate/`。完整 ULog、逐条转发日志、控制轨迹和交互轨迹回放保存在本机 `results/vio-stress/<轮次名>/`，未纳入 Git；仅拿到版本化哈希不能独立重算全部结论。`tools/snapshot_vio_gate_results.py` 可重新生成小型证据副本和哈希索引，`tools/generate_vio_replay.py` 可重新生成轨迹回放。首轮失败五机基线和所有试探性轮次也保留在本机，未从结论中删去。
