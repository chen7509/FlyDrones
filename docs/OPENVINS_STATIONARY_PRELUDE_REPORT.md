# OpenVINS 单机悬停前奏开发诊断（2026-10-03）

**结论：新增 4 秒悬停段的末尾满足离线“低速”门槛，OpenVINS 回放也首次出现少量真实的视觉更新；但初始化发生在悬停段之前，轨迹严重发散，飞行越界，VIO、EKF2 外部视觉融合和安全闭环仍未通过。**这次结果不能证明悬停修复了初始化，也不能作为果蝇策略与 EGO-Swarm 胜负证据。没有改动已封存的 20 个未见评测场景、控制器权重或正式验收门槛。

只在既有单机人工纹理开发世界 1701 上运行一次新 PX4/Gazebo 回合。新命令行参数要求记录 RGB/相机信息，并在 PX4 起飞完成后、策略首次决策之前用原有 `Gateway.advance` 路径发送 80 个零速度/零航向速率目标，50 ms/步；姿态、电机及安全约束仍由 PX4 和既有接口处理。缺省参数为零，不改变正常 runner 路径。场景 JSON/SDF 和两张贴图与上一轮保存的开发夹具逐字节相同。完整果蝇控制器 `fly_raw` 从 33 秒开始工作，其模型哈希仍为 `b6be8b3dd901e2e0893303c04058a110d6e0fb9922a69022b26514efcf06100c`。回合从 29 秒计时，预奏 29–33 秒全部执行，约 37 秒后终局 `out_of_bounds`；采集保存 661 张 160×120 RGB、661 条相机信息和约 19.2 MB PX4 ULog。ULog、逐帧 RGB 哈希、相机内参与计数通过保存清单核验；进程结束后未发现该回合遗留的 PX4/Gazebo/回放进程。约 66 秒的 Gazebo 时钟对应 444.10 秒墙钟，粗略 RTF 约 0.149；这不是实时性能通过。

新增的离线门槛只判定**策略首次决策前最后两秒**的 PX4 EKF2 融合速度小于 0.1 m/s，且相机帧、ULog、有效位、重置计数和时间间隔齐全；它没有评价 OpenVINS 实际初始化时刻，也没有把 EKF2 或 Gazebo 真值喂进 OpenVINS。回放后追查发现静止初始化发生在 26.2 秒，当时 EKF2 仍估计显著运动。[OpenVINS 静止初始化器](https://docs.openvins.com/classov__init_1_1StaticInitializer.html)需要起始静止条件，因此原先的初始化假设冲突并未解决。EKF2 是融合估计，不是独立物理真值；这些数据仍不足以断定哪个单一机制导致后续漂移。

只读复核发现初版 runner 若在预奏中途发生基础设施异常，会把已经完成的步数报告为零。**本次实际采集使用的初版 runner** SHA-256 是 `40759c03090fbf7dd7b68bbf21a765c854cb0d047df4355ec8deff776f5653c1`；采集本身顺利执行满 80 步，这个缺陷没有改变本次原始结果。事后修正版分别记录成功推进与成功评分的步数，并在最后一步采样失败时保留故障状态；相机乱序丢帧也会使离线门槛关闭，即使结果中的接受标记错误。修正版不冒充本次采集时的代码，已保存的原始回合和回放均未重跑。修正版对同一 ULog/RGB 只读再审，`gate-reviewed-v3` 的速度和通过结果与初版相同。

回放沿用 [上游 OpenVINS](https://github.com/rpng/open_vins) 提交 `69488123ed9362dd44b6f28e7f4680abbff1442b`（GPL-3.0）的隔离研究构建、既有 v2 配置、同一个 ROS-free 运行器与离线导出器，各只执行一次。运行器 SHA-256 为 `bf811d145e82a0b70b7eb242349d429e56261212dc5e6986491720b9fd460899`，诊断动态库为 `31e8a063018f256a32fe4027de37c146e49e2a3859a117e897f7eee6339921ae`，配置为 `eaa40224f0de2f4c5b0f1d33504d215670544b9cc000252a0e92f404478360e6`。15,880 条 IMU 和 635 张处于 IMU 时域内的图像输入保留原始时间戳，外参/时间偏移仍是未经实测标定的开发配置。

约 293 MB 的诊断动态库因体积未放入本轮 ZIP；归档包含上游提交、其插桩补丁/构建说明与动态库哈希，能够复核日志和结果，但**仅凭 ZIP 无法重新计算动态库 SHA 或保证逐字节重建**。这限制离线回放的独立可复现性，不影响保存的输出逐项复算。

按插桩日志与状态时间对齐：初始化至预奏前 28 帧有 181 次候选特征窗口尝试、零次三角化成功；预奏内 40 帧有 110 次候选尝试、零次三角化成功；预奏后 330 帧有 989 次候选尝试、25 次三角化成功、23 次卡方接受，对应 16 帧正数 MSCKF 更新。这些“次数”不是互不重复的物理特征。视觉更新仅说明部分量测进入滤波器，**不能覆盖**极大的位置、尺度/速度误差和越界失败。上一轮无预奏开发回放是零次视觉更新、ATE RMSE 65.82 m；本轮路径和时序已改变，且两者都失败，不能把差值解释为预奏的因果效果或算法优劣。

本轮最直接的下一项依赖是让 VIO 的初始化条件真正发生在可核验的静止窗口，再独立校准相机–IMU 外参、时间偏移和噪声并评估可观测运动；不能通过放宽三角化门槛或使用 Gazebo 真值冒充 VIO。只有持续、低误差且带健康/协方差的 VIO 估计成立，才可接入 PX4 EKF2 并注入故障。单机安全门槛未过，5/20/100 机升级、原生 Linux 性能、HITL 与实飞没有因此获得通过依据；当前电脑也未安装原生 Linux。

全量回归第一次运行时，Windows 四进程 UDP 压力测试的一个子进程读取已原子发布的 `start.json` 遇到瞬时 `PermissionError`，没有产生对应 CSV；原始 pytest 临时目录保留该子进程 JSON，单项复跑通过。现为启动信号读取增加最长 5 秒的有界重试，仍以原子替换发布，且聚合器会优先报告子进程错误而非误导性的“CSV 缺失”。相关单元测试覆盖瞬时拒绝、持续拒绝和错误传播。它只修复测试/分布式启动可靠性，不改善本次 VIO 或安全性能。

`evidence/openvins-stationary-prelude-dev-1701.zip` 保留最初采集、审计和回放的 719 文件快照；`evidence/openvins-stationary-prelude-dev-1701-reviewed.zip` 与相邻 SHA-256 索引保留审查修正后的代码/测试、初版 runner 独立副本、插桩补丁和相同的全部 661 张图像、ULog、失败结果、命令、回放日志/状态及逐样本速度。证据目录 `results/openvins-stationary-prelude/` 不被测试覆盖。最终针对性测试 **28 passed**，全量回归 **381 passed、1 warning**（158.34 秒）；警告是既有 Malecns 神经元组无匹配项。Ruff 与 `git diff --check` 通过。测试、代码检查和 ZIP 成员复核只能确认本诊断可复核，不代表 VIO 通过。
