The frozen `study-v5` was dispatched once after three host-free-memory checks above the existing 900,000 KiB reserve and an empty competing-process/container check. It **failed before PX4/Gazebo stepping**: `RuntimeBinding` rejected `declared baseline drift or type mismatch`. Its `capture-v1` has no ULog or sensor frame. The owned worker exited 2, its original process group was empty after reap, and the failure evidence remains at `results/depth-physical-development-preflight-dev-1701/study-v5`. A read-only SHA comparison found five changed WSL library files (`libpng16`, `libXpm`, `libfreetype`, `libpoppler`, `libxml2`), with no missing baseline file. This is an environment-binding refusal, not a fruit-fly or VIO accuracy failure. The first command-line attempt lacked `PYTHONPATH` and failed to import `tools` before dispatch; no v5 output existed then.

The existing preparer produced a separate `study-v6` declaration against the current dependencies, retaining seed 28001, the source study, estimator, body, physics step, sensors, motion, thresholds and safety conditions. It returned 0 with `capture_completed`, no capture errors, 25,000 native-reference cycles, 50,000 physics pre/post records, 6,251 IMU samples, 251 RGB/CameraInfo/depth messages, 24 unarmed heartbeats and 222 public OpenVINS states. One 7,618,511-byte PX4 ULog has SHA-256 `24a5f46b1bb8213b138bdd62b787e91579e8c48fb588d740c10dd716aaef4d05`. The original owned process group was empty after reap, PX4 exited 0, and no matching process remained. The declared runtime files stayed stable and registered PX4/OpenVINS mapping phases passed; whole-OS runtime closure is not claimed.

The independent offline trajectory audit applied the **pre-existing** four-DoF yaw/translation gauge, unit scale, zero time shift and exact-time native-reference matching. Maximum position error was **0.066501 m** (limit 0.25 m), maximum velocity error **0.042514 m/s** (limit 0.25 m/s), maximum attitude error **0.977619°** (limit 10°), and terminal position error **0.019450 m**. Public-state coverage reached 24.9 s with a 100 ms maximum gap. These are development-fixture VIO accuracy screens; Gazebo truth was used only for offline scoring and isolated fixture bounds, never as VIO input or correction.

All 251 raw depth protobufs match their recorded byte lengths and SHA-256 digests. Each decodes as a 160×120 `R_FLOAT32` image with 76,800 pixel bytes; the 251 images contain 3,370,364 finite pixels out of 4,819,200, spanning 0.414703–18.703823 m. There are **54 distinct pixel arrays** after excluding protobuf metadata, so unique protobuf hashes alone would have exaggerated scene variation. This verifies transport, numeric format and retained image content. It does **not** verify obstacle-distance accuracy, camera hardware calibration, alignment to the RGB frame, or depth use by the autonomy policy. The capture lasted 94.436 wall seconds for 25 simulated seconds (approximately 0.265 RTF). The new sidecar and extensive diagnostics add load, and there is no prospectively matched no-depth control, so this is not an isolated depth-overhead or five-camera capacity result.

OpenVINS accepted 6,502 native messages including the single pre-anchor motion intent, and the offline evidence reports source and native health for this run. Its last derived quality was still **0** with `covariance_profile_unqualified`; the native result still has `quality=null` and `reset_counter=null`, and the raw noise model is not hardware calibrated. The trajectory auditor therefore keeps `estimator_health_qualified=false`, `fusion_eligible=false`, and `flight_ready=false`. No ODOMETRY was published, no EKF2 external-vision injection or arming occurred, and no fruit-fly training or open-source head-to-head comparison was performed.
