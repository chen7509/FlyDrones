# Exact-byte ROS build: competing Docker build guard

Date: 2026-10-10. The exact-byte ROS 2 build is still unstarted. The prior preflight at 742,864 KiB remained below its frozen 900,000 KiB host-memory threshold; no `--resume-preflight`, Docker container, colcon build, PX4 or Gazebo was launched in this stage.

The bounded runner already refused visible PX4/Gazebo/colcon/training processes and running Docker containers. A Docker CLI build can consume memory before it creates a running container, but the preflight did not recognize `docker.exe`/`docker` build commands. Two synthetic process-list tests reproduced acceptance of `docker build` and `docker buildx build` with an empty `docker ps`. Two more reproduced acceptance of `buildx bake` and `compose up --build`. The runner now records those identifiable CLI processes as competitors and refuses launch. An idle Docker backend and a `docker ps` command remain noncompetitors.

Independent review found command-shape gaps in the first fix: `compose up --build=true` was missed and `docker ps --format build` was falsely treated as a build. Further counterexamples covered `docker image build`, `docker builder build`, top-level `docker bake`, Docker TLS value options, and Compose `--ansi`/`--progress`/`--parallel` options. Each gap was reproduced before correction. The final checker identifies the top-level Docker action and the relevant `buildx`/`compose` subcommand, skipping recognized global/project options. It accepts `--build`, `--build=true` and `--build=1` as build intent, while `--build=false` is not a competitor. Installed Docker CLI help confirmed the supported command forms without starting a container; see the [Docker CLI reference](https://docs.docker.com/reference/cli/docker/) and [image build reference](https://docs.docker.com/reference/cli/docker/image/build/).

This is a process snapshot of identifiable `docker` CLI commands, not an atomic reservation of host resources. It cannot prove that no Docker daemon-side build exists without a visible CLI process, that no build starts after the snapshot, or that memory will remain above the guard during compilation. The original source/image pins, 259-file verifier, container CPU/RAM/PID/network bounds, one-time resume reservation and 1,800-second timeout are unchanged. A future build must still run its own immediate preflight and retain its source, generated type, exit and cleanup evidence. The previous CRLF build remains unqualified.

The initial four build-command cases failed before the change and passed afterward. Review counterexamples also failed before correction and passed afterward. A final independent read-only review found no Critical or Important issue. The final adjacent and prior runner/source-verifier suite passed **31 tests**; changed-file Ruff and `git diff --check` passed. This stage only validates the resource guard; it does not produce a compiled ROS type, owned PX4/DDS/ULog source, VIO fusion, policy training or a fair drone comparison.
