# 项目阶段与漂移审计

日期：2026-09-27

审计对象：`codex/vio-faults` 分支、总路线图、五机 PX4/Gazebo 证据、相机错峰实验、训练与对照实验文档。

## 审计结论

项目没有进入真实 VIO、HITL 或实飞阶段。当前准确位置是：

> **总路线图阶段 0 尚未正式关闭；阶段 1 已有部分传感器与时序基础设施，但未通过；正在实施“现实 VIO 替换”实施包 A 的前置仿真容量诊断。真实相机 + IMU VIO 本体尚未接入。**

现阶段可以继续做五相机持续渲染容量诊断，因为它用于确定阶段 1/实施包 A 的仿真基础设施是否足以承载真实 VIO 输入。但不得把该诊断称为阶段 2 已开始，更不得进入 HITL、实飞或扩大规模。

## 发现的漂移

### 1. 路线图分支漂移：已修复

总路线图提交 `6affe41` 原先只存在于 `codex/curriculum-training`，当前 `codex/vio-faults` 从共同祖先 `491b1b4` 后独立演进，没有包含路线图文件。实现工作虽然参照了另一个工作树中的路线图，但当前分支自身无法还原这一约束来源。

审计期间只将该纯文档提交带入当前分支，生成提交 `09d22c3`。没有合并训练分支的代码或结果。

### 2. 渲染证据语义漂移：已识别，结果已纠正

先前五机 D3D12 正式轮全程 RTF 为 `0.9501～0.9607`，稳态为 `0.9807～0.9958`。这些轮次的渲染证明在每路收集 11 帧后停止订阅。Gazebo 会停用没有订阅者的渲染传感器，因此这些结果证明的是渲染器身份和短时出图，不是五路深度相机持续运行能力。

最终相机错峰开发轮持续订阅五路图像，每路 186～187 帧，RTF 为 `0.5266`。相机频率和相位通过，但五机 PX4 起飞门槛失败。`CAMERA_PHASE_STABILITY_REPORT.md` 已将整套结论标为 `rejected`，没有用短时证据覆盖持续运行失败。

### 3. 实施范围横向扩张：存在，但仍属于必要前置工作

“现实 VIO 替换”尚未接入开源 VIO。当前分支先后处理了视觉流故障门控、ULog 证据、PX4 命令确认、OFFBOARD 连续设定值、渲染后端、起飞执行器链和相机时序。这些工作都能解释为真实 VIO 前的基础设施门槛，但十次相机阶段修订说明原 Python 观察架构已经接近继续试补的边界。

因此后续不再继续修改超时、频率或安全门槛，而是执行已批准的四单元容量分解。它是根因诊断，不是新的策略训练或 VIO 功能扩展。

### 4. 验收门槛漂移：未发现

- 相机仍为 160 x 120、`R_FLOAT32`、每机 10 Hz。
- 五机相位仍为 `0/20/40/60/80 ms`。
- p95 相位误差和相邻间距误差仍不超过 8 ms。
- PX4 起飞期限仍为 12 秒，没有因慢速仿真延长。
- 正式运行 RTF 门槛仍为 0.95。
- 策略权重、动力学、任务、安全监督器和 PX4 内环没有为通过实验而放宽。
- 版本化配置哈希测试通过；相机快照索引测试通过。

### 5. 证据等级漂移：未发现新的错误声明

当前报告持续声明：定位输入是 Gazebo 位姿真值经故障中继形成的外部视觉替身，不是由图像和 IMU 求出的 VIO。现有结果属于 PX4 SITL + Gazebo 物理仿真；没有 HITL、机载计算板或实飞证据。

### 6. 工作树漂移：受控

当前 Git 跟踪文件无未提交代码修改。`results/` 下存在未跟踪原始运行目录，它们是故意保留的 ULog、CSV、JSONL 和控制台证据；紧凑摘要和 SHA-256 索引已经提交。原始目录不得被误加到 Git，也不得在完成归档前删除。

## 当前子阶段

当前子阶段命名为：

**A0：五相机持续渲染容量与观察边界诊断。**

这里的 A0 属于总路线图“实施包 A：现实 VIO 替换”的前置条件，不等于阶段 0 已通过，也不等于已开始训练 VIO。目标只是回答：在当前 WSL/D3D12 主机上，五路真实持续深度流的瓶颈来自 Python 观察边界，还是来自持续渲染/Transport/环境容量。

后续固定顺序为：

1. 为已批准的容量规格编写实施计划。
2. 实现原生 C++ 观察器和四单元、三重复容量试验。
3. 若三次 `native-5` 全部达到 RTF `>=0.95`，才替换正式相机辅助链并重跑一次五机开发门禁。
4. 若任一次 `native-5` 低于 0.95，停止当前主机上的生产集成，转向原生 Linux/GPU 环境实施包。
5. 阶段 0 正式关闭并解决持续相机容量后，才开始至少两个开源 VIO 候选的正式选择和图像+IMU接入。
