# EGO 因果关联离线契约（开发阶段）

固定上游静态审计已说明：`PositionCommand.trajectory_id` 只命名轨迹，不给出规划实际使用的里程计或已应用的深度帧。本阶段新增纯 Python `EgoCausalJoin`，用独立会话的观测、地图更新完成事件和规划记录做严格关联。成功关联仅返回数据身份及 `teacher_qualified=false`，不会启动控制、记录训练标签或改变 EGO/PX4。现有桥接与旧对照证据保持原样。

## 具体门禁

- 观测需有严格递增的序号、仿真/相机/里程计时间、深度/里程计/相机位姿和标定摘要，并显式声明 `px4_ekf2`、`calibrated_rgbd`、健康且未使用真值。**这些声明尚未经运行时生产端证明**，所以不能授权教师标签。
- 地图事件必须标记实际更新完成；其源序号、深度摘要、相机位姿摘要、帧时间必须匹配已记录观测。单纯收到图像不足以加入地图事件。
- 规划记录需关联当时可见的里程计摘要、已完成地图修订与源序号；创建时间不得早于这些输入。起始状态另需明确标为来自里程计，或来自本会话中已登记的上一轨迹。**可见里程计不等于重规划实际使用的起始状态。**原始轨迹号必须为正且在固定 C++ `int` 范围内，与中间存储号完全相等，且同一会话不可复用。
- 指令只能按会话、轨迹号和当前观测与规划记录关联。`PositionCommand` **没有**轨迹开始时间或输入 ID；验证器不虚构它们，也不把指令 header 时间当作规划输入时间。新观测到达后的旧轨迹指令、跨会话同号、缺记录、乱序、缩窄别名、非有限数或异常额外字段均拒绝。

该契约保守地要求当前观测的可见里程计与最近完成的地图帧具有同一源序号。固定 EGO 的异步规划可能经常不满足这一条件；普通控制参考仍可经原安全监督器处理，但不能借此称为当前帧的教师标签。进一步核对固定源码发现 `ego_replan_fsm.cpp:643-645` 在初次规划时从里程计赋予 `start_pt_/start_vel_`，而 `672-674` 在重规划时从上一条轨迹采样位置、速度和加速度；因此新契约另记 `start_state_origin` 和本会话 `parent_trajectory_id`，不能把最新里程计直接称为重规划起点。当前纯验证器尚无实际起点数值或上一轨迹采样证明，始终不能授权训练。地图有积累历史，本模块也尚未记录完整修订窗口。未来上游插桩必须实际记录起点来源、采样时间、地图窗口与每次应用的输入身份，不能将本模块的合成字段当作上游已经产生的证据。

## 验证与边界

先记录了目标模块缺失的 RED；补齐摘要绑定和数值边界后又记录 RED→GREEN。第一版合成验证为 25 项针对性、67 项相邻测试通过；发现重规划起点来源差异后新增 RED→GREEN 两项，当前为 27 项针对性、69 项相邻测试通过，改动 Ruff 通过。初版已封存于 `ego-causal-join-dev-1701.zip`；修订后的证据另作 v2，不覆盖旧包。固定上游三个头文件依据提交树 blob ID 抓取并复算 Git blob 哈希；本阶段未修改或构建 ROS/C++ 上游，也未启动 Docker、PX4、Gazebo、OpenVINS 或训练。宿主当前空闲内存约 1.75 GiB，仍低于完整 MaleCNS 的既有 4 GiB 门槛。

状态：离线严格关联逻辑**仅实现并通过合成测试**；真实上游只读插桩、二进制/type-support 身份、原版数值等价、非真值 PX4/相机生产端、单机物理教师语料和公平基线结果均**未验证**。下一步按现有[计划](superpowers/plans/2026-10-10-ego-causal-provenance.md)为固定 EGO 构建独立版本的只读诊断插桩，先在开发场景验证真实消费链及旧轨迹拒绝，再考虑资源门槛允许的物理采集。历史失败、五机相机 0.873 RTF 不达 0.95 和未完成的 VIO→EKF2 闭环保持原状态。
