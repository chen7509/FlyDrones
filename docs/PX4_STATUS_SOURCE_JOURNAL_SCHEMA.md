# PX4 EstimatorStatus source journal schema (offline draft)

The independent status collector will write `flydrones.px4_estimator_status_cdr.v1` JSONL, separate from every historical odometry journal. This schema and the Python auditor currently have synthetic tests only. They do not verify live PX4 provenance or decode parity.

Each sample records the fixed `/fmu/out/estimator_status` topic, `px4_msgs/msg/EstimatorStatus` type, pinned message SHA-256 `44cba4424c224753b8249729e9bf7e530d0b34e04d5299fcf94f2677c8f50bd5`, run ID, contiguous journal sequence, RMW implementation/GID, optional RMW sequence and source/receipt timestamps, callback steady nanoseconds, both PX4 publication and delayed-state sample microseconds, the four status flag masks, horizontal/vertical accuracy, seven innovation ratios with seven explicit availability booleans, five reset counters, bounded CDR hex and CDR SHA-256. Unavailable nonfinite innovation ratios are encoded as JSON `null` with availability `false`, never as zero. This is a decoded projection; the CDR remains the authoritative bytes pending an independent ROS deserializer check.

The auditor requires exact row keys, bounded lines and CDR, strictly increasing PX4 and callback times, sample time no later than publication, stable GID/implementation/run/reset counters, and explicit terminal completion or failure. A sample-time jump greater than 100,000 µs terminates this strict source-continuity journal; that is a predeclared diagnostic refusal, not a PX4 health or flight limit. A `fault` row retains bounded offending CDR where possible. The session ends fail-closed on source replacement, reset, rollback, duplicate, malformed status, or incomplete/failed terminal. A DDS sequence gap is recorded only as a DDS reader observation; upstream PX4/Agent loss cannot be inferred from it.

The `timestamp - timestamp_sample` result is **publication-to-state delay**, not wall-clock state age. State age needs a separately evidenced PX4-to-steady-clock map and cannot be inferred from fresh arrival. The auditor always returns `live_source_authenticated=false`, `upstream_loss_qualified=false`, `fusion_qualified=false`, `camera_calibration_qualified=false`, and `training_eligible=false`. A publisher GID alone does not authenticate a PX4 process.

An independent typed C++ collector source and package now implement this envelope without editing the historical odometry package. **Its C++ source is not yet compiled or exercised.** Next: derive and seal a separate source tree, then compile and run synthetic callback/CDR parity and I/O fault tests in a newly declared bounded offline container. Actual firmware publication and unarmed receipt remain separate, resource-gated work.

For the schema/auditor stage, the first new-module test run failed at collection and the first importable stub run had 43 behavioral failures (one Windows symlink-permission skip). After implementing the auditor, the new and adjacent historical odometry auditor suites passed **83 tests with one symlink-permission skip**; changed Python Ruff and `git diff --check` passed. These tests use synthetic JSON/CDR envelopes, not an independent CDR deserializer or an actual ROS callback. The C++ source is deliberately reported as **implemented but uncompiled** until the next stage.
