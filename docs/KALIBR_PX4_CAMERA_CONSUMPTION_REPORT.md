# Operational Kalibr artifact consumption (software only)

The PX4 camera production API/CLI can now apply a byte-bound Kalibr-format artifact to diagnostic camera poses and state lookup. It applies the inverse IMU-to-camera transform and signed camera-to-IMU time offset, retaining original frame timestamps and all original refusals. The separate point-projection API applies pinhole/radtan intrinsics/distortion. **No genuine Kalibr solve, measured own-rig artifact, actual ULog/native/PX4 capture or calibration qualification occurred.** This completes a production-interface dependency, not spatial/time calibration of the aircraft.

The new `KalibrCameraArtifact` reads an exclusive selected bundle's exact SHA-bound camchain YAML and result TXT. The bundle binds current rig SHA/body/camera and explicitly declares the virtual `px4-d6f12ad-sensor-combined-frd-interval-mean-v1` IMU contract; a raw device-IMU artifact is refused instead of silently interpreted as body FRD. These identifiers and TXT bytes are **unverified caller assertions**, not measurement-process authentication or quality evidence. YAML must contain1–8 cameras, selected pinhole/radtan parameters, a proper4x4 transform and matching resolution; anchors/aliases/duplicates fail. Each document is capped64KiB; directories must be controlled/static and in-process reflection or hostile concurrent replacement is outside this portable boundary. Bounds are per document, not aggregate I/O or certified peak memory.

The existing producer has an optional `calibration_artifact` argument; existing CLI has paired `--calibration-artifact/--calibration-sha256` arguments and snapshots exact bundle/references under inputs/calibration before consumption. Previous default output fields and behavior are unchanged; no previous real exporter or cached native study was rerun. When enabled, original health/sample/reset audits remain mandatory. Shifted timestamp state selection runs the **same**100ms state/sample,2s flags,50ms skew and reset gates, combining both sets of refusals. Neither an offset nor a supplied artifact can rescue a previously refused PX4 row. Diagnostic geometry uses shifted selected position/attitude and inverse T_cam_imu; original source rows remain original, with shifted indices/publication/sample separately retained in calibration_lookup.

The decimal time-offset literal is retained. Exact comparison enforces the supported1s magnitude before rounding; nanoseconds use half-even rounding with recorded decimal rounding error, preserving integer timestamps above2**53. Original ULog/image timestamps are never rewritten, nearest-matched, interpolated, dropped or silently resynchronized. A shifted time outside boot range produces a per-row explicit refusal with the original timestamp/audits, while other rows continue. Metadata distinguishes parameters loaded, lookup-applied/refused frame counts and pose-applied frame counts; it does not claim loading equals full application. The pose-only CLI loads/reports intrinsics/distortion and **does not invoke point projection**. Projection is a separate production API for explicit3D point callers; only constructed point tests called it this phase. All source/clock/measured calibration/training/flight qualifiers remain false, receipt remains null, and no Observation/CaptureInputEvidence/publisher or control gate is bypassed.
