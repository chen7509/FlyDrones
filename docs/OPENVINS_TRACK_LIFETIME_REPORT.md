# OpenVINS 起飞前特征 ID 寿命诊断（2026-10-04）

**结论：PR #26 所见的 9/9 半窗合格轨迹，直接对应前端补点函数每帧保留 9 个长期 ID、淘汰另 9 个上一帧 ID 并补入 9 个新 ID。**在预解锁的 40 帧中，KLT 和 RANSAC 对 720 个输入全部放行，720 个最终都写入特征库；因此这段数据的主要流失发生在下一帧匹配之前的 `perform_detection_monocular`，不是 KLT 或 RANSAC。当前日志尚未区分该函数内部的边界、近邻栅格或掩码剔除原因，也未证明修复。

## 固定输入与来源

沿用 [PR #25](https://github.com/chen7509/FlyDrones/pull/25) 封存的唯一 PX4/Gazebo 单机采集及 [PR #26](https://github.com/chen7509/FlyDrones/pull/26) 半窗审计：608 张 RGB、15,203 条 ULog IMU；输入 manifest SHA-256 `dfea7a901eb5894be1f09c77c1f371f9022ac7cdc510979e6bdd1b66b7c3ca5e`，runner `bf811d14...`，配置 `eaa40224...`。本阶段没有重跑物理仿真、训练或飞行控制器。预解锁窗口为 15.618–19.642 秒，对应 40 张处理图像；这属于开发场景，不是冻结后的未见测试集。

基于 [OpenVINS 固定提交](https://github.com/rpng/open_vins/tree/69488123ed9362dd44b6f28e7f4680abbff1442b) `69488123ed9362dd44b6f28e7f4680abbff1442b`（GPL-3.0），在独立源码副本上依次应用前两轮初始化计数补丁和本轮 `TrackKLT.cpp` 只读补丁。官方 [TrackKLT API](https://docs.openvins.com/classov__core_1_1TrackKLT.html)及 [ICRA 2020 论文](https://pgeneva.com/downloads/papers/Geneva2020ICRA.pdf)说明了 KLT 稀疏特征前端与 VIO 背景。GitHub 2026-10-04 查询显示仓库未归档、最近推送记录为 2025-11-30；此事实不等于上游为本项目配置提供支持。没有引入新的前端或更改 15/15 初始化阈值。

隔离库 SHA-256 `a13296b877333646065851e61831df7eba380829052f3962bd12e78501e9b319`，大小 292,811,280 字节，由 Ubuntu g++ 13.3、OpenCV 4.6.0 构建；`ldd` 核对 runner 解析到该库。一次固定输入离线回放退出码 0，墙钟 7.72 秒、峰值 RSS 67,148 KB。新状态 CSV 与 PR #26 完全相同，SHA-256 均为 `1ccb4cd2eb55294e5130f052800d0bf83a962538ecba68c00c97e28c22af8975`。这验证保存状态的字节奇偶，不保证额外日志对所有线程时序完全无影响。

## 逐级计数

审计器严格解析 608 个单目帧、前端各级计数和逐 ID 写库日志；二次审计还逐项核对 608 个时间戳与原始 `frames.csv` 顺序相同、无重复，并要求 PR #26 的 254 次可计数初始化尝试时间唯一且能与前端帧配对。预解锁 40 帧的逐帧中位数及总数如下；`audit-v2/frames.csv` 保留所有帧，`id_lifetimes.csv` 保留所有写库 ID：

| 前端阶段 | 逐帧中位数 | 40 帧总数 |
|---|---:|---:|
| 上帧 ID | 18 | 720 |
| 补点函数保留上帧 ID | 9 | 360 |
| 补入新 ID | 9 | 360 |
| 送入 KLT / KLT 成功 | 18 / 18 | 720 / 720 |
| RANSAC 成功 / 两者共同通过 | 18 / 18 | 720 / 720 |
| 最终写入数据库 | 18 | 720 |

该窗口共有 **369 个不同写库 ID**：**9 个 ID 各写入 40 次，另 360 个 ID 各只写入 1 次**。于是数据库 ID 总数会增长，但能横跨两个初始化半窗的轨迹仍只有少数。PR #26 在同一窗口独立读到旧/新半窗合格数均最多 9，固定门槛 15/15；两个日志视角数值相符。不能把总写库 720 次称为 720 条独立长轨迹，也不能把 `perform_detection_monocular` 的流失直接归因于图像纹理。固定上游代码在此阶段依次检查边界、近邻栅格和掩码，随后补点；本次没有分别计数这些条件。

## 验证界限与下一依赖

解析器的合成日志测试覆盖正常、首帧、缺失/重复 ID、畸形行、阶段数量不守恒、相机错配、时间倒退及原始帧时间序列错位，先 RED 后 GREEN。新旧审计合并的针对性测试 **20/20**、Ruff 已通过。设置当前工作树 `src` 为 `PYTHONPATH` 后，最终完整回归为 **544 passed、2 条既有警告**（209.86 秒）。警告分别来自重复 ZIP 成员的刻意拒绝测试和 Malecns 缺失神经元组。首次直接运行全套测试时，环境中另一 FlyDrones 可编辑安装导致 41 个导入收集错误；不能将收集错误描述为代码功能失败。

本包将保存补丁、构建/命令/退出码、原始 stdout/stderr、状态、资源、逐帧与逐 ID 表、配置/输入哈希及报告；约 293 MB 的隔离库仅以哈希和构建命令标识，不并入仓库。下一项应在同一保存图像上分别计数 `perform_detection_monocular` 对已有 ID 的**边界、近邻栅格与掩码**淘汰，确认 9 个一次性 ID 的具体去向，再提出单变量开发修正。任何后续前端修正须重新验证状态、初始化时间、PX4 EKF2 闭环和飞行安全；现阶段原物理飞行仍 `out_of_bounds`，VIO→PX4 融合、5/20 机、HITL 和实飞仍未验证。五机 WSL2 容量约 0.873 RTF，低于 0.95 门槛，此轮未改变。
