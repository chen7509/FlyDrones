# Fixed XRCE Agent: bounded offline WSL build

The fixed Micro XRCE-DDS Agent v2.4.3 built successfully in Ubuntu WSL with Ninja, GCC/G++ 13.3.0 and one compile job. `configure.exit=0` and `build.exit=0`; the bounded build ran from 2026-10-11 23:56:49 to 2026-10-12 00:08:19 China time, under a 1,500-second wall limit. The resulting `MicroXRCEAgent` SHA-256 is `ded56cf545394670effaf112c642d62e8dd0e7145e53a6c9b0593014b721fcfe`. This verifies a **local binary build and bounded startup/usage path**, not a PX4/DDS publisher, authenticated sensor producer, EKF2 fusion or flight.

The [design](superpowers/specs/2026-10-11-agent-offline-build-design.md) and [plan](superpowers/plans/2026-10-11-agent-offline-build.md) used the previously audited [direct dependency objects](PX4_AGENT_DEPENDENCY_OBJECTS_REPORT.md) and [Fast-DDS gitlinks](FAST_DDS_GITLINK_OBJECTS_REPORT.md). A new isolated Linux object store gave the nine distinct repository URLs fixed local Git targets. Unmapped HTTPS was rejected with `fatal: transport 'https' not allowed`; an exact Fast-DDS URL resolved to commit `575d045…`. The new Fast-CDR staging store contains **both** the Agent direct commit `757d5e4…` and the different Fast-DDS gitlink `1bc9c91…`; a deliberately wrong object was rejected. The sealed bare stores were not modified. The Micro-CDR store had only the audited commit, so the build-only local `v2.0.1` tag is an explicit alias to `3d1b177…`, **not** a claim to possess the original upstream tag object.

The build-owned Agent source has the same 214 file paths as sealed `source-v4`; per-file SHA-256 comparison shows exactly one changed file, `cmake/SuperBuild.cmake`. Its four added CMake arguments force Fast-DDS to the fixed Asio and TinyXML2 submodules, use the separate fixed Fast-CDR 2.2.0 installation, and disable submodule update. The full diff and both file hashes are retained. No upstream source file or historical evidence was overwritten. The direct XRCE Client, Micro-CDR, Fast-CDR, Fast-DDS, foonathan and spdlog checkout IDs, plus all four Fast-DDS submodule IDs, match the fixed object audits.

Actual nested Fast-DDS CMake output and cache select the fixed Asio and TinyXML2 submodule directories, the separately built Fast-CDR 2.2.0 and foonathan installation, bundled Boost headers, and Ubuntu OpenSSL 3.0.13. Agent's own CMake selection uses Ubuntu's TinyXML2 configuration; this is separate from Fast-DDS's fixed TinyXML2 selection. The generated `libfastrtps.so.2.14.7`, `libfastcdr.so.2.2.8`, Agent library and executable were linked successfully. The dynamic loader also needs host `libstdc++`, `libc`, `libssl`, `libcrypto`, `libm` and `libgcc_s`; this is **not** a portable binary for arbitrary Linux hosts.

Bare `MicroXRCEAgent --help` printed usage but exited 1 because no transport was specified. `MicroXRCEAgent udp4 --help` exited 0. A separate `runtime-bundle.tar.gz` includes the executable and its five locally built shared-library families. It was extracted to a different directory, resolved those five libraries from that extraction via `LD_LIBRARY_PATH` with no unresolved dependencies, and passed bounded `udp4 --help` there. The original binary retains a RUNPATH to the temporary build; consumers must use the bundle's library path or deliberately relink for deployment. No Agent listener, PX4, Gazebo, OpenVINS or training process was started for this check.

Three preparation failures are retained. V1 tried to clone a shallow pin-only bare store with no HEAD and obtained an empty repository. V2 fixed that by staging named refs but found the sealed Micro-CDR store lacked the build-required tag ref. V3 imported all fixed objects but ran a Git check from WSL's invalid view of the Windows worktree `.git` pointer. V4 uses a Linux scratch directory and the explicit tag alias; no failed attempt was silently relabeled as passing. The top-level `--help` exit 1 is retained separately from the successful transport-specific usage check.

The evidence package `evidence/agent-offline-build-dev-1701.zip` has 51 members, SHA-256 `75705de8b27b3204335a6f57ec0aa01193005a475b6be049e4b3d48759132a34`; all archived members passed ZIP CRC and per-member SHA-256 verification. It contains scripts, source comparison, source commits, selected CMake caches, complete build log, failure notes, binary/library hashes, dynamic-link output and the runnable bundle tar (bundle SHA-256 `4a5a104380bd320f87a3e1df1db4007287a4be4102d8ac511187ce69dd55596b`). The independent audit confirms those bounded facts and deliberately leaves `px4_dds_publisher_authenticated=false` and `vio_to_ekf2_fusion_verified=false`.
