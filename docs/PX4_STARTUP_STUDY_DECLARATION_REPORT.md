# 分阶段 PX4 启动试验清单接入（2026-10-10）

此阶段推进 [启动门禁计划](superpowers/plans/2026-10-10-px4-startup-phase-gate.md) 的任务 4，补齐正式试验清单与已实现的 `capture-wire-startup-v2` 采集配置之间的断点。原 `live_wire_study` 清单校验只接受 `capture-wire-v1`，因此新配置即使通过采集器本身的校验，也无法被前置的清单和文件哈希校验接受。

现在清单校验可显式接受 v2，并要求从 PX4 spawn 起算的 `startup_max_wall_ns` 为严格整数、范围 `(0, 60 s]`。会话 ID、零时钟原点、清单中的配置文件身份与哈希、实际执行命令、25 s / 1 ms / 250 Hz IMU / 10 Hz 160×120 RGB-D 负载和其余门槛仍需逐项一致。v1 仍按原精确格式校验；新增字段或改变原时钟/端点都不能被忽略。通过清单只表示**离线声明可核验**，返回的 `live_qualified` 和 `fusion_qualified` 仍为 `false`，不会生成捕获结果或授权发送消息。

测试先在 v1-only 校验器上观察到 v2 文件适配失败（`mismatched wire clock`），修改后相邻 95 项通过。独立只读复核没有发现阻断项；它指出原无效上限测试仅改动配置一份副本，可能由后续绑定不一致偶然拒绝。测试随后同步改变配置与执行声明，临时移除上限检查时四个无效输入均明确失败，恢复检查后五个针对性用例通过。最终全库测试使用仓库 `src` 作为 `PYTHONPATH`，**4400 passed、38 skipped、4 warnings**；改动文件 Ruff 与 `git diff --check` 通过。首次未设置 `PYTHONPATH` 的全库尝试在收集阶段出现 74 个 `flydrones.benchmark` 导入错误，原日志保留，它不是断言失败，也不能计入通过数。

本轮仍**没有**生成和冻结新物理 study manifest，也没有运行 PX4/Gazebo、TIMESYNC、VIO 或训练。资源快照显示 Windows 空闲内存 786,788 KiB，低于现行 4 GiB 试验门槛，未发现相关 PX4/Gazebo/OpenVINS 进程；固定 WSL socket 路径虽存在，先前只读 `ss` 未见监听者，但其归属和启动前占用仍需在实际试验前重新确认，不据此删除。封存的 v10 首次 TIMESYNC 未发布失败及五机相机 0.873 RTF < 0.95 仍为失败。

**已验证：** v2 离线清单/文件校验、严格上限拒绝、v1 回归和无授权状态。**仅实现：** v2 真实采集接线及其可被清单接受的声明路径。**未测试：** 新 study 的完整 runtime 冻结、真实 PX4 启动、500 个 TIMESYNC 接受样本、基线恢复、25 秒物理轨迹与 VIO→EKF2 闭环。下一步需在独立 study ID 下前置冻结完整资源、配置、源身份、socket 占用处理和失败保留规则；只有宿主资源满足门槛且无竞争进程时才允许一次未解锁物理开发试验。不能回填或覆盖 v10。
