# Owned PX4 ULog and camera artifact association interface

Implemented, software verified; actual Linux descriptor duplication and new PX4 capture are untested. This production capture interface closes the missing *recording path* between an explicitly owned PX4 child, the ULog inode it has open for writing, preserved ULog bytes, and the final camera/event artifacts from that capture. It does not establish measured spatial/time calibration or sensor source authority.

`--record-owned-ulog` requires the existing declared `source-diagnostic-v1` logger and owned Agent/wire capture context. The execution contract freezes the option, max256 fd entries, max8 log identities, max64 observations, a1s simulated sampling interval and64MiB **per artifact** hash-read cap. Worker forwarding and actual spawn/stepping/prestop/post-collection hooks are implemented. The unchanged25s capture uses1ms physics,250Hz IMU and10Hz160x120 RGBD; no speed, accuracy, RTF, safety or memory admission threshold was reduced. A future physical run needs a new frozen study/load declaration; old sealed studies are not amended.

The observer registers only the actual PX4 `Popen` after its cleanup has been installed. PID/start_ticks/pgrp/session/executable and declared executable SHA bind the owner. It enumerates only that PID's descriptors, witnesses regular `.ulg` files inside the new controlled private runtime, and compares source device/inode. It samples after a stepping batch at most once per simulated second, plus immediately before owned PX4 termination. Any observation failure latches refusal, discards partial new witnesses, and cannot prevent the existing owned-child stop. Exclusive owner/observation files are retained.

Independent review identified a race in combining procfs stat with separately read fdinfo flags. The corrected Linux x86_64 adapter uses `os.pidfd_open` and libc `syscall438(pidfd_getfd)`, then obtains `fstat` and `F_GETFL` from the **same duplicate open file description**. It does not read/write/seek/change flags on the shared description and closes both newly allocated local handles. Denied permission, unavailable API or unsupported architecture refuses the capture; there is no racy fallback or privilege change. The Ubuntu x86_64 header declares438; the persisted header and architecture observation is explicitly post-implementation, while the earlier tool-only read is not backfilled. No actual pidfd_getfd syscall was executed in this stage.

After PX4 exits, the original collector preserves all ULogs first. The sidecar then requires every collected log to have an owned writable-opener witness **and every witnessed log to survive collection**, checks source inode and source/copy bytes against the collector's SHA/size, and binds final RGB manifest, CameraInfo, event journal and ULog manifest bytes. Failure retains the original copies and writes refusal evidence before the capture is marked failed. CameraInfo and manifest hashes are artifact association, not calibrated camera/IMU geometry or proof of image contents or sensor causality. All source authentication, sole-writer, sensor generation time, clock epoch, measured calibration, fusion/training/flight fields stay false.

The directory must be controlled and static for post-exit reads. Path/stat/open checks do not defend against an adversarial concurrent namespace replacement, arbitrary in-process monkeypatching, or another writer with the same inode. Sampling is incomplete between observations and may miss a short-lived log; absence refuses qualification rather than fabricating a witness. The64MiB cap bounds individual reads, not aggregate I/O or certified process peak. Ptrace access may deny pidfd duplication even for an owned child: actual host permission/usability remains pending. The adapter is currently Linux x86_64 only. It grants no state validity, reset/heading health, clock calibration, LOCAL_NED authority, landing proof, or source authentication.

Research used [Linux procfs descriptors](https://man7.org/linux/man-pages/man5/proc_pid_fd.5.html), [fdinfo access/status flags](https://man7.org/linux/man-pages/man5/proc_pid_fdinfo.5.html), [pidfd_getfd duplicate semantics and ptrace permissions](https://man7.org/linux/man-pages/man2/pidfd_getfd.2.html), and [PX4 logger documentation](https://docs.px4.io/main/en/dev_log/logging). Existing local PX4 source d6f12ad1/BSD3 and Python/MIT are reused; no installed package, firmware, ROS, calibration tool, native consumer or algorithm byte was changed. Syscall research is metadata only, not a repeat kernel lifecycle experiment.
