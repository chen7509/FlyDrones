# EKF2 航向对齐成对开发探针（2026-10-03）

**结论：在同一固定开发世界、同一当前 PX4 二进制和相同 4 秒零速度悬停命令下，低高度回合的悬停窗口 `heading_good_for_control` 为 0/494，高高度回合为 493/493。** 稀疏 EKF2 状态中，`cs_mag_aligned_in_flight` 分别为 0/5 和 4/4。这个成对结果支持高度相关的磁航向最终对齐机制，是针对先前 0/604 张 RGB 帧通过完整 EKF2 健康门槛的原因定位；它不证明 1.5 m 是唯一因果阈值，不代表视觉里程计已接入，也不是果蝇策略的任务成功率。

## 解释与限制

上游 PX4 这个版本的 `EKF2.cpp` 使 `heading_good_for_control` 依赖 `isYawFinalAlignComplete()`；在磁航向控制路径上，最终对齐要求空中磁对齐完成并持续一段时间。高高度回合在悬停前出现空中磁对齐，悬停阶段切换到 `cs_mag_3d` 并持续给出适合控制的航向；低高度回合持续为 `cs_mag_hdg`，无空中磁对齐。两次 `dist_bottom_valid` 都为假，所以现有日志不能直接确认 EKF 使用的离地高度或把代码中的 1.5 m 检查归为已证实的唯一因果链。起飞时间、轨迹和传感器观测也随目标高度改变；每个高度仅一次独立运行，没有重复性或阈值扫描证据。

探针没有运行果蝇策略、相机帧对齐或 VIO 测量注入；PX4 来源标志 `cs_ev_pos` 在两次悬停状态中均为 0。Gazebo 真值只用于评分碰撞和边界，不作为策略控制里程计。故不能据此放开“真实 VIO 替换”、学习数据采集、正式未见测试集或 5/20 机扩展门槛。历史纹理任务仍是 `out_of_bounds`，其 0/604 帧健康结果保持原结论。WSL2 仿真性能也不能据此归因于果蝇策略。

下一步应先把这个 EKF2 航向条件作为明确的安全门诊断项，与高于门槛且已校准的实际飞行高度/可靠高度来源配套验证；随后让相机数据经过真正的 VIO 和 PX4 外部视觉输入，在保留 EKF2 拒绝、延迟和故障日志的单机闭环中重新审计帧级健康。只有这一门槛通过，才可将完整果蝇策略接入并继续逐级评测。
