# PX4 ROS 2 full-odometry source journal, development stage

This stage adds an opt-in, read-only v2 journal for the fixed PX4 `VehicleOdometry` type. It retains seven complete decoded geometry and variance arrays beside the original serialized CDR, RMW publisher metadata, PX4 timestamps, reset counter and the existing fail-closed terminal record. Four-argument execution and historical v1 journal semantics remain unchanged. The Python reader audits v1 and v2 separately and permits a v2 geometry projection only for **offline analysis** with an explicitly provisional PX4 session and instance. Neither the journal nor the geometry projection authenticates an owned PX4/Agent source, calibrates the camera, establishes CDR-to-field parity, admits training data, or grants fusion.

The frozen interfaces are PX4 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4` and official `PX4/px4_msgs` `148bdb4b8214a4d8de83029777fe8d334c74db6f` (BSD-3-Clause), whose `VehicleOdometry.msg` Git blob is `cf117ff82cdbf191bf576db91db900b7ce34f6a7` and file SHA-256 is `a528b3d0b4c1a9083a71b32c367bad71a900e959efd82b9d03a9eb0e99fe6017`. The implementation reuses the installed ROS 2 Humble typed `rclcpp` callback and CycloneDDS interface from the pinned `fly-ego-benchmark:humble` image, plus the existing Python causal camera adapter. This adds no new runtime transport and costs one bounded JSONL row per callback. The fixed upstream repositories and official semantics were reviewed in the [PX4 message](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/msg/versioned/VehicleOdometry.msg), [PX4 ROS 2 guide](https://docs.px4.io/main/en/ros2/user_guide), [uXRCE-DDS guide](https://docs.px4.io/main/en/middleware/uxrce_dds) and [pinned px4_msgs tree](https://github.com/PX4/px4_msgs/tree/148bdb4b8214a4d8de83029777fe8d334c74db6f). `quality=0` is an unused field in this fixed PX4 publisher, never a health grant. The v2 float arrays retain nonfinite coefficients as JSON `null`, which the offline geometry extractor rejects.
