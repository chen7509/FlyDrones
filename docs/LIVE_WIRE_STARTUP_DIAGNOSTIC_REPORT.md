# PX4 启动观察与采集执行绑定（2026-10-09）

**结论：独立诊断执行入口已实现并在假采集器及 WSL POSIX 文件系统上验证；尚未准备或执行 v7 物理研究。** 上次 v6 缺首个 TIMESYNC 的原因仍未知，原始 2 秒/8 秒门槛仍失败。

`observe_px4_startup.py` 现在只在确认 `px4.log` 不存在后发出就绪信号。新的 `live_wire_startup_runner.py` 等待该信号才调用原采集 runner；它保存采集 runner 的原返回码或异常，同时保留观察器独立状态、错误、线程退出、选中研究及诊断声明摘要和缺失标记。`runner_invoked=true` 仅表示调用过 runner，不能证明 OS 已启动 PX4。无日志也仍为无日志，观察到的文本时间仍只是宿主首次可见时间。内部失败不变成启动成功，诊断摘要恒为 `qualification_granted=false`。

`execute_live_wire_startup_diagnostic.py` 用独立声明固定原研究清单 SHA、观察器和协调器源码 SHA、固定 60 秒观察/5 秒就绪上限及三个准确路径。声明本身以调用时指定的摘要选择，并有限读取普通文件；符号链接、重复 JSON 键、额外成功字段、清单/源码/路径/期限漂移和已存在的输出均在调用原 owned wire executor 前拒绝。原 executor 继续管理一次激活请求、资源检查、dispatch、采集和 completion；新入口不修改 PX4 参数、启动脚本、机体、传感器或 wire 的 2 秒/8 秒门槛。

纯声明和假采集器测试验证了就绪顺序、旧日志拒绝、缺日志、采集异常、原返回码保留、错误字段/摘要/期限拒绝。Windows 的符号链接创建受权限限制，相关用例跳过；WSL POSIX 单独证明了符号链接声明在启动前被拒绝、假采集只在观察器就绪后运行，以及重复输出拒绝。所有这些都是**接口验证**，没有实际 PX4/Gazebo、EGO 教师、ODOMETRY、EKF2 注入、解锁或训练。
