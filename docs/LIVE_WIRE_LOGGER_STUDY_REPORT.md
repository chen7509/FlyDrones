# PX4 diagnostic logger live-wire declaration (2026-10-12)

`live-wire-study-v3` binds the opt-in PX4 `source-diagnostic-v1` logger to a distinct, prospective single-machine study. This stage validates the declaration and its one-attempt entry; it did **not** run PX4, Gazebo, OpenVINS, the Agent, training, or an EKF2 injection. The added logging load is diagnostic and does not count as the earlier capacity workload.

The v3 manifest retains the v2 owned Agent and the frozen 25 s, 1 ms physics, 250 Hz raw IMU, 10 Hz 160×120 RGB-D, motion, safety, source and timeout requirements. It changes the development seed to 27603 and requires exact records for the canonical logger topic file and profile. Its execution contract pins both SHA-256 values, the `PX4_PARAM_SDLOG_PROFILE=0` child override, the inventory and baseline, and the new `--logger-diagnostic-profile source-diagnostic-v1` argument. The v1/v2 file sets and commands remain unchanged. File-adapter validation checks the current repository's canonical logger profile; the read-only auditor performs the same check and leaves source, record-chain, live and fusion qualification false.

The v3 entry now checks observed **host** free memory against the existing 4 GiB physical threshold before recording an activation request and immediately before dispatch, after declaration and resource revalidation. On Windows it uses `GlobalMemoryStatusEx`; from WSL it queries Windows free physical memory rather than WSL's assigned memory. A failed or unknown observation refuses. The first observation is recorded in the request; a later drop leaves that request and no dispatch. The version decision comes from the already validated command, and the manifest identity is checked again after revalidation to close a schema-change race. This is a sampled gate, not a reservation of RAM after dispatch. Observed host free memory fell from about 2.5 GiB to 2.13 GiB during this stage, so no physical attempt was made.

The initial v3 test failed because the validator did not know the new schema. A file-adapter test later exposed an out-of-date synthetic baseline, which was rebuilt from the exact test inputs. Independent review found a missing serialized-file happy/drift test and a missing executor memory gate; both were added. A second review found a race between declaration revalidation and a fresh schema read; a regression now changes the manifest in that interval, and the final code rejects it before dispatch. The first broad regression ran while that Python source was being edited: its repository-source freshness check correctly failed, so it is retained as an invalidated run and repeated after the source was fixed. The surviving command logs and review findings are retained with the evidence; initial RED assertions are described here rather than presented as complete raw logs.

The stable adjacent selection reported **138 passed, 1 skipped** in 322.40 s. The earlier invalidated selection reported 136 passed, 1 skipped and the source-freshness failure. Five final v3 entry tests passed separately. Changed-file Ruff and `git diff --check` passed. Independent review found no remaining reproducible Critical or Important issue after the race fix. This is targeted and adjacent regression, not a claim that the entire repository test suite passed.
