# Synthetic PX4 odometry DDS/CDR parity: sixth attempt

The pinned ROS 2 collector received **one synthetic** `px4_msgs/msg/VehicleOdometry` sample, and an independent deserialization of the recorded CDR matched all seven array fields and six scalar fields. This resolves the earlier *synthetic callback/parity* evidence gap. It does **not** authenticate a PX4 publisher, involve an XRCE Agent, prove `logger_topics.txt` selection or `vehicle_odometry` in a new ULog, qualify a VIO source, or establish EKF2 fusion or training eligibility.

The [narrow retry design](superpowers/specs/2026-10-10-px4-synthetic-sixth-attempt-design.md) and [execution plan](superpowers/plans/2026-10-10-px4-synthetic-sixth-attempt.md) retain the original v1–v5 directories. The new selector requires v5 `status=preflight_failed`, `started=false`, no `launch.json`, integer `free_kib`, the exact frozen 900,000 KiB minimum, and measured free memory below that minimum before returning the new v6 path. One new test first failed because the selector was absent. Independent review then found that a falsified higher recorded minimum could qualify a retry; another regression failed as expected before the exact-minimum check was added. The final run passed 10 selector tests and 25 targeted/adjacent tests. The initial RED invocation had a missing `PYTHONPATH` import failure before the corrected, expected one-test failure. Ruff on changed Python files and `git diff --check` passed. The original preflight gate and Docker CPU, memory, network and timeout limits were unchanged. This post-run selector hardening did not alter the real v5 record or any v6 launch behavior; the synthetic container was not rerun.
