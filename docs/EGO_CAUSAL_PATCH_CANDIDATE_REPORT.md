# Fixed EGO causal diagnostic patch: static candidate

Date: 2026-10-11. This is a development-only, read-only instrumentation candidate against EGO-Swarm commit `23a8d5a191711dd65633df689bd00f55d4dea8f9`. The original checkout remains unchanged. The patch is a derivative of the GPL-3.0 upstream code and is kept separate from the unpatched benchmark image.

## Result and boundary

The 10-file patch `tools/benchmark/ego_causal_readonly.patch` is byte-bound to eight original Git blobs and adds two diagnostic files. Its SHA-256 is recorded in `patch-manifest.json`. It applied to an isolated copy of the pinned source with `git apply --check` and `git apply`. A small native C++ test compiled the shared diagnostic writer against WSL g++ 13.3.0 and OpenSSL 3.0.13; SHA-256, escaping, invalid session, unwritable path, and two-DSO shared sequence `1,2` passed. This is **not** a ROS build, a trajectory-equivalence result, an online timing result, or a qualified teacher source. `patched_ros_build_verified`, `trajectory_numerical_parity_verified`, and `teacher_qualified` remain false.

The patch records depth and pose receipt separately from a completed occupancy update. It logs applied map revision, image/pose serialized digests, relevant timestamps and source kind. It records whether an initial start state came from odometry or a replan start came from the previous trajectory, including parent trajectory identity and sample time. It also records published B-spline identity and the separate trajectory server's received B-spline and emitted command identities. The writer uses one `plan_env` shared-library implementation per process, a session ID, PID, monotonic local sequence, and append-locked JSONL. Missing or corrupt logs must cause the later bridge verifier to reject a teacher label.

This is intentionally not a direct feed into `EgoCausalJoin`. The C++ map receive sequence is independent of the bridge observation sequence; an adapter must join exact image/pose digests, source timestamps, session and runtime identity before supplying the verifier's observation sequence. Plans using the odometry-pose depth callback also depend on an extrinsic callback that is not yet bound here, so that route remains unqualified. Any nonzero cloud mutation requires its own source proof. Serialization failures yield an empty digest, which must be rejected. The diagnostics add hashing and disk I/O; they have not yet been measured for observer effect or numerical parity. The journal is append-locked, not `fsync` durable and not a security boundary against a hostile process. Cross-process command linkage still needs actual ROS runtime evidence.

## Dependency decision

The selected one-shot `SHA256()` API is documented by [OpenSSL 3.0](https://docs.openssl.org/3.0/man3/SHA256_Init/); the same page identifies the Apache-2.0 license and distinguishes the deprecated incremental `SHA256_Init` family. WSL has OpenSSL 3.0.13 and `libssl-dev` usable by g++; the pinned ROS container's development headers, linker inputs and binary identity have **not** been verified. The patch uses `find_package(OpenSSL REQUIRED)` and links `OpenSSL::Crypto`. The [ROS rosdep base rules](https://github.com/ros/rosdistro/blob/master/rosdep/base.yaml) were checked for the `libssl-dev` key rather than treating the `openssl` command-line package as headers. The observed rules are mutable upstream metadata, not a frozen container installation record. [Humble `rclcpp` serialization source](https://github.com/ros2/rclcpp/blob/humble/rclcpp/src/rclcpp/serialization.cpp) supports the intended serialized-message path, but the candidate has not compiled against the exact Humble image or custom EGO message type support. Reusing ROS serialization and the installed crypto library is lower adaptation cost than designing an independent wire digest implementation; it adds a package and build dependency. No upstream maintenance claim beyond the versioned source and metadata in earlier audits is needed for this static stage.

## Verification and next gate

- Isolated patch application: passed; original upstream HEAD and clean status checked after application.
- Native diagnostic core and shared-library test: passed. These tests do not compile the map, FSM or trajectory server.
- ROS package build, type-support compilation, patched binary/dependency hash, runtime sessions and numerical equivalence against the unpatched planner: **untested**.
- Bridge adaptation of independent source sequences and exact cross-process causality, physical input capture, and teacher eligibility: **untested**, and eligibility remains false.

The host had about 0.92–1.04 GiB free RAM during this stage while unrelated Python regression tests were already running. A new Docker ROS build or PX4/Gazebo run would compete for resources, so none was started. Once resources permit, build the patch in an isolated container, freeze the patched executable and message type support, run deterministic patched/unpatched trajectory parity, and only then attempt a new owned single-drone development capture. Retain old v6 TIMESYNC and five-camera 0.873 RTF failures; neither measures fruit-fly learning quality.
