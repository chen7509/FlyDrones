# OpenVINS 克隆相机运动与 PX4 EKF2 参考对照（开发世界 1701）

**结论：OpenVINS 实际用于视觉特征三角化的短窗口相机平移，与同一飞行 PX4 EKF2 位姿推导的平移在方向和尺度上明显不一致；相对旋转则较接近。** 在 183 次清理后的特征窗口尝试中，独立射线求解器使用 OpenVINS 克隆位姿得到 167 次非正深度、16 次正深度；使用 EKF2 参考得到 5 次非正深度、178 次正深度。OpenVINS 本身仍是零视觉更新。这是同一份开发数据上的离线诊断，不能把 EKF2 位姿叫作真值，也不能宣布 VIO 或 PX4 EKF2 视觉融合已经通过。

本轮在独立的上游 OpenVINS `69488123ed9362dd44b6f28e7f4680abbff1442b`（GPL-3.0）检出上，只增加每个观测所对应克隆相机位姿的日志。其 [ClonePose 定义](https://docs.openvins.com/structov__core_1_1FeatureInitializer_1_1ClonePose.html)明确 `R_GtoC` 是全局到相机的旋转、`p_CinG` 是相机在全局的位置；[FeatureInitializer](https://docs.openvins.com/classov__core_1_1FeatureInitializer.html)使用这些位姿三角化。原有图像特征日志也保留。仍重播相同的 604 张 RGB、PX4 ULog IMU、离线适配器和配置，没有启动新的 PX4/Gazebo 仿真，也没有改果蝇策略。重播状态 CSV 的 SHA-256 仍为 `f0f1966527c80bc49a5d219053a3e9c282aeb04eab7439dccd0fe3d265f8740f`，与未插桩运行逐字节相同；183 次候选中的 **1001/1001** 个图像观测均匹配到唯一克隆位姿。首次插桩编译因上游 `ClonePose::Rot()/pos()` 成员函数不接受 `const` 对象而失败，改为非 const 引用后构建和重播成功；失败没有产生可用重播数据。

脚本对相同时间戳的 EKF2 姿态、NED 位置沿用上一轮的有效位、重置和 20 ms 插值缺口检查，以及冻结的相机外参。克隆日志 SHA-256 固定为 `d330736bc6c4f9236edc33389584cea01452af3c524ac331aa144fae6699bf8f`；参考三角化逐条复算，状态、原因、基线、深度、条件数和重投影误差均与上一轮 CSV 比较，无差异。相对旋转、首帧相机坐标系内的首末位移方向、首末基线长度不依赖两个系统的全局原点或共同刚体朝向，无需对齐或尺度拟合。两套轨迹都不是独立地面真值；EKF2 可能包含模拟 GPS 等误差。对同一个归一化图像观测，分别用两套位姿运行同一个独立的射线最小二乘求解器，不能直接等同上游 OpenVINS 的三角化实现或阈值。

两套位姿的首末相对旋转差中位数 **0.108°**（第 90 百分位 0.539°），平移方向差中位数 **161.0°**（第 90 百分位 166.7°），基线长度比中位数 **15.76**。预先规定的时间中点 42.9 s 前有 67 次尝试，中点后有 116 次；后半段基线比中位数 **19.25**，方向差中位数 **163.3°**，表明平移分歧持续并扩大。全部 183 次短窗口都可评分；完整逐条数据保留负深度、离群值及状态。上一轮上游记录的 178 次线性失败中，167 次深度低于 0.1 m；本轮独立求解恰有 167 次非正深度，但当前日志没有把每条三角化拒绝与特征 ID 配对，**不能声称这 167 次逐条相同**。

下一项单独假设应检查 **PX4 `sensor_combined` IMU 量测经离线适配器进入 OpenVINS 的坐标轴、加速度符号、单位、时间戳与初始化状态是否与其传播模型一致**。这是由“旋转相近、平移方向几乎相反且尺度随时间扩大”推断出的优先排查方向，尚非已证明根因。应先用保存的 IMU 与 EKF2/相机短窗口做只读一致性检查，记录每条变换，再考虑任何参数修正；不能通过放松视觉门槛或把 EKF2/ Gazebo 位姿喂给 OpenVINS 来制造通过结果。相机–IMU 动态时间偏移和惯性噪声仍未完成真实标定。

`evidence/openvins-clone-motion-dev-1701-reviewed.zip` 保存原始克隆日志、插桩补丁、逐次 CSV、汇总 JSON、版本和哈希索引；前轮纹理证据包已保存原始 RGB/ULog，本包按哈希引用它。约 293 MB 的诊断共享库不并入 Git，精确哈希和字节数保存在元数据。所有结果属于开发数据离线诊断，不是正式未见场景对照、五机容量门槛、HITL 或实飞。离线重播耗时约 19.9 秒，不等于机载推理时延或实时闭环性能。

最初从轨迹几何分支直接跑完整项目回归得到 **339 passed、1 failed、1 warning**：失败仍是已定位的 UDP `start.json` 空读竞态，原始 `agent-2.json` 已保留在证据包。随后把已审查的独立修复 [PR #13](https://github.com/chen7509/FlyDrones/pull/13)作为本诊断分支的依赖，不修改任何 VIO 数据或评分，再跑完整回归得到 **343 passed、1 warning**（182.70 秒）。警告是既有 Malecns 数据的神经元组无匹配项。克隆/几何针对性测试 **17 passed**，Ruff 与 `git diff --check` 通过。

审核中发现旧证据包的回放退出码文件仅有换行；新版包已根据当次 `/usr/bin/time` 的 `Exit status: 0` 与命令返回码补写为 `0`，不改变原始日志、状态或评分。
