# PX4 estimator-status firmware build executor protocol

The isolated PX4 `d6f12ad` source and EstimatorStatus DDS candidate remain unchanged. This stage adds a **candidate one-shot build executor**, not a compiled firmware result. Its last read-only admission observed Windows available memory 3,227,664,384 bytes, below the frozen 4 GiB minimum; WSL available memory was 7,394,267,136 bytes, disk free 995,456,999,424 bytes, the process scan was complete with no competitor, and the result path did not exist. The runner refused before scope or build dispatch. Earlier two-phase observations at 2.182/2.170 GiB and later refusals are retained separately. No PX4, Gazebo, OpenVINS, Agent or training run was started in this stage.

The executor requires two fresh source/resource admissions with matching source facts. Before creating a result directory it checks an unused nonce-named scope and WSL result path, rejects unexpected tracked, untracked or ignored files and an existing `build/` tree, then hashes ten selected compiler/build/launcher executables plus the EmPy and PyYAML entrypoint files against frozen installed identities. If admitted, it would create an exclusive evidence directory and dispatch the absolute `/usr/bin/make -j1 px4_sitl_default` through a scope with `MemoryMax=4G`, `CPUQuota=100%`, a 90-minute inner timeout and a separate 90-minute host deadline. The build receives a cleared environment with fixed `/usr/bin:/bin` PATH, disabled ccache and Git protocol fetch, and no `PX4_UXRCE_DDS_NS`. The runner records the command, launcher, scope cgroup/limits/peak, stdout/stderr and selected toolchain hashes before and after. Cleanup binds the scope's invocation ID to the active sample or the exact unit line in its launcher stderr, refuses to stop a scope without that identity, rechecks identity before TERM and KILL, and inspects the scope even if the Windows launcher already exited. Any forced cleanup is a failed execution, not a successful build. A separate binary/generated-header audit remains required; no path grants `firmware_compiled_verified`, live authentication, fusion or training authority.

Harmless WSL probes verified a two-second named scope's active cgroup/member and subsequent disappearance; a TERM-resistant short probe exercised exact-unit stop, retained non-graceful cleanup, then reset only that probe unit. A command-prefix probe ran harmless Python under the revised cleared environment and observed the fixed PATH, absent PX4 namespace and disabled Git protocol. A network-scope probe showed `IPAddressDeny=any` in systemd's active property, but a localhost connection yielded `ECONNREFUSED`, so enforcement is **not** qualified and the build command does not claim network isolation. Git protocol fetch is disabled, but the selected six submodules have not been proven to cover every offline build dependency. No probe compiled firmware.

The revised code adds refusal/cleanup tests for those cases; 74 focused and adjacent tests pass, changed Ruff and `git diff --check` pass, and real installed toolchain and pristine-tree snapshots match the narrow frozen checks. A final-record disk failure is returned in the CLI JSON with `final_record_persisted=false`, but cannot be called durable evidence.
