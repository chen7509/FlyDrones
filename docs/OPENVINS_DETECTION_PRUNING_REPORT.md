# OpenVINS 单目旧角点淘汰原因诊断（2026-10-04）

**结论：在固定开发输入的预解锁 40 帧里，前端每帧淘汰的 9 个旧 ID 全部走了上游 `perform_detection_monocular` 的图像边界分支。** 该窗口共有 360 个只写库一次的 ID，逐 ID 对账表明它们全部在写库后下一帧（0.1 秒）被 `edge` 删除。此次只加日志、没有改变检测或初始化逻辑，状态 CSV 与前两轮逐字节相同。这是离线开发回放中的代码路径诊断，**不是** VIO 初始化、PX4 闭环或自主飞行成功证明。

## 输入、上游与执行边界

复用 [PR #25](https://github.com/chen7509/FlyDrones/pull/25) 封存的同一次 PX4/Gazebo 单机输入：608 张 RGB 图像、15,203 条 ULog IMU；输入 manifest SHA-256 `dfea7a901eb5894be1f09c77c1f371f9022ac7cdc510979e6bdd1b66b7c3ca5e`。复用 [PR #27](https://github.com/chen7509/FlyDrones/pull/27) 的 runner（SHA `bf811d14...`）、配置（`eaa40224...`）、预解锁窗口 15.618–19.642 秒、254 次可配对的初始化尝试及上一轮状态 SHA `1ccb4cd2...af8975`。没有新起 PX4/Gazebo、没有训练、没有改变 15/15 初始化门槛或测试场景。

上游固定为 [OpenVINS `69488123ed9362dd44b6f28e7f4680abbff1442b`](https://github.com/rpng/open_vins/tree/69488123ed9362dd44b6f28e7f4680abbff1442b)，许可证 GPL-3.0。其 [TrackKLT API](https://docs.openvins.com/classov__core_1_1TrackKLT.html)和 [ICRA 2020 论文](https://pgeneva.com/downloads/papers/Geneva2020ICRA.pdf)提供算法来源。本轮使用隔离的 ROS-free 上游源码副本，依序应用此前三份计数补丁和 `openvins_detection_pruning.patch`；后者仅输出每个旧 ID 的淘汰原因、坐标及每次检测的汇总。继续复用既有接口；不引入新跟踪器，适配成本仅为约 293 MB 的隔离编译库和审计器。没有将 GPL 源码合并进本项目 MIT 飞行栈。2026-10-04 GitHub 查询显示上游未归档、最近推送记录为 2025-11-30；此信息不保证后续维护。

隔离库由 Ubuntu g++ 13.3、OpenCV 4.6.0 构建，大小 292,818,728 字节，SHA-256 `413e6adf693e3e5adff7ec66ced28fe641bb5312f009bd79219336188b5548e3`。保存的 `ldd` 结果确认 runner 加载了此库。一次离线回放退出码 0，墙钟 8.06 秒，峰值 RSS 68,292 KB；`states.csv` SHA-256 `1ccb4cd2eb55294e5130f052800d0bf83a962538ecba68c00c97e28c22af8975`，与上一轮完全相同。字节相同只证明保存的估计器状态未变，不证明额外日志对所有线程时序均无影响。

## 逐帧、逐 ID 证据

审计器要求每条内部检测汇总与随后的一条 `FD_KLT_FRAME` 按调用顺序配对，严格核对原始 608 张图像时间序列、254 次唯一初始化时间、旧 ID 来源、五个互斥剔除原因与输入/留存数守恒。完整的 `frames.csv` 与 `drops.csv` 包含所有帧和所有淘汰 ID，不只筛出成功样本。

| 范围 | 旧 ID 输入 | 留存 | 新补入 | 边界删除 | 近邻碰撞删除 | 其他三类删除 |
|---|---:|---:|---:|---:|---:|---:|
| 预解锁 40 帧 | 720 | 360 | 360 | 360 | 0 | 0 |
| 608 帧全回放 | 逐帧见原始表 | 逐帧见原始表 | 逐帧见原始表 | 3,055 | 60 | 0 |

预解锁窗口的 369 个不同写库 ID 中，9 个各写入 40 次，其余 360 个各写入 1 次；这 360 个一次性 ID 均在下一个 0.1 秒检测调用中有同一 ID 的 `edge` 日志。注意“预解锁窗口内有 360 次 `edge` 删除”和“窗口内的 360 个一次性 ID 都在下一帧被删除”是两个单独核对的命题；窗口最后一帧的一次性 ID 可在窗口外下一帧删除。上游这一分支用转换为整数的像素坐标与距图像边界 10 像素的规则比较。原始记录含诸如 `(8.516, 5.514)` 和 `(150.475, 61.450)` 的坐标；在 160×120 输入上它们与该边界规则相符。当前证据没有证明这些点靠边是由纹理、相机标定、视场、表演目标板位置或图像压缩中的哪一项造成。

## 验证与下一步

解析器合成日志测试先 RED 后 GREEN，覆盖正常配对、提前返回、缺失/重复 ID、未知原因、计数不守恒和时间错位。原始回放的 608 条检测汇总、每条淘汰记录与状态哈希均通过严格审计。定向测试 **29/29**、Ruff 通过；完整回归 **553 passed、2 条既有警告**（219.59 秒）。警告分别来自重复 ZIP 成员拒绝用例和 Malecns 缺失神经元组。独立只读复核重算了 360/360 下一帧 `edge` 删除、608/608 时间配对和状态、补丁、上游库哈希，未发现改变核心结论的缺陷。构建命令、补丁、完整源码 diff、`ldd`、原始 stdout/stderr、资源、退出码、逐帧/逐 ID CSV 和逐文件哈希在封存包中可复核。库体积约 293 MB，仅保留哈希及重建命令，不随仓库归档。

下一项开发试验应先在现有图像上衡量**内区角点的可持续数量与空间分布**，再只改变一个可控因素（例如开发目标板在相机视场中的占比或前端检测 ROI），比较 15/15 半窗计数、初始化、计算延迟和完整轨迹。直接放松初始化门槛或把靠边特征强行保留都不能当作已验证修复。原 PX4/Gazebo 飞行仍有 `out_of_bounds`；VIO→PX4 EKF2 融合闭环、故障注入、5/20 机、HITL 和实飞仍需独立证据。五机 WSL2 性能基线约 0.873 RTF，低于 0.95 门槛，此轮未触及。
