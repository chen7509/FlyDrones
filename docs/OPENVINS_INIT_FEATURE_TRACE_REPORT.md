# OpenVINS 初始化特征追踪：开发场景 1701

**结论。** 已有 4 秒预解锁静止窗口满足 RGB/IMU 时间连续性和 PX4 EKF2 低速检查，但固定 OpenVINS 在这 40 张图像对应的每次初始化尝试中，跟踪器特征库均为 **0**，最新可用特征时间为 `-1`。因此本次没有形成静止初始化所需的两半时间窗视差统计。特征库直到仿真时间 28.3 秒才首次非零，29.8 秒才有 18/18 条轨迹通过两半窗口的 15/15 数量门槛；离线 runner 在 30.3 秒的相机行首次观察到 `initialized=1`。这是 **单机 PX4/Gazebo 开发场景的原始采集加离线 OpenVINS 诊断**，并非 PX4 接收 VIO 的闭环成功，也不是正式陌生场景通过。

## 方法与可复核输入

- 上游为 [rpng/open_vins](https://github.com/rpng/open_vins) 的 `69488123ed9362dd44b6f28e7f4680abbff1442b`（GPL-3.0）。固定配置和输入、前一次回放的来源记录在 [预解锁报告](OPENVINS_PREARM_STATIC_REPORT.md)。本次从固定提交创建独立 WSL 检出，只给 `try_to_initialize` 和 `InertialInitializer::initialize` 增加结构化日志；[补丁](../tools/benchmark/openvins_init_feature_trace.patch)没有修改控制流、阈值或估计状态。上游[静止初始化文档](https://docs.openvins.com/classov__init_1_1StaticInitializer.html)与[固定源码](https://github.com/rpng/open_vins/blob/69488123ed9362dd44b6f28e7f4680abbff1442b/ov_init/src/init/InertialInitializer.cpp)说明初始化判据。
- 重用同一批 650 张可用 RGB、16,254 条 PX4 IMU、同一 v2 配置、同一 runner 和原始机载数据；没有喂入 Gazebo 位姿真值。库 SHA-256 `532ae57a6a952a0137cc1de291bc47ad556d419c7524fbb23b7a90c00addab5b`；编译器 Ubuntu g++ 13.3.0，OpenCV 4.6.0。实际命令、依赖哈希、构建复核、原始 stdout/stderr、状态、逐帧审计和视觉角点探针均封存在[审查后证据压缩包](../evidence/openvins-init-feature-trace-dev-1701-v2.zip)，SHA-256 `caaaef214d38bc03de15ba26916523e1c72e85024bdef971a5d3bea1cb8fbb7e`，22 项，69,467 字节；[索引](../evidence/openvins-init-feature-trace-dev-1701-v2.index.json)。原始 v1 证据包仍保留。原始 RGB/ULog、配置和 runner 的完整副本仍在前次已审阅证据包中，避免重复封存；本包中的 manifest 给出精确 SHA。
- 只执行一次新的离线回放，退出码 0。新 `states.csv` SHA-256 `e69af3be567e4f80345bf7e079130f55de5127246824bc46103658ea55fe1e9b`，与无本次日志的原回放 **逐字节一致**。这支持“日志没有改变 runner 看到的估计输出”，不证明库内部所有并发时序都等价。日志有 273 个 `FD_INIT_FRAME` 和 273 个成对 `FD_INIT_DISP`；[审计器](../tools/benchmark/audit_openvins_init_feature_trace.py)按相机时间戳与 278 行首次初始化前状态对齐，允许异步初始化线程导致的 5 行无新尝试。独立审查发现早版解析器会跳过截断日志，已改为遇到畸形 `FD_INIT_` 行立即失败，并补充回归测试；同一原始日志在严格解析器下仍为 273 对。

**图像侧交叉检查。** 预解锁 40 张 RGB 的文件哈希只有 1 种，符合静止相机观察到恒定场景。使用 OpenCV 4.6.0 在原始灰度与直方图均衡后图像上运行 FAST、阈值 20：18.0 秒图像分别有 5/11 个角点，28.3 秒为 4/43，29.8 秒为 24/84。该轻量探针与早期特征不足方向一致，但没有执行 OpenVINS 的网格、遮罩、KLT 和跨帧存活规则，**不能把角点数等同于 OpenVINS 轨迹数，也不能单独断言根因是纹理**。40 张相同图像也不等于传感器停发；原采集时间戳与 IMU 连续性已在前次审计核对。

`ready` 在日志中仅表示两半轨迹数满足各 15 条，不表示静止/运动视差、IMU 静止条件或整个初始化已通过。OpenVINS 初始化在线程中执行，29.8 秒触发尝试，runner 直到 30.3 秒的图像行才观察到完成状态；不能把 0.5 秒直接解释为算法纯推理延迟。前次 368.08 米离线 ATE 和任务越界失败仍然有效，本诊断没有修复它们。原始 PX4/Gazebo 约 0.152 RTF 的 WSL 慢速仿真只描述平台吞吐，不能归咎于果蝇策略。

## 下一门槛

先在**独立开发场景**检验相机在预解锁位置是否能够看到充足、跨帧存活的纹理（例如固定外部纹理目标或相机可视区域），保持机体参数、相机内外参、OpenVINS 阈值和安全监督不变，并记录原始 RGB、特征轨迹和静止门槛。此诊断尚未证明哪一种场景调整有效。仅当离线估计、时间标定和 PX4 外部视觉接入均通过，再进行单机闭环与故障注入；正式未见场景不得据此调参或删除失败。五机、二十机、HITL 和实飞仍未由本阶段验证。
