Execute inline with systematic-debugging/TDD and existing autonomous authorization. This is a bounded repair of the existing frozen fair-baseline runner/report workflow, not a new benchmark, model, simulator or low-level probe.

The current batch runner skips any existing result.json after only reading status; it can mistake another job/freeze or a nonterminal state for a consumed attempt. The report consumer checks freeze but not result seed/controller versus the requested pair. Introduce a shared read-only result check: mapping, exact integer seed equal to the requested job, exact controller string equal to the requested job, identical freeze SHA, and one of the six existing terminal statuses. Failed terminal episodes are consumed and never retried. All existing results are checked before any new batch launch, so a later invalid record cannot permit an earlier pending job to start. Newly produced results receive the same check before bookkeeping; report ingestion reuses it. No invalid file is deleted, edited or retried.

Alternatives: silently skip unmatched records destroys failure accounting; rewriting their metadata invents evidence. Refusing with the original files intact is the required behavior. A matching self-declaration does not authenticate process identity, source health, ULog, real runtime consumption, complete MaleCNS training or fair physical conditions. Existing freeze/file and ULog checks remain independent. This does not qualify the legacy Gazebo-truth comparison as the original trusted-source benchmark. Frozen historical inputs and tests remain untouched; no new formal random seeds are generated.
