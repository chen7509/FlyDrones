# OpenVINS 延迟输入诊断执行计划

**目标：**在不重跑飞行、不调 VIO 的条件下，用同一保存回合检验从静止预奏开始的相机/IMU 输入是否改变初始化和轨迹结果。

**边界：**开发世界 1701、单机、固定 29.0 s 截点、一次回放。上一轮全部失败和原始回放保留。使用相同 GPL-3.0 上游提交 `69488123ed9362dd44b6f28e7f4680abbff1442b`、v2 配置及诊断库；EKF2 与 Gazebo 只作离线评分。

1. 对输出适配器先写正常、边界、缺失/乱序、哈希不符和防覆盖测试，再实现严格截取和不可覆盖的导出清单。
2. 独立核验截取输入的 IMU 六轴/时间戳、RGB 帧顺序与原始 CSV 完全一致；保存逐文件 SHA-256 和固定截点。
3. 仅一次运行原 OpenVINS runner，记录版本、命令、退出码、资源、初始化日志、逐帧状态与正数视觉更新。
4. 用现有事后真值评分器和 PX4 EKF2 窗口工具评估，保存全部失败；区分初始化时机、视觉更新和可用于飞行的误差门槛。
5. 写独立中文报告与非覆盖哈希索引证据包，运行针对性测试、Ruff、全量回归和只读复核，再提交草稿 PR。若结果未达到 VIO 门槛，停止 EKF2 接入，转向标定/几何证据。
