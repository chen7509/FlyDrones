# 自主商业无人机集群总路线图

> **For agentic workers:** 本文是总路线图。开始任何阶段前，必须为该阶段单独编写实现计划，并使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐项执行。

**目标：** 把当前 FlyDrones 原型发展成一套可给出任务目标、由最多 100 架无人机在缺少持续中台控制、卫星定位受限和通信退化时自主分工、局部避障、重分配和集合的系统，并最终满足商业表演所需的可重复性、安全性和可审计性。

**架构：** 每架无人机运行独立的感知、定位、果蝇启发反射、局部规划、任务分配、健康管理和通信代理；学习模型只提出受限的高层运动意图。本地 PX4 飞控和确定性安全监督器始终控制姿态、电机、围栏、失联和降落。任务站只负责在起飞前下发任务合同、监视结果和触发独立急停，不在任务执行期间逐机发送轨迹。

**技术栈：** Python、PyTorch、MaleCNS/MiniFly 脉冲神经网络、PX4 SITL/HITL、Gazebo、MAVLink/UDP、相机/IMU/气压计/测距传感器、ULog 离线证据、pytest/Ruff。

**规格：** 本路线图综合以下已批准设计：

- `docs/superpowers/specs/2026-09-21-decentralized-mission-agents-design.md`
- `docs/superpowers/specs/2026-09-21-hybrid-local-trajectory-planner-design.md`
- `docs/superpowers/specs/2026-09-22-multitask-continual-learning-design.md`
- `docs/superpowers/specs/2026-09-22-resumable-curriculum-training-design.md`

## 1. 最初想法的工程化定义

最终系统接收的是“搜索这个区域并在目标点集合”“完成一段动态灯光表演”等任务合同，而不是 100 份人工航点。每架机依据本机传感器、任务账本和有限邻机消息自行决定下一步。失去任务站或部分邻机后，任务应继续；环境或自身状态超出安全边界时，该机应减速、悬停、返航或降落。

果蝇模型承担视觉运动、逼近物反射和短时逃逸等快速决策，并可向学习策略提供偏置。它不是完整的飞行控制器，也不直接输出电机 PWM。学习策略负责任务相关的高层选择和局部导航残差；确定性规划器和安全监督器拥有最终否决权。真实飞行中的在线学习先只在影子模式记录候选动作，通过回归、签名和金丝雀门槛后才允许有限控制。

“没有中台”在本项目中表示没有中央实时航点、速度、避碰或任务重分配命令。商业运行仍需要独立的监控、地理围栏和全机降落/停机通道，但这些通道不替无人机做日常路径决策。

## 2. 当前基线

截至 2026-09-26，工程已经证明：

- 100 个独立进程可以在运动学环境中使用本地状态和 UDP 消息完成分布式任务测试。
- 5 个独立 PX4/Gazebo 实例可以使用各自的深度感知、局部规划和点对点通信飞行。
- 任务层支持合同、竞价、租约、低电量换班、节点失效接管、搜索、确认和集合。
- 多任务训练框架支持出口、跟随、搜索、覆盖、编队、门框等任务，并有检查点、回归和回滚流程。
- 一次五机试验在第 5.039 秒关闭 0 号机 GNSS 融合后，PX4 EKF 使用外部视觉状态继续 19.636 秒，5 架机均完成集合和降落；ULog 证明视觉位置/速度融合已生效。

这些结果仍属于实验室原型。当前“视觉里程计”输入是 Gazebo 真值的替身；100 机结果不是 100 个 PX4 物理实例；现有最小机间距 0.7421 米和森林净空 0.2287 米不足以支持商业运行；硬件适配器尚无本项目的真实飞行证据。

## 3. 全局约束

- 飞控、学习策略、任务代理必须运行在每架机本地；中央进程不得出现在运行时控制链。
- 学习模型不得直接控制电机、解除围栏、缩小最低间距或修改返航电量。
- 每项能力都必须依次通过单元测试、快速仿真、独立物理仿真、HITL 和分级实飞；不得用低层级结果替代高层级证据。
- 测试报告必须从逐机日志和飞控 ULog 重算结果，不能只信控制器自己上报的成功标志。
- 所有随机场景保存种子、配置、模型哈希、代码提交、传感器故障时间线和逐机日志。
- 任何碰撞、越界、失控、未解释的估计器复位或安全监督器绕过都使该次试验失败。
- 商业演出时冻结已验证的软件、模型和配置；在线学习只生成下次候选版本，不能在同一场演出中未经验证地改变控制策略。

## 4. 安全间距与统一验收指标

真实最低间距不能使用固定经验值，必须按机型和速度计算：

`d_safe = 2 × 机体包络半径 + 相对速度 × 总延迟 + 相对速度² / (2 × 可保证减速度) + 3 × 定位标准差 + 额外余量`

在机型尚未确定前，仿真暂用以下最低门槛：低速机间距不小于 2 米，高速交叉不小于 3 米，森林/建筑净空不小于 1 米。选定实机后重新标定，不得直接沿用。

所有阶段统一记录：

- 碰撞、擦碰、围栏越界和安全覆盖次数。
- 最小机间距、障碍净空、最大速度、加速度和急动度。
- 任务完成率、完成时间、重复任务率和失效接管时间。
- 定位误差、漂移率、估计器复位、传感器新鲜度和错误检测延迟。
- 消息率、有效吞吐、丢包、延迟、网络分区后的收敛时间。
- 控制循环频率、最坏推理延迟、CPU/GPU/内存、温度和功耗。
- 人工接管、返航、降落和急停的触发原因及结果。

## 5. 分阶段执行计划

### 阶段 0：冻结当前能力和证据

**做什么**

1. 给现有快速仿真、100 进程任务试验和 5 PX4 试验建立统一运行清单。
2. 将代码提交、配置、随机种子、模型摘要、环境版本和 ULog 写入不可变清单。
3. 把“网页演示、运动学仿真、PX4 物理仿真、HITL、实飞”明确标注为不同证据等级。
4. 建立每次候选版本必须通过的回归基线，保留当前结果作为比较基准。

**测试什么**

- 在全新目录连续运行 3 次，验证命令、依赖和报告可复现。
- 修改模型、配置或代码后，验证清单哈希必然变化。
- 故意缺失一个逐机日志或 ULog，验证验收器拒绝给出“通过”。
- 运行全部单元测试、Ruff 和编译检查。

**通过门槛与产物**

- 三次运行均能生成完整证据；指标差异处于预先声明的随机范围。
- 产出“能力矩阵”和“证据等级表”。任何后续宣传都引用对应等级。

### 阶段 1：把理想传感器改成现实传感器模型

**做什么**

1. 为相机、IMU、气压计、磁力计、测距和 GNSS 加入噪声、偏置、温漂、遮挡、延迟、不同步、冻结和重启模型。
2. 用带滚动快门、运动模糊、曝光变化、重复纹理、无纹理墙面、雨雾和动态障碍的虚拟相机取代理想深度/位姿输入。
3. 建立时间同步层，所有观测携带采样时间、到达时间、方差和健康状态。
4. 删除控制链对 Gazebo 真值位姿、真值障碍距离和全局无人机状态的依赖。

**测试什么**

- 单一故障：相机掉帧、IMU 偏置、气压跳变、磁干扰、深度冻结、GNSS 消失。
- 组合故障：运动模糊 + 200 ms 延迟；GNSS 消失 + 视觉短时遮挡；时间戳乱序 + 丢帧。
- 真值泄漏测试：禁止的真值主题和接口在运行时不可用，任务仍能执行或安全终止。
- 100 个固定种子和一组未见过的随机森林/建筑布局。

**通过门槛与产物**

- 所有传感器故障在规定检测时间内被标记；过期数据不能继续驱动前进。
- 无真值输入时仍满足零碰撞、零越界；无法定位时必须安全悬停或降落。
- 产出传感器误差配置、场景包和故障注入报告。

### 阶段 2：接入真实视觉惯性里程计

**做什么**

1. 对至少两个开源 VIO 候选做时间、精度、许可证和机载算力评估，再选主方案和备用方案。
2. 让 Gazebo 相机和 IMU 经过与真实设备一致的消息管线进入 VIO，而不是直接读取仿真位姿。
3. 把 VIO 位姿、速度、协方差和重定位事件送入 PX4 EKF，并记录完整 ULog。
4. 实现 VIO 初始化、失锁、重定位、尺度异常和坐标系复位处理。

**测试什么**

- 静止、慢速、高速、急转、穿门、森林重复纹理、暗光和过曝数据集。
- GNSS 正常、GNSS 突然消失、GNSS 错误漂移、VIO 暂停 0.2/1/3 秒、VIO 重新定位。
- 将估计轨迹与仿真真值离线比较，但真值不能进入飞行控制。
- ULog 检查 EV 融合标志、创新、协方差、复位计数和惯性航位推算状态。

**通过门槛与产物**

- 普通场景位置误差和漂移满足选定任务包络；具体数值在选择相机、速度和场地后锁定。
- GNSS 关闭后不出现未解释的真值接管；VIO 失效时 PX4 与安全层按设计降级。
- 产出可回放传感器包、VIO 基准报告和 PX4 融合证据。

### 阶段 3：状态估计健康管理和故障隔离

**做什么**

1. 建立统一 `EstimatorHealth`，融合创新、协方差、数据年龄、重置、源间残差和漂移趋势。
2. 实现 `NOMINAL → DEGRADED → HOLD → RETURN/LAND → EMERGENCY` 状态机。
3. 用独立观测交叉检查 GNSS、VIO、气压高度和测距，拒绝跳变、卡死或自相矛盾的数据源。
4. 将健康状态传给局部规划和任务分配，使失去能力的无人机自动释放任务。

**测试什么**

- GNSS 欺骗式缓慢偏移、固定值、间歇跳变；VIO 尺度漂移、时间戳回退和重定位跳变。
- 传感器同时报告“正常”但彼此不一致的拜占庭式输入。
- 单机健康降级后邻机接管其任务，且该机不会继续竞争新任务。
- 误报和漏报测试，测量检测延迟与安全动作延迟。

**通过门槛与产物**

- 所有已定义故障都有唯一、可复现的降级动作；无振荡式模式切换。
- 状态不可信时不再执行进攻性运动；任务接管在合同时间内完成。
- 产出健康状态规范、故障树和逐故障验收报告。

### 阶段 4：高复杂度场景生成和域随机化

**做什么**

1. 建立多种森林、建筑、走廊、门框、起伏地形、动态人车和其他无人机的程序化场景。
2. 随机化树木密度、建筑布局、光照、风、传感器材质、目标路线和通信遮挡。
3. 同一任务同时包含出口寻找、目标跟随、区域搜索、覆盖、编队、门框、电量换班和节点失效。
4. 分离训练场景、验证场景和完全未见过的封存测试场景。

**测试什么**

- 稀疏到极密森林、室内外切换、狭窄门框、移动障碍和高空交叉。
- 横风、阵风、下洗近似、亮暗突变、视觉重复纹理和部分地图错误。
- 同时注入三类以上故障，验证失败可复现而不是随机隐藏。
- 检查训练和封存测试之间没有种子、地图或轨迹泄漏。

**通过门槛与产物**

- 每个任务至少有简单、中等、复杂、组合压力四档场景。
- 候选策略在封存场景达到预先固定的成功率，同时零碰撞、零越界。
- 产出版本化场景库、场景清单和难度校准报告。

### 阶段 5：高速局部避障和机间避让

**做什么**

1. 用相对位置、速度、加速度、定位方差和消息年龄预测未来占用体积。
2. 果蝇逼近反射负责毫秒级刹停/偏转建议，确定性轨迹规划器负责可证明的速度、加速度和间距约束。
3. 对通信缺失的目标采用机载视觉/雷达检测；消息过期时扩大安全包络并减速。
4. 为高速穿越机建立单独的动力学包络、制动标定和赛道模式，不能沿用低速机参数。

**测试什么**

- 双机正对、十字、汇入、追越、盲角和上下层交叉。
- 10/20/50/100 机在高密度汇聚点进行随机和对抗式交叉。
- 延迟、丢包、错误速度广播、视觉漏检和一架机突然急停的组合。
- 从低速逐级增加速度，每一级重新计算 `d_safe` 并测量最坏刹停距离。

**通过门槛与产物**

- 所有封存压力场景碰撞为零，实测最小距离始终大于动态安全距离。
- 安全层介入时仍保持飞行稳定；局部死锁能够检测并以确定性规则解除。
- 产出速度包络、制动曲线、冲突类型报告和高速准入清单。

### 阶段 6：抗干扰通信和无通信自治

**做什么**

1. 限制 P2P 消息为邻机状态、任务摘要、健康状态和证据哈希；控制循环不等待网络。
2. 加入消息身份、完整性、单调序列、防重放、限流和版本校验。
3. 设计网络分区期间的本地任务策略、冲突避免规则和恢复后的账本收敛。
4. 在两个不同无线链路/仿真信道上测量容量，定义正常、退化和完全失联模式。

**测试什么**

- 0% 至 50% 随机丢包、50 至 1000 ms 延迟、抖动、乱序和 1 至 60 秒黑障。
- 网络分成 2 至 5 个区域后继续任务，再恢复并消除重复认领。
- 畸形包、重放包、错误任务哈希、身份冒用和消息洪泛。
- 地面任务站在任务开始后退出，验证中央飞行命令计数始终为零。

**通过门槛与产物**

- 无通信时单机保持本地安全并按合同执行可独立完成的工作。
- 网络恢复后账本在规定时间内收敛；无消息可绕过安全层或直接控制飞行。
- 产出信道压力报告、威胁模型、密钥/身份生命周期方案和失联行为表。

### 阶段 7：分布式任务协同完善

**做什么**

1. 为搜索、跟随、覆盖、编队、门框、集合、充电/换班和故障接管定义有限任务合同。
2. 完善竞价、租约、证据确认、能力匹配和任务完成共识。
3. 让每架机只按本机电量、能力、距离、风险和邻机摘要计算投标。
4. 给商业表演增加分布式时间基准和“角色槽位”，任务站只发布整体节目合同。

**测试什么**

- 随机终止 1、10、30 架机；低电量、传感器失效和计算超时同时出现。
- 同一任务被两个网络分区重复认领，恢复后只保留一个有效所有者。
- 任务中途改变可用能力，例如带相机节点退出、照明节点电量不足。
- 任务站退出、重启或发出错误版本合同，执行中的合同不得被无授权替换。

**通过门槛与产物**

- 100 个独立进程、100 个独立账本和端点；中央实时飞行命令为零。
- 10% 节点失效后，未完成任务在合同时间内重新分配；无永久双重所有权。
- 产出合同模式库、任务层验证器、重分配报告和审计时间线。

### 阶段 8：学习策略和果蝇反射的正确分工

**做什么**

1. 建立三组对照：纯确定性基线、确定性 + 学习、确定性 + 学习 + MaleCNS 反射。
2. 明确果蝇输入映射、神经活动、读出和安全覆盖，禁止把人工规则标成完整果蝇学习。
3. 课程训练由单任务逐步进入多任务、组合故障和未见场景。
4. 使用共享策略参数，但每架机保留独立循环状态、任务状态和观测；训练可用集中式 critic，部署包不得包含全局真值输入。

**测试什么**

- 消融测试：关闭反射、关闭学习残差、关闭任务先验，量化每部分贡献。
- 旧技能回归：学习新任务后，出口、跟随、搜索等旧任务不能显著退化。
- 分布外场景、对抗障碍、错误观测和推理超时。
- 重复 5 至 10 个训练种子，报告中位数和最差值，不只选择最好一次。

**通过门槛与产物**

- 学习候选必须在安全不退化的前提下显著改善至少一个任务指标。
- MaleCNS 后端全程真实运行、零回退时才能给出“果蝇反射参与”结论。
- 产出消融报告、训练清单、部署模型、回归报告和失败案例库。

### 阶段 9：受约束的持续学习

**做什么**

1. 实飞数据只进入影子学习管线；候选策略同时计算动作但不控制无人机。
2. 对候选执行离线回放、仿真回归、封存场景和策略差异检查。
3. 通过后签名为候选版本，先在单机低速金丝雀任务中使用，并保留一键回滚。
4. 商业演出期间冻结模型；演出数据只能生成下次测试周期的候选。

**测试什么**

- 模型文件损坏、签名错误、版本倒退、推理超时、异常动作和回滚失败。
- 影子候选与已批准策略在相同观测下的动作差异和风险评分。
- 新任务学习后的全量旧技能与安全回归。
- 金丝雀触发任何安全失败后，验证立即回退且不能自动再次启用。

**通过门槛与产物**

- 未签名、未通过回归或无完整清单的模型永远不能进入控制路径。
- 回滚时间小于本机安全层容许窗口；更新过程不会同时改变整个机群。
- 产出模型注册表、签名清单、影子报告和回滚演练记录。

### 阶段 10：扩大独立物理仿真规模

**做什么**

1. 从当前 5 PX4 依次扩展到 10、20、50，最后评估 100 个独立 PX4/物理实例所需算力。
2. 若单机无法实时运行 100 个高保真实例，建立分层验证：100 机任务/网络压力、20 至 50 机全物理、高风险冲突的局部高保真重放。
3. 所有实例使用独立 PX4、传感器流、VIO、任务代理、通信端点和日志。
4. 监控仿真实时率；低于规定实时率的结果不能用于时延和避碰结论。

**测试什么**

- 规模阶梯中的 CPU、GPU、内存、网络和仿真实时率。
- 100 机任务同时启动、集中穿越、分组汇合和 10% 节点失效。
- 多轮随机种子与长时间耐久运行，检查端口泄漏、时钟漂移和资源增长。
- 关闭任何集中式辅助接口，验证每架机仍独立决策。

**通过门槛与产物**

- 每一规模连续通过规定批次后才能扩大；不能用一次成功替代统计结果。
- 100 机任务和通信验收全部通过；物理层能力必须明确标明实际验证的最大机数。
- 产出规模曲线、资源预算、失败分布和最大可信规模声明。

### 阶段 11：选择机体、传感器和机载计算板

**做什么**

1. 先确定首个实机用途：低速室内验证机；高速穿越机和商业表演机随后分别选型。
2. 建立算力预算：VIO、目标检测、MaleCNS/核心子图、策略推理、日志和通信的最坏负载。
3. 建立质量、续航、散热、供电、电磁兼容、接口和成本表。
4. 选用 PX4 兼容飞控与伴随计算板；伴随板失效时飞控独立悬停/返航/降落。

**测试什么**

- 桌面基准：最坏场景下控制频率、推理延迟、温度、功耗和内存。
- 限频、过热、存储满、进程崩溃、伴随板重启和总线断开。
- 电机工作时的相机、磁力计、无线和供电干扰。
- 带实际机载重量的续航、重心和制动能力测量。

**通过门槛与产物**

- 最坏负载仍保留至少 30% 算力余量，控制链无热降频造成的截止时间违约。
- 伴随板完全掉电时 PX4 仍执行预定失效保护。
- 产出选型报告、物料清单、接口图和每机算力/功耗预算。

### 阶段 12：HITL、台架和笼内实飞

**做什么**

1. PX4 HITL 验证真实飞控、伴随板、相机/IMU 时间同步和通信链。
2. 无桨台架检查解锁、模式切换、设定值范围、看门狗和急停。
3. 有桨系留或飞笼内按单机、双机、五机逐级试飞。
4. 每一级只开放上一层已验证的速度、空间和任务。

**测试什么**

- 断任务站、断 P2P、断 GNSS、遮挡相机、重启伴随板、低电量和飞控模式拒绝。
- 单机悬停/降落，双机交叉/失联，五机搜索/接管/集合。
- 独立人工急停、自动降落和越界保护。
- 把实飞日志回放到仿真，检查模型偏差并更新场景参数。

**通过门槛与产物**

- 台架和飞笼内所有故障都有确定且可重复的安全结果。
- 实飞安全间距大于重新标定后的 `d_safe`，无未解释估计器复位。
- 产出视频、逐机 ULog、伴随板日志、检查表和模型偏差报告。

### 阶段 13：开放场地扩群和商业表演功能

**做什么**

1. 按 5、10、20、50、100 架逐级扩大，每一级重新做场地风险和通信容量评估。
2. 增加演出专用的分布式时间同步、灯光状态、节目段落、备用集合点和安全走廊。
3. 建立部署、编号、充电、电池筛选、校准、起飞前检查和演后日志归档流程。
4. 根据当地监管、场地和机型制定飞行许可、隔离距离和人员职责。

**测试什么**

- 全节目重复运行、冷启动、部分起飞失败、中途退出、灯光失步和时钟偏差。
- 观众隔离区外的最大故障包络、风限、雨限、GNSS/无线环境和急停覆盖。
- 10% 无人机退出后剩余无人机安全重构节目或按合同结束。
- 彩排与正式配置的哈希一致性，任何临时改动都必须重新验收。

**通过门槛与产物**

- 每一规模连续多次彩排通过，零碰撞、零越界、零未解释控制失效。
- 任务完成和表演同步达到业务指标；任何单点故障都不会导致群体失控。
- 产出标准作业程序、场地报告、维护周期、事件响应和商业运行证据包。

## 6. 每阶段共同使用的故障矩阵

| 类别 | 必测故障 |
|---|---|
| 定位 | GNSS 消失、漂移、跳变、欺骗；VIO 掉帧、尺度漂移、重定位；源间冲突 |
| 感知 | 暗光、过曝、运动模糊、遮挡、重复纹理、动态障碍、深度冻结 |
| 通信 | 丢包、延迟、乱序、黑障、分区、恢复、洪泛、重放、错误身份 |
| 计算 | 高负载、推理超时、进程崩溃、存储满、过热降频、伴随板重启 |
| 飞行器 | 低电量、电压骤降、单传感器故障、动力下降、急停、飞控拒绝模式 |
| 集群 | 1/10/30% 节点退出、重复认领、任务站退出、时钟分歧、局部拥堵 |
| 环境 | 风、阵风、狭窄通道、森林、建筑、移动人车、不同高度高速交叉 |

每个阶段先测单故障，再测两种组合，最后测至少三种同时发生。组合故障失败时必须保存最小复现种子并加入永久回归集。

## 7. 执行顺序和停止规则

严格按阶段门槛推进，但允许场景库、计算板调研和测试基础设施并行准备。任何阶段发生以下情况时停止扩大规模或速度：碰撞；围栏越界；估计器状态不可信但仍继续高速飞行；中央控制意外进入控制链；日志不足以还原事件；连续两次出现同类未解释失败。

停止后先复现、定位根因、增加回归测试，再恢复原规模验证。修复后必须重跑当前阶段全部安全测试，不能只重跑失败场景。

## 8. 近期三个实施包

### 实施包 A：现实 VIO 替换

- 写独立设计规格：真实虚拟相机/IMU → 开源 VIO → PX4 EKF。
- 删除 Gazebo 真值里程计在控制链中的使用。
- 完成 GNSS/VIO 单故障和组合故障 ULog 验收。

### 实施包 B：动态安全距离与高速交叉

- 用机体包络、相对速度、总延迟、制动能力和定位方差计算安全距离。
- 建立双机到 100 机交叉压力场景和确定性安全屏障。
- 先在快速仿真筛选，再在 5 至 20 个 PX4 物理实例中复验。

### 实施包 C：机载计算与 HITL

- 选择一套低速安全验证机、PX4 飞控、相机/IMU 和伴随计算板。
- 在候选板上跑 VIO、策略、反射、通信和日志的最坏负载。
- 完成无桨 HITL、看门狗、伴随板掉电和飞控独立降落验证。

推荐首先执行实施包 A。它会消除目前最大的证据缺口：现有无 GNSS 成功仍依赖仿真真值替身。A 通过后再提高速度和购买硬件，能够避免用理想定位调出一个无法迁移到真实无人机的策略。

## 9. 项目完成定义

项目不能以“仿真飞起来”或“一次 100 机运行成功”作为完成。只有满足以下全部条件，才可称为商业级自主集群候选：

1. 任务执行期间没有中央实时飞行或分配命令。
2. 100 架真实目标机型完成规定次数的全流程彩排。
3. GNSS、通信和部分节点失效时仍满足动态安全距离、围栏和降落要求。
4. 所有控制软件、模型、配置和任务合同可追溯、可签名、可回滚。
5. 学习系统从未绕过 PX4 和确定性安全监督器。
6. 每种关键故障均有实测证据、操作程序和责任人。
7. 场地、人员、机型和运行流程满足实际部署地点的监管和保险要求。
