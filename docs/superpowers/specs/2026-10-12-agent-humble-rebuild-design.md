# Fixed XRCE Agent rebuild in the pinned ROS 2 Humble image

The existing fixed Agent v2.4.3 WSL runtime bundle requires GLIBC 2.38 in two libraries; the pinned Humble image provides 2.35. To enable a later same-network Agent and typed `VehicleOdometry` collector, build the **same fixed source and dependency commits** inside that image. This is a toolchain/ABI adaptation, not an Agent version migration or a grant of DDS/PX4 source provenance.

Mount the audited WSL source and local bare Git stores read-only at their original path. Use a new empty Linux workspace for all build products. The proposed container limit is one CPU, one build job, 1 GiB RAM/no swap, 128 PIDs and a 1,500-second wall timeout with no network. Require at least 2 GiB host free memory immediately before launch so the bounded container does not exhaust the desktop; this is a separate offline-build preflight, not a change to the 4 GiB physical-simulation gate. If memory is below it, record a refusal before creating a container. Force Git's file-only dependency resolution through the sealed local config; capture CMake selection, selected dependency commits, compiler/image identity, complete logs, exit code and per-file source hashes before/after. Do not fetch new upstream data or modify the earlier WSL build. Preserve any configuration or build failure, including OOM, as a failed attempt with its exact resource settings.

If a binary is produced, verify its dynamic libraries and maximum required GLIBC versions against the image, then run only bounded usage/start/stop and wrong-input refusal checks in an owned container. A successful build or listener would still leave XRCE client identity, DDS discovery, typed CDR, PX4, ULog, VIO/EKF2 and flight unverified. A separate study must demonstrate those interfaces before any new physical capture. The established 4 GiB host-free gate for full physical/FlyCNS work remains unchanged.
