# PX4 ROS 2 VehicleOdometry source journal

## Purpose and boundary

The checked EGO corpus gate still has no producer of authenticated PX4 state. Add a **read-only, disarmed-source journal** that can receive actual `/fmu/out/vehicle_odometry` ROS 2 samples when the owned uXRCE Agent and matching message package are installed. It must preserve the serialized ROS message, callback receipt clock and available RMW publisher metadata before any camera/teacher association. This stage does not certify that a ROS publisher is PX4, calibrate the camera, enable a corpus writer, publish ODOMETRY, modify PX4 parameters or arm a vehicle.

- Official `PX4/px4_msgs` commit `148bdb4b8214a4d8de83029777fe8d334c74db6f` contains the **same message blob**, under BSD-3-Clause. The repo was non-archived and last-push metadata observed on 2026-10-10 was 2026-10-07. One matching message does not prove every ROS interface or generated type support matches the whole local PX4 tree.
- The local `fly-ego-benchmark:humble` image digest `sha256:a4dae62b38bc01a01d084be7b68db83ec804fef7673604e1a9c986a4baa88a6` has ROS 2 Humble `rclcpp` 16.0.19 and CycloneDDS RMW 1.3.5. It currently lacks `px4_msgs` and `MicroXRCEAgent`; no ROS 2/DDS physical trial is possible from that image as-is. Full `px4_msgs` generation must be bounded separately under the host-memory gate. Do not silently install a current incompatible release.
- The installed Humble `rclpy` executor returns only the message from `take_message`, discarding `MessageInfo` in its callback; installed `rclcpp::GenericSubscription` also lacks a `MessageInfo` callback. Use a typed `rclcpp::Subscription<px4_msgs::msg::VehicleOdometry>` serialized callback with `rclcpp::MessageInfo`, whose installed headers expose the metadata. ROS 2/rclcpp is Apache-2.0. RMW GID is local-context continuity evidence, **not** global publisher authentication. See [PX4 uXRCE-DDS](https://docs.px4.io/main/en/middleware/uxrce_dds), [pinned px4_msgs](https://github.com/PX4/px4_msgs/tree/148bdb4b8214a4d8de83029777fe8d334c74db6f), and [Micro XRCE-DDS Agent](https://github.com/eProsima/Micro-XRCE-DDS-Agent).

## Journal contract

The bounded receiver subscribes only to the fixed topic and fixed ROS type with a prospectively declared QoS and one event-loop thread. For each callback, record the exact *ROS serialized CDR representation returned by RMW* (not Ethernet or XRCE wire bytes); PX4 publication and sample timestamps; RMW source and reception timestamps, publisher/reception sequence numbers and publisher GID where supported; a local `steady_clock` callback receipt; local journal sequence; and the decoded frame/reset/quality fields. Preserve unsupported metadata as unknown, never invent a sequence or translate an RMW clock into PX4 HRT. A change in GID, type, topic, frame profile, reset counter, nonmonotonic source time or callback order records the offending sample and latches failure. A complete unobserved 8-bit reset-counter wrap remains undetectable.

The journal is exclusive-create, append-only, bounded by event count, CDR size and duration. Every line must be parseable with an explicit schema, and every sample or decode-fault row carries a CDR hash; short write, flush/close failure, overrun or deadline stops the receiver and leaves a failed or incomplete artifact. Startup, completion and all failure paths must later retain binary/config/source hashes and process identity from an owned launcher. The initial reader checks claimed type/blob and CDR hash but **cannot yet independently deserialize CDR with generated official type support**. A syntactically complete terminal is not proof of successful process exit or durable storage. This journal never supplies `CaptureInputEvidence` or marks `eligible_for_live_capture=true`. Full CDR decode parity, owner identity and camera/estimator gates remain required before forwarding a qualified event to the existing causal adapter.

## Execution gates

First prove the C++ callback and journal logic using a bounded ROS 2 synthetic publisher in the pinned image, with official `px4_msgs` generated from the fixed commit. Record compiler, image, generated-package and executable hashes. This proves ROS callback/serialization, not PX4. Only after the owned Agent and current resource gate are available may one disarmed PX4 SITL run record real samples, ULog, agent/PX4 process identity, DDS graph, clock relation and loss/restart faults. Camera extrinsic, EKF2 health, goal frame, checked EGO teacher and reset rebase remain separate gates; no training or flight claim follows merely from receiving a topic.
