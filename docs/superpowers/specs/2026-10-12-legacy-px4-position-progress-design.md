# Legacy PX4 position progress and loss guard

Status: software-only safety repair. This document records the design after the first exploratory implementation/tests; it is not a predeclared physical experiment. Existing user authorization covers implementation and review.

`Telemetry.t` remains control-loop time. It must not be treated as the generation or transport-arrival time of `LOCAL_POSITION_NED`. The legacy `MavlinkDrone` backend will separately retain the last accepted PX4 boot timestamp and the local monotonic time at which the message was decoded by `telemetry()`. Only finite, correctly identified, strictly progressing position/velocity samples renew the observation timer. Duplicates do not change cached position or renew the timer. Source-time regression, invalid payload, wrong/unknown identity, or expired observation locks refusal until a new explicit connection. A 32-bit boot-time rollover is conservatively treated as a discontinuity. The configured default observation timeout is 0.5 s; this is a local software policy, separate from PX4 `COM_OF_LOSS_T`, and has not been physically qualified.

PX4 takeoff must observe usable position before switching OFFBOARD or requesting arm, while priming neutral setpoints, and throughout ascent. All five coordinated-startup sources must pass an explicit `require_position_observation()` hook before any vehicle enters the mode/arm loop. Public PX4 `send()` polls nonblocking telemetry first, including preflight neutral priming, so an active queued stream is consumed. Clock high-water and old observation expiry are checked before renewal; a newly decoded packet cannot conceal an expired interval or clock regression. A latched fault makes telemetry reads refuse too, preventing cached landing values from appearing authoritative. Once arm has been requested, any readiness/wait/ascent exception must attempt PX4 LAND. Loss attempts a neutral setpoint followed by LAND, propagates refusal, and never force-disarms. LAND command success is only an attempted command; no ACK or actual landing is proven. The realtime caller must attempt LAND and actual connection close even when its stop setpoint fails, report cleanup failures, and preserve a primary loop exception. Explicit reconnect closes the prior transport and clears cached telemetry/source/clock state; active PX4 flight rejects reconnect. ArduPilot retains its existing position-source behavior.

Scope exclusions and remaining gaps: an increasing but delayed backlog can pass this guard, because the source clock has not been synchronized with the local clock and decode time is not kernel network-arrival time. This does not establish EKF2 validity, reset provenance, VIO/camera provenance, command ACK, source authenticity, or a hardware safety case. The benchmark gateway has a private direct setpoint path outside this backend gate; it must be assessed separately before any new physical qualification. Existing frozen evidence is unchanged.

## Sources and adoption

- MAVLink `LOCAL_POSITION_NED` message 32 supplies `uint32 time_boot_ms`, NED position and velocity. Official definition: https://mavlink.io/en/messages/common.html#LOCAL_POSITION_NED . Existing pinned `common-v20.xml` and PX4 d6f12ad source snapshots are reused; no new estimator or dependency is introduced. MAVLink schema/library provenance remains that of the existing project evidence, not a new maintenance observation.
- PX4 Offboard requires a continuous external setpoint/proof-of-life stream; its configured loss behavior is separate from position observation. Official guide: https://docs.px4.io/main/en/flight_modes/offboard . Adopt the existing BODY_NED velocity interface; do not rewrite the PX4 control loop or parameters.
- MAVLink routing guidance treats decreased boot time as a reboot indication: https://mavlink.io/en/guide/routing.html . A regression here is a conservative refusal, not proof of reboot cause.
- Existing optional pymavlink interface is reused. The reused installed-package metadata is 2.4.49 / LGPLv3; its previously pinned upstream commit is `2a500b8acfb507255d02ed8257b6eb132e5b86d7`, and COPYING includes a generated-code license exception. Current GitHub metadata is non-archived, pushed 2026-10-08; GitHub's license detector says NOASSERTION, so it is not substituted for COPYING. PX4 d6f12ad is BSD-3-Clause; current repository metadata is non-archived, pushed 2026-10-12. These metadata checks do not change the fixed versions. Runtime package version is not asserted by injected fakes. Resource cost is constant state and per-message checks; no physical simulator, complete connectome graph, Docker image, or new installed package is needed. Official protocol/source contracts supply this software behavior; no paper is claimed as proof of estimator calibration or flight safety.

## Verification contract

Use deterministic fake clock/link fixtures without a socket. Cover absent source before arm, accepted progress, duplicate/no-data loss, invalid/nonfinite/huge payload, wrong system/component, boot-time regression, clock regression, stale neutral command, active-flight refusal, LAND attempted after neutral-send failure, arm-wait failure, and realtime cleanup despite stop/LAND errors. Tests must distinguish bootstrap/API/import failures from behavioral RED assertions. Record changed-file Ruff, diff whitespace, adjacent control/distributed/simulation regressions and independent review. Report software passing separately from untested PX4/SITL/hardware behavior.
