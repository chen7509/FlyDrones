# Fixed Agent and ROS 2 collector colocation feasibility

The current pinned Agent binary runs in WSL, while the typed ROS 2 Humble collector runs inside Docker. The first topology study proved only Docker-to-WSL unicast UDP on the WSL interface. Before assigning an actual DDS collector to a future physical episode, check the reverse path and the exact binary ABI without starting PX4, Gazebo, Agent, VIO, or training.

Use a non-production UDP port and short-lived Docker listeners with bounded memory/PIDs. Compare Docker host-network listeners addressed via the WSL default gateway and Docker host interface against a Docker bridge listener with an explicitly published UDP port. Count a path as delivered only when the listener records the exact payload; `sendto` returning a length is insufficient. Capture per-case commands, exit codes, timeout, port/container release and live addresses. No routing result establishes DDS discovery or an XRCE session.

Read the pinned WSL Agent executable and selected shared libraries' required GLIBC symbol versions and compare them with the pinned ROS 2 image's actual glibc. A symbol-version incompatibility disqualifies using the current bundle unchanged in that image. Do not silently switch Agent version, substitute a different ROS message type, or alter the v12 physical declaration. If colocation is selected later, build the same fixed Agent source/dependency graph against the target image with an independent byte-bound build and tests, then prove an actual XRCE-created DDS endpoint and typed collector path before any physical PX4 study.
