# Kernel datagram receive timestamp evidence

This is a necessary transport dependency for distinguishing queue residence from callback time. The existing bounded `DatagramReceiver.received_ns` is userspace monotonic recvmsg-return time; it remains that time. It must not be relabelled kernel arrival or sensor-generation time. Firmware/physics and complete-model gates remain blocked by about2.1GiB host available memory; this independent study uses small local sockets only.

## Chosen upstream interface and boundary

Use existing Python3.12 `socket.recvmsg` ancillary support with Linux `SO_TIMESTAMPNS_NEW`, not a hand-built packet timestamp or a source-clock guess. Official kernel documentation recommends NEW's fixed `__kernel_timespec` ABI. Python in installed WSL does not expose SO_TIMESTAMPNS/SCM_TIMESTAMPNS constants, so derive actual option, cmsg, flag and layout values from a small C program compiled against installed headers before any socket study. Freeze C source/compiler/header/dependency/binary/ABI output identity. Narrow this first profile to x86_64/little-endian/16-byte signed64 sec+nsec, with a32-byte CMSG_SPACE buffer; refuse unknown ABI/version/schema/type/definition or a changed ABI digest. No numeric constant is guessed from the Python environment.

References: [Linux timestamping API](https://docs.kernel.org/networking/timestamping.html), [fixed v6.6 receive path](https://github.com/torvalds/linux/blob/v6.6/net/socket.c), [fixed v6.6 socket options](https://github.com/torvalds/linux/blob/v6.6/net/core/sock.c), [fixed UAPI constants](https://github.com/torvalds/linux/blob/v6.6/include/uapi/asm-generic/socket.h), [Python3.12 recvmsg](https://docs.python.org/3.12/library/socket.html#socket.socket.recvmsg). Kernel sources are GPL-2.0 family; UAPI declares the Linux syscall exception. Python is PSF-licensed. Installed WSL kernel6.6.87.2 patches are not asserted equivalent to v6.6. This adds standard-library/socket operations and a tiny header probe, no daemon or new dependency. No paper is claimed as calibration or flight proof. Man7 retrieval failed and is not used as evidence.

Linux's receive path can synthesize a current timestamp when timestamp enabling races an already queued packet. Therefore the new opt-in profile must be enabled and confirmed on an observed **unbound** IPv4 UDP socket before bind and before this study's owned sender generates traffic. Enabling on an already bound socket refuses; the receiver itself must never enable after binding. Revalidate the same socket object/descriptor, nonblocking mode, endpoints, ownership guard and enabled option before every read. Pre-bind configuration and known owned generation reduce the observed race; they do not eliminate hostile networking or prove every kernel packet timestamp originated at the hardware receive boundary.

The timestamp is kernel software system-real-time metadata, not hardware NIC time and not guaranteed monotonic. Preserve raw ancillary bytes and level/type/length, original payload and receive flags before clock/guard/journal callbacks can fail. Require exactly one valid NEW timestamp; reject missing/duplicate/unknown/truncated metadata, payload/control truncation, wrong peer, invalid sec/nsec/range, future stamp relative to a later realtime observation, realtime regression and kernel-stamp regression. No fallback to callback time. Keep monotonic read bounds/deadlines, source/descriptor guard, reentry, failure latch and event capacity unchanged; opt-in reserves the extra timestamp event slot. Record raw realtime brackets and userspace monotonic return separately, without deriving an authenticated mapping or source-generation age.

`ReceivedDatagram` gets an optional immutable kernel-realtime timestamp. Default receiver behavior and historical schemas remain untouched. The new receiver profile is not yet activated through existing frozen CaptureWireOwner/live manifests or Gazebo stepping; that requires a separately declared profile binding ABI, clock mapping and real PX4 owner. All source/network/clock-mapping/fusion/training authorities remain false.

## Verification and one bounded local study

First pure/fake tests for ABI validation, pre-bind enable/confirmation and option drift; then receiver tests for retained raw ancillary, actual recvmsg buffer, clock/metadata/truncation/peer/journal failures, latch/reentry and legacy behavior. Include callbacks failing after actual read without losing bytes. Inspect final source with independent review and adjacent receive/segmented/session regressions.

Compile the installed-header probe with existing GCC, no install, single job, at most10s; preserve compiler version, selected system-header hashes, dependency list, binary and ABI output. After validation and before trial freeze, use one Python-owned pair of exclusive loopback UDP sockets at existing14548/14588 only if ports/resources are clear. No PX4/Gazebo/Docker/ROS, no MAVLink/ODOMETRY payload, no human recipient. A20s outer limit bounds the whole tiny study. Send3 explicitly marked opaque packets only after pre-bind option setup and bind; retain send realtime/monotonic bounds, payload hash and FD identity, intentionally delay consumption40ms, then verify exact returned bytes/peer/ancillary and observe the kernel-to-read realtime difference. The difference is diagnostic, not an end-to-end/VIO/decision latency qualification. An independent declared option-drift case must refuse before receive. Close only owned sockets, retain failures and exact close/FD observations; do not claim all unrelated processes exited. No silent retries if bind/compile/probe fails. Freeze a new variant explicitly for any repair.

No load/physics/RTF/safety threshold is changed, and no physical capacity is claimed. Integrating this evidence with TIMESYNC, source sample times and EKF2/CameraInfo still remains necessary before student capture or flight.
