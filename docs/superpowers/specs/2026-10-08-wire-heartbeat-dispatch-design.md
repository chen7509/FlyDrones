# Preserve heartbeat delivery in the shared wire path

The actual capture currently uses mavutil.recv_match(type=HEARTBEAT), which consumes other frames while filtering. The new ObservedWireSession separately owns recvmsg and its responder only records non-TIMESYNC frames. Attaching both readers would lose messages. Before live lifecycle integration, make the existing single-decoder path capable of forwarding verified unarmed heartbeat events to the existing capture dispatch function. This is an architectural interface change with prior user approval for routine design/implementation; no new network/physics authority.

## Research and decision
Reuse installed pymavlink2.4.49 commonv20 and existing PinnedCodec, fixed PX4 d6f12ad, current capture dispatch_heartbeat. Generator license (L)GPLv3 with generated output MIT exception; distribution LGPLv3, PX4 BSD3, Python PSF. Retained metadata/source hashes remain historical observations, not fresh maintenance claims. Official MAVLink TIMESYNC/message-interval and Python receive docs consulted; installed mavutil source inspected without sockets. No changed OpenVINS numerical method or new paper result. Resource cost is bounded frame dispatch journal/callback, no new worker, socket, decoder or dependency.

Do not repeat known default-rate diagnosis: TIMESYNC default10Hz cannot supply500 in8s at realtime; prior startup/interval reports already identify proposed100Hz and missing actual transaction/rollback. This stage does not apply it. Do not add a second socket reader, reparse bytes in another codec, change time gates or call this complete capture integration.

## Contract
Add keyword-only optional heartbeat_sink to TimesyncWireResponder, OwnedWireBootstrap and ObservedWireSession. None preserves existing behavior. Require callable when supplied. A datagram is wholly decoded/CRC/framing checked and all headers remain strict system9/component1. In opt-in mode accept at most one heartbeat, require autopilot12 and mavlink_version3, refuse armed bit128 before dispatch or TIMESYNC send. Multiple/wrong/armed heartbeats retain raw/decoded evidence but do not deliver a readiness event. Ordinary uint base_mode/custom_mode bounds checked. A malformed TIMESYNC request, duplicates or invalid remote clock must not deliver an otherwise valid mixed heartbeat.

Before any reservation/send, deliver the heartbeat exactly once locally using a copied existing capture-shaped event: kind heartbeat, arrival_monotonic_ns=original userspace recvmsg-return timestamp (not kernel or newly sampled time), observed_sim_ns=selected independent observation, system_id9, base_mode, custom_mode. Validate nonnegative integer observed_sim_ns even for standalone responder. No ODOMETRY/truth enters this path. Capture wiring is demonstrated against the existing dispatch_heartbeat with fake writer/fanout; actual receiver thread is unchanged and remains mutually exclusive with a future wire-mode reader.

Record dispatch attempt with frame index before the callback; record returned_none/return_type after it returns, before later checks can conceal partial delivery. A callback return is not durable writer completion. Non-None, exception, journal failure, reentry, close, source/clock failure or deadline stops reply, latches failure, no retry/rollback claim. Callback gets an independent copy. Shared remote clock failure is checked in the responder. ObservedWireSession wraps dispatch with the existing profile/context/final boundary checks and checks again after callback via the normal wire/session path. An already executing callback/send cannot be retrospectively undone.

Keep 2s/8s/500/4096 and same socket/endpoint/profile. HB-only datagrams return None and never reserve/send/increment accepted TIMESYNC count. Raw packet and decoded fields keep original wire sequence and frame bytes. Network/delivery/fusion flags remain false. Live descriptor ownership, continuous receive after bootstrap, apply/restore rate transport and actual PX4 clock convergence remain later gates.
