# Generated source graph binding

## Intended result
Bind the actual generated world and recursive original SDF/COLLADA references to the explicit runtime baseline before NativeClient/TestFixture/PX4. Preserve repeats, unsupported edges, source lexical paths and canonical identities. No new physics is authorized by this development stage. Standing autonomous user approval applies.

## Design
1. Extend the installed native resolver with a `bound-uri` local profile. Installed SDK still selects paths. Enumerate the fixed source's local candidate locations in native C++ using SDK paths/URI/filesystem helpers, including cwd, SDFormat getSharePath/version directory and SDF_PATH, Common FilePaths and COLLADA direct/fallback locations. Reject different canonical choices, nonregular/dangling candidates, unknown query/fragment/escape schemes and unsupported lexical forms. Include candidates carry model.config dependencies. Clear callbacks only in isolated helper processes and state that this is not a runtime callback observation. Existing `uri` behavior remains a research interface.
2. A strict Python query client accepts the frozen binary and finite environment/cwd, records commands, return code, raw stdout/stderr, errors and timings before parsing; query10s, graph60s, maximum512queries and256documents/4096edges, source8MiB. Unknown schema/key/type, duplicateJSON/nonfinite, nonzero/timeout refuse. Do not infer SDK selection ordering in Python. Freeze resolver source/binary/declared direct dependency paths before any queries.
3. A graph walker reads original bytes only from already-declared or verified generated files. It recursively follows includes and DAE meshes, verifies returned selected/config/material paths are in the pre snapshot, preserves source/reference positions and duplicates, refuses cycles/unsupported edges. STL is terminal; other mesh formats refuse. Classic script is only the existing exact sentinel, recorded against installed gazebo.material; material names must be the fixed supported Gazebo/DarkGrey paired with that script. No mesh decoding/rendering claim. Every query/partial graph remains after failure.
4. RuntimeBinding v2 adds `graph` declaration while v1 remains explicit legacy without graph verification. The v2 graph specifies cwd, explicit query environment and expected SDK context; reserved inventory roles graph:resolver (one), graph:source (one), graph:dependencies (nonempty) must be baseline-checked first. Generated copies and baseline are snapshotted before graph queries; the same files are rechecked after queries before the final pre manifest. No discovered file is silently whitelisted. Unknown graph coverage refuses. Post capture still runs on graph/pre failure. Separate local_file_graph_verified from runtime_closure_qualified=false; lazy mappings, other processes, callbacks in the real Server and gauge remain separate unverified gates.

## Research and selection
Use existing Apache-2 fixed Sim446a443, Common442a7ab and SDFormat97d9b0 sources plus installed Sim8.15/Common5.9/SDFormat14.9. Common SystemPaths/Material and SDFormat SDF.cc give exact local candidate/fallback semantics. Server.cc installs SDFormat Fuel and Common URI fallback callbacks; helper clearing is not real Server evidence. Public getSharePath and URI APIs consulted this stage: https://gazebosim.org/api/sdformat/14/InstallationDirectories_8hh.html and https://gazebosim.org/api/common/5/classgz_1_1common_1_1URI.html . Reuse PR52 maintenance observations, do not label new upstream activity. No dependency installs, no custom opponent/algorithm substitution. SDK queries and hashing add preflight CPU/disk cost, not capacity optimization. Installed patch equivalence remains unproven; retain actual SDK winner agreement and exact binary hashes.

Alternatives rejected: Python recreation of search order; silently adding selected files after baseline; calling Server merely to inspect paths; rewriting SDF to absolute paths. They would weaken source or runtime evidence.

## Validation
Synthetic native different-root/dangling/include-config/callback/remote failures; strict client malformed/duplicate/timeout/nonzero/schema failures; recursive graph missing declaration, source drift, repeated refs/cycle, unsupported mesh/material, relative source and symlink cases; v2 preflight failure produces post and no pre success. A new named offline generated-world integration uses copied sealed original world/3textures, current declared dependencies and native resolver. It may expose an unresolved binding; retain failure rather than modifying old ZIPs or claiming runtime/VIO success.
