# Gazebo 连接组课程序列生成设计

## 目标

为完整 MaleCNS 连接组课程生成可追溯、可复现且与正式对照测试隔离的六阶段训练和验证序列。序列由统一 PX4/Gazebo 单机模型产生部署时可见的 RGB-D、运动状态和目标输入，由固定版本的 EGO-Swarm 产生教师控制与短期轨迹标签。采集结束后关闭所有仿真进程，课程训练只读取离线序列。

本设计服务于完整 `ConnectomeConstrainedCore`，不把 PPO、简化反射或蒸馏学生称为完整果蝇。它扩展《可恢复多任务课程训练设计》和《可恢复课程训练与完整连接组绑定》，但不修改已经冻结的正式果蝇与 EGO-Swarm 对照证据。

## 已选方案

考虑过三种数据来源：

1. 快速几何仿真直接合成传感器帧。生成速度快，但没有真实渲染、相机时序和 PX4 动力学，不能作为本阶段的主要真实性证据。
2. 在 Gazebo 中边仿真边训练。传感器真实性较高，但会把训练吞吐量绑定到实时或慢速仿真，也使断点恢复和确定性回放复杂化。
3. Gazebo 采集、离线训练。它保留相机、PX4 动力学和实际教师调用延迟，同时让后续长时间训练使用不可变数据集。

采用第三种方案。快速世界生成器仍负责确定性地产生开发世界；它不负责伪造 RGB-D。Gazebo 负责渲染和动力学，EGO-Swarm 负责教师规划，课程运行器负责离线训练。

## 范围

首版完成以下工作：

- 建立从课程阶段和种子到 Gazebo 世界、PX4 飞行、EGO 教师输出及 `TrainingSequence` 的完整采集链路。
- 使用三个公开开发场景验证接口、时钟、传感器、教师标签和资源释放。
- 冻结第二版课程配置和数据集契约后，生成六阶段训练与验证序列。
- 对完整 MaleCNS 运行一次受限单批性能门检，记录墙钟时间、进程峰值内存、CUDA 峰值内存及失败原因。
- 性能门检可承受时，从课程状态机开始或恢复正式离线训练。

首版不启动正式二十场对照测试，不用训练结果覆盖已有冻结报告，不执行真机飞行，也不声称离线损失下降等于实际飞行成功。

## 不可变边界

- 正式冻结封印 `9d10bb72c1fda4048f0439c9dfb823583d8464a8491349f9e732e9cced87d937`、正式二十场世界、轨迹和结果不得进入训练或验证目录。
- 模型输入只能包含 `Observation` 已有的 RGB、深度、帧时间、位置、速度、航向、角速度和目标字段。
- 世界几何、障碍物未来运动和无噪声状态只能用于教师计算、离线净空标签和数据质量检查，不能写入学生输入数组。
- 果蝇与教师使用同一机体、传感器观测、速度和加速度限制。安全层若在采集中生效，必须在样本清单中记录，不能静默改变教师标签。
- 已提交的 v1 smoke 配置、状态、检查点摘要和报告保持不变。真实数据使用新的 v2 配置与输出目录，避免破坏恢复身份。

## 组件

### 课程语料配置

新增独立语料配置，声明数据集版本、阶段、世界族、训练和验证种子、每个种子的回放数、最长仿真时间、相机参数、动力学限制、扰动参数、教师身份和输出根目录。

配置加载器拒绝以下情况：

- 训练、验证、三个开发场景或正式测试种子之间存在重叠。
- 阶段缺失、顺序错误、空种子集、非正回放数或非正时限。
- 教师提交、容器摘要、机体摘要或传感器摘要缺失。
- 输出路径位于正式冻结证据目录内。
- 扰动配置允许真值进入学生观测。

第二版课程配置引用带版本的数据集根目录，不改写 v1 路径。每个阶段首版至少包含六条训练回放和三条验证回放；相同世界种子可以使用明确编号的传感器与扰动回放种子，但训练和验证世界种子始终互斥。数据量可以在性能门检后通过新增数据集版本扩展，不能原地追加到已封存版本。

### 世界构建

语料生成器复用现有 `benchmark.worlds` 的车辆包络、可通行性验证和 SDF 写入规则，并为六阶段提供明确世界族：

- `stability`：开阔空间、目标方向变化和有限横风，不设置近障碍。
- `looming`：单个及少量正面障碍，覆盖左右规避方向和不同接近速度。
- `corridor`：连续墙体、随机门隙、转弯和高度变化。
- `forest`：静态柱状与箱体障碍的随机组合。
- `dynamic`：在静态环境中加入按仿真时间运动的障碍物。
- `disturbance`：在复杂环境中加入风、深度噪声、帧延迟和有限丢帧。

每个生成世界必须通过车辆包络膨胀后的静态可通行性检查。动态阶段还要检查障碍物运动边界，确保其不会永久封死唯一通路。生成的世界 JSON、SDF 和生成配置分别计算 SHA-256，并在回放前复制到该序列的输入快照目录。

### Gazebo 回放会话

每次回放只启动一架统一机体。会话负责：

1. 启动固定版本的 Gazebo、PX4 SITL、桥接进程和 EGO-Swarm 适配器。
2. 等待仿真时钟、PX4 健康状态、RGB-D 相机及教师端点全部就绪。
3. 使用同一仿真时钟采集观测、教师决策、短期轨迹和质量标签。
4. 在到达目标、发生碰撞、超时、传感器失效或教师失效时形成明确终止状态。
5. 正常关闭本次会话创建的进程，并按进程身份检查资源释放。

生成器只终止自己记录的进程树，不按进程名称清理全机进程。资源检查区分退出成功、超时后有序终止和残留失败。存在残留时停止后续回放并输出需处理的进程身份，避免重复启动竞争仿真。

### 教师与标签

教师使用可核验的上游 EGO-Swarm 源码、提交标识和容器或构建摘要。EGO 适配器只接收与学生相同的 `Observation`。每个采样点记录：

- 教师速度和偏航率命令。
- 由教师参考点组成的固定长度 ENU 短期轨迹；不足长度时使用终止掩码而不是伪造未来点。
- 当前机体包络到静态和动态障碍物的最小净空。
- 教师调用的实际墙钟时间和是否经过公共安全投影。
- 到达、碰撞、超时、教师失败和传感器失败状态。

教师调用超时、时间戳过旧、非有限命令或轨迹不完整会使该序列失败。失败回放保留诊断元数据和日志，但不写入课程数据目录。

### 序列写入与封存

现有 `TeacherSequenceRecorder` 继续负责把类型化观测和教师输出转换为 `TrainingSequence`。在其外层增加数据集清单与事务式提交：

- 每条序列先写入临时目录，完成数组校验、哈希校验和回读后再原子改名。
- `manifest.json` 记录 split、世界种子、回放种子、阶段、教师身份、世界摘要、配置摘要、样本数和终止状态。
- 数据集根清单列出所有预期与实际序列、失败回放、文件哈希及生成工具提交。
- 数据集只有在所有要求序列完成、训练与验证种子互斥检查通过、所有文件可回读后才能封存。
- 封存后再次运行只做验证或拒绝写入；需要补充样本时创建新版本。

RGB-D 原始数组可能较大。首版保留训练特征所需的统一分辨率和深度精度，同时把原始 Gazebo 日志列为可选诊断产物，不纳入 Git。仓库只提交配置、封存清单、摘要和小型开发验证报告。

## 数据流

```text
课程阶段与独立种子
        |
        v
确定性世界 JSON/SDF -----> 输入快照与哈希
        |
        v
PX4 + Gazebo 单机 ----RGB-D/状态----+
        |                            |
        +------同一 Observation----> EGO-Swarm 教师
                                     |
                     控制/轨迹标签 --+
                                     v
                         TeacherSequenceRecorder
                                     |
                              临时序列 + 回读
                                     |
                               原子提交与封存
                                     |
                          完整 MaleCNS 离线课程
```

## 开发验证与冻结顺序

采集接入先在三个公开开发场景运行：单障碍、走廊和混合环境。这三场只验证数据流，不进入六阶段训练或验证集。每场必须证明：

- RGB 与深度尺寸匹配，时间戳单调且帧不来自未来。
- 观测可以经过现有编码边界，未出现世界真值字段。
- EGO 输出有效、教师实际延迟被记录、短期轨迹长度符合契约。
- 序列能够写入、回读并得到相同摘要。
- 会话结束后本次创建的 PX4、Gazebo、EGO 和桥接进程全部释放。

三个场景通过后冻结语料配置、数据契约和生成器提交。冻结之后再生成正式六阶段语料；不得根据正式语料中的训练结果修改单个测试世界或教师标签。

## 完整模型性能门检

数据集封存后先执行只包含一个短序列、一个优化器批次和一次验证前向的完整 MaleCNS 门检。门检必须使用完整 166,700 神经元、25,582,837 连接和正式映射，不能降级为 tiny 模型。

门检记录：

- 模型加载与单批训练墙钟时间。
- 前向、反向和检查点写入的分项时间。
- 进程峰值常驻内存、CUDA 已分配与保留峰值。
- 实际设备、PyTorch/CUDA 版本和是否发生回退。
- 检查点大小、可恢复性和参数摘要。

CUDA 内存不足、非有限损失、映射或身份不一致、单批无法完成时，门检失败关闭。失败后先优化稀疏执行或调整批次和截断长度，再重新建立一个有版本的训练配置；不得换成 PPO 或 tiny 模型并继续称为完整果蝇。

门检通过只表示可以开始离线课程，不表示满足 35 ms 实时决策门槛。实时延迟仍由后续稀疏运行时工作单独解决。

## 失败处理

- 世界不可通行：记录被拒候选与原因，按确定性候选序列继续；超过上限则整个数据集生成失败。
- PX4、相机或仿真时钟未就绪：终止本回放，保留日志，不提交序列。
- EGO 超时或崩溃：标记教师失败，不以安全层命令替代教师标签。
- 碰撞或超时：序列可作为带终止标签的有效困难样本，但必须由配置预先声明允许；否则进入失败目录。
- 磁盘不足、哈希不一致或回读失败：停止生成，不修改最后一个有效数据集版本。
- 资源未释放：停止队列并报告精确进程，不能继续启动下一场。
- 用户中断：完成当前原子操作后退出；已提交序列保留，临时目录在下次恢复时验证后清理或隔离。

## 测试策略

- 配置测试覆盖种子重叠、正式种子污染、非法阶段、缺少教师身份和输出路径越界。
- 世界测试覆盖六阶段特征、确定性、包络可通行性和动态障碍边界。
- 会话测试使用受控假进程验证就绪、超时、只清理自有进程和残留失败。
- 记录器测试确认世界真值不会进入输入、教师延迟只进入元数据、失败回放不会进入课程目录。
- 数据集测试覆盖原子提交、恢复、封存、重复运行、文件篡改和训练/验证互斥。
- 三个开发场景执行真实 PX4/Gazebo/EGO 接入测试并生成摘要。
- 完整模型单批门检保存测量报告和恢复检查，不以估算代替实际结果。
- 最后运行连接组课程测试和完整仓库测试；已有 MaleCNS 空分组警告单独记录。

## 完成标准

- 三个开发场景均产生可回读序列和完整资源释放证据。
- 六阶段版本化数据集包含配置要求的全部训练、验证及失败记录，且封存清单校验通过。
- 正式冻结测试文件、种子和封印未出现在任何课程输入中。
- v2 课程配置能加载封存数据集，并拒绝未封存、被篡改或身份不匹配的数据。
- 完整 MaleCNS 单批门检给出实际时间和内存结果；成功时生成可恢复检查点，失败时给出可定位的硬错误。
- 仓库测试通过，且报告明确区分 Gazebo 仿真证据、离线训练结果和尚未验证的实机能力。
