# Owned online estimate output in disarmed capture

The immediate missing production leg is that the actual online OpenVINS process flushes fast predictions to fast.jsonl, but NativeClient returns only an IMU acknowledgement. Capture cannot consume those predictions online. This change connects that existing native output to the actual capture client, without replaying a completed study, modifying the consumed native adapter, or declaring an estimate qualified.

Use an explicit `--online-estimate-feed` selection in capture_disarmed_sensors. The same selection travels through worker_options and the exact execution declaration. It requires a declared, bound native capture and rejects restart/fault profiles. The ordinary legacy route remains unchanged. Actual create_client selects a managed subclass of NativeClient; ShadowInput's existing delivery/failure and CaptureJournal cleanup therefore own the new leg.

The managed client only reads its newly created fast.jsonl after the matching native acknowledgement. It checks the actual 20ms target grid generated by the existing C++ adapter, the triggering IMU sequence/sample, last delivered camera stamp, native call clocks and complete bounded JSONL payload. Each4ms IMU acknowledgement can release at most one fast prediction. Missing, extra, truncated, oversized, mismatched or regressed output latches failure. No following camera/IMU request is sent after failure. Native state/covariance values are retained verbatim; quality/reset remain null and every qualification remains false. Camera acknowledgements and fast rows are joined in a prospective online-estimates.jsonl with the owned child PID, sample/receipt clocks and source arrival. Only latest camera/fast rows are retained in memory.

Each operation uses the inherited2s transport budget, checked again after bounded file consumption. There are no new arbitrary user callbacks. Regular filesystem/logging operations and the inherited first-ack runtime-binding callback are not hard-cancellable; outer process supervision remains mandatory. This is not a real-time/flight guarantee. Cleanup closes the additional descriptor/journal even when parent cleanup fails, preserving the primary failure.

Alternatives considered: changing C++ acknowledgement content would need a new build and native admission; retrospective full-file parsing cannot establish online availability. The bounded live drain reuses the existing flush-before-ack order and explicitly refuses incompatible protocol output.

This is the concrete native-output leg of a future managed source, not the complete EstimatedControllerState producer: calibrated image-time optical pose, measured nonzero offset support, actual PX4 fusion/source/reset evidence, controller/mission orchestration and planner remain pending. No ODOMETRY/ARM/control sender is introduced. No positive health, covariance calibration, source authentication or fusion/flight authority is invented.

Retain original4GiB physical gates,330/315/360/300s scope/inner/outer/worker limits, original sensors/precision/safety/RTF, consumed studies and all UNKNOWN/evidence limitations. Do not dispatch native processes, import simulator/SDK, poll resources or run old native attempts in this software task. User explicitly authorized inline software without staged approvals. Publish only personal/PR65 after one source review and one bounded executor fix pass.
