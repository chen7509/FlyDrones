# Target-bearing measurement capture design

Status: researched design; production implementation, final load freeze and actual capture/solve are pending. Standing autonomous authorization applies. This is a new development study, not a change to any consumed experiment or a calibration qualification. The original PNG consumer remains unconsumed/pending its own2GiB gates; cached OpenVINS, Kalibr targetv1/v2 and EGOv3 remain consumed.

## Evidence and interface decision

Kalibr1f60227442d25e36365ef5f72cd80b9666d73467 camera/IMU calibration requires a stationary target and motion of the rigid camera/IMU system exciting rotation and translation. Its pinned source needs native ASLAM/splines/backend, not just the already built AprilTag detector. Five retained reference files match the official Git tree/blob/size and SHA; full ASL/Skybotix advertising customBSD4 LICENSE is retained. A download is not installation. The official [collection guide](https://github.com/ethz-asl/kalibr/wiki/camera-imu-calibration) recommends low jitter/common-clock timestamps and beforehand IMU intrinsic correction/noise characterization; its20Hz/200Hz examples do not authorize changing our10Hz/250Hz load.

The installed Gazebo bindings expose `Link.add_world_wrench(ecm,force,torque)` and `add_world_force`. Actual read-only introspection: Gazebo8.15.0-1~noble, Python extensionSHA1369b99d39623f532dca9209066b6e6bd0bf94612f01d7ffd57bdd9e45bad01c. [Link API](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1Link.html) distinguishes force at COM from a one-step world-frame wrench at link origin. Keep gravity support as per-linkCOM force; request angular excitation by zero-force/pure-torque wrench on base_link, avoiding an accidental force moment at link origin. This API was not invoked against an ECM, model, fixture or physics engine.

Existing capture cannot directly provide this study: `parse_capture_args` requires estimator-aware native shadow/reference plus supported-ready-v1 for wire/source fan-out; `main` copies a fixed old sealed board scene. Owned ULog source recording also requires diagnostic logger/ownedAgent/wire/runtime binding/execution contract. Injecting a new world/trajectory under an old profile would violate its seal and declared workload. Implement a distinct raw measurement profile/graph with explicit new scene and force/torque identity. Keep every old mode's guards and scene selection unchanged. No dummy shadow binary/reference, monkeypatching old profile identity, disabled health fields, or virtual qualification upgrade.

## Production boundary

Create a named raw measurement contract and worker graph, `target-bearing-raw-v1`, carrying exact source/toolchain/model/target/world/motion hashes, seed, private runtime and endpoint identities. The camera/IMU producer uses the existing actual owned PX4 Popen, ownedAgent, wire ownership/startup deadlines, diagnostic logger and pidfd ULog witness/collector; it uses successful journaled RGB/CameraInfo/IMU/disarmed-heartbeat readiness, without requiring a VIO output or native trajectory reference. This is a new data-only path, not permission to weaken the old estimator-aware fan-out. Reuse capture lifecycle functions with explicit graph dependencies; do not clone the1000-line worker and diverge cleanup/safety logic.

All sensor generation remains actual Gazebo/PX4. Truth may feed abort/audit monitors only; it may not drive the excitation schedule, estimator, source geometry, IMU rows, covariance or calibration initializer. External support/torque is an explicitly declared disarmed simulation diagnostic, never a flight-controller bypass for flight tests. Preserve gravity, dynamics, collisions, rotor/controller behavior, original heartbeat freshness and armed refusal. No pose/velocity teleport/reset, kinematic rig, gravity disable, truth feedback, force clipping to hide an overshoot, or synthesized gyro/accelerometer samples. A witness permission denial stops the new study without privilege changes/fallback.

Use original simulation25s, physics1ms, IMU250Hz and RGBD10Hz160x120R8G8B8, camera near0.2/far19.1, all other model/sensor bytes unchanged. Capture all original frame/IMU rows and every failure, including startup/unseen/out-of-range frames, raw per-sensor sample times/intervals/counters and dropped native observations. No filtering, interpolation, re-timing, receipt invention or covariance/orientation fabrication. Current virtual-IMU contract remains PX4d6f12ad sensor_combined FRD compensated interval means; a fitted offset would describe that virtual stream, not certify physical IMU intrinsics or sensor-generation time.

Resolve complete merged SDF semantic frames into an absolute initial pose before freezing, not an assumed sum of nested model poses or a runtime truth-based placement. Retain all source transforms as design candidates, never measured extrinsics.

At the current horizontalFOV1.274 and160pixels, the ideal pinhole focal length is roughly108pixels. At0.60m, a0.12m tag projects to about22pixels, only2.2pixels/module with border2. Plate margins may leave the image while active tags remain; tilted/translated views may crop tags. Never hide those frames or reduce the original image/sensor workload to improve detection. Before dispatch, evaluate all planned target corners and model collision envelopes over the complete requested schedule using frozen design geometry; distinguish predicted visibility from actual native rows. If the design fails, revise the unexecuted design rather than start a known-incomplete physical experiment.

Keep original bounded startup/readiness+support lift, then sequential compact-support rotations about three world axes and translations along three axes, with time-only coefficients and a return-to-rest segment inside25s. Candidate shape is q(u)=64u^3(1-u)^3, u in[0,1], with endpoint position/velocity/acceleration zero. Candidate pulse amplitudes are8degrees/rotation and0.01m/translation over2seconds each. Final torque scales must come from the complete pinned merged rigid-body inertia, including camera lever arm and rotor links; base_link inertia alone is insufficient. Preserve existing abort ceilings1m displacement,3m/s speed,pi/4roll-pitch,0.1m ground clearance and40N total support force; add explicit target-collision/torque/angular bounds before final study freeze. Runtime state can only abort, never correct the predeclared program. Journal requested/per-link returned force and torque calls, readiness anchor, complete pre/post physics audit and any partial failure. A call return does not prove movement, safety, sensor excitation or observability.

## Measurement toolchain and quality

The pinned [ROS1 Dockerfile](https://github.com/ethz-asl/kalibr/blob/1f60227442d25e36365ef5f72cd80b9666d73467/Dockerfile_ros1_20_04) uses a mutable Noetic desktop-full base, apt dependencies and unbounded host-parallel catkin build. Do not execute it as-is. No Kalibr/Noetic-named image was seen in the limited configured Docker cache inventory; this does not prove no installation exists elsewhere. Acquisition/build needs a separate digest-bound base/dependency/source bill, full transitive license inventory, disk/network estimate and admitted owned build specification. Existing Ubuntu24.04/Gazebo Python bindings are not evidence of ROS1/ASLAM availability. No image pulled, package installed, source built or optimizer created by this design research.

Actual toolchain completion must use the original pin and exact CLI names from source: `--cams`, `--imu`, `--imu-models`, `--target`, `--bag`, `--recover-covariance`, `--dont-show-report`, `--export-poses`. Leave temporal estimation enabled. Do not pass bag cropping/downsampling, `--perform-synchronization`, artificial clock shifts, disabled time calibration or tuned noise/thresholds. The pinned CLI default is30iterations/time padding0.03s; buildProblem default spline order6/pose and bias70knots per second. Roughly1750knots per25s spline is a scale estimate, not actual variable count or certified peak. The optimizer chooses cpu_count()-1 threads and block Cholesky; CPU quota alone is not a thread-count override. Resolve this resource behavior in the admitted build/runtime plan without silently patching algorithms or claiming existing256MiB TagDetector budget covers the solver.

Do not select `calibrated` IMU model based on a YAML name or FRD scaled values alone. Freeze actual intrinsic/noise assumptions and virtual-IMU limitations before solve; no existing candidate YAML is a measured noise certificate. If such evidence is absent, solve/qualification stays pending or a separately declared intrinsic-calibration study is needed. The current25s motion capture is not a long stationary Allan-noise study.

Retain pre/post extraction counts and all raw native tag/corner rows; Kalibr's own corner-outlier filtering is enabled in pinned source. Preserve both raw input identities and actual retained/rejected estimator observations rather than labeling every input consumed. Preserve actual optimized poses, camera/gyro/accelerometer residual distributions, timestamp-delta/jitter and sample-interval rows, corner spatial coverage, axis excitation and covariance outputs. Covariance recovery is optional upstream; requesting it is required here, but a finite covariance alone is not full observability. A marginalized calibration-information rank/conditioning analysis needs documented scaling and actual upstream Jacobian/Schur provenance; do not substitute motion energy, quaternion norm, successful exit or finiteT/t for observability. Formal measured/source/flight qualification remainsfalse until independently reviewed requirements are satisfied. No post-seal scene/noise/solver tuning to pass this same capture.
