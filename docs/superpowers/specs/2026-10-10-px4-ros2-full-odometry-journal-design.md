# Versioned full PX4 odometry journal design

## Intent and qualification boundary

The checked EGO corpus still lacks a producer of authenticated, non-truth PX4 state. The existing read-only ROS 2 journal records raw CDR and source metadata but omits the decoded geometry needed by the existing `Px4OdometryCausalAdapter`. Extend that established collector with an opt-in v2 row. Keep the v1 CLI, schema, parser and old evidence unchanged. The v2 file is an offline geometry candidate only: caller-supplied run labels and DDS GID cannot prove owned PX4/Agent, clock epoch, EKF2 health, camera calibration or EGO teacher. Neither journal version can grant training capture, publish `ODOMETRY`, arm PX4 or bypass the safety supervisor.

## Fixed upstream choice

Use PX4 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4` and official `PX4/px4_msgs` `148bdb4b8214a4d8de83029777fe8d334c74db6f`. Their `VehicleOdometry.msg` Git blob is `cf117ff82cdbf191bf576db91db900b7ce34f6a7`, file SHA-256 `a528b3d0b4c1a9083a71b32c367bad71a900e959efd82b9d03a9eb0e99fe6017`, BSD-3-Clause. `position` and `velocity` are NED with the frozen frame profile; `q` is Hamilton wxyz body-to-world; `angular_velocity` is BODY_FRD; three variance vectors have their distinct units; `quality=0` is unused and not a health score. The fixed ROS 2 Humble `rclcpp` 16.0.19/CycloneDDS 1.3.5 subscription from the current `fly-ego-benchmark:humble` image uses Apache-2.0 ROS code. The existing report records official `px4_msgs` repository non-archived and push metadata observed 2026-10-07; this is maintenance evidence, not a guarantee of future support. Reusing the typed subscriber costs one bounded JSONL row per callback, avoids a new transport/dependency, and still needs a prospectively exact-byte build. Sources: [fixed PX4 message](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/msg/versioned/VehicleOdometry.msg), [PX4 ROS 2 guide](https://docs.px4.io/main/en/ros2/user_guide), [uXRCE-DDS guide](https://docs.px4.io/main/en/middleware/uxrce_dds), [pinned px4_msgs](https://github.com/PX4/px4_msgs/tree/148bdb4b8214a4d8de83029777fe8d334c74db6f).

## V2 data and failure contract

An explicit `--full-state-v2` final CLI option selects `flydrones.px4_ros2_odometry_cdr.v2`; absence selects historical v1. V2 retains every v1 sample, fault and finish field and adds seven decoded arrays: `position_ned_m[3]`, `q_body_to_ned_wxyz[4]`, `velocity_ned_m_s[3]`, `omega_body_frd_rad_s[3]`, `position_variance_m2[3]`, `orientation_variance_rad2[3]`, `velocity_variance_m2_s2[3]`. The typed C++ deserializer is the only source of these fields. JSON finite values use enough decimal precision to round-trip float32; nonfinite PX4 coefficients become JSON `null` at their exact indices, while raw CDR remains byte-for-byte retained. Reader rejects wrong lengths, booleans/strings, nonfinite JSON constants, values beyond float32, negative finite variance, schema mixing and all existing sequence/reset/source faults. Invalid geometry may be recorded but cannot become an adapter event. Unknown quaternion, position or covariance is never filled from Gazebo truth, previous frames or defaults.

The Python reader continues to audit bounded complete or failed journals. A separate offline extraction API accepts only complete v2, rechecks journal identity while reading, and yields rows marked `eligible_for_live_capture=False`. A geometry bridge may instantiate `VehicleOdometryEvent` only with an explicitly supplied provisional session/instance, then run the existing causal adapter against fixed camera stamps and extrinsics; the output remains unqualified. Until an exact-byte compiled v2 binary and owned PX4/Agent session are verified, synthetic rows cannot be called live PX4 evidence. File hashes authenticate local consistency against the file itself, not a hostile writer or CDR/JSON semantic parity.

## Verification gates

First write failing Python v2/v1 compatibility and malformed-data tests, then implement the reader. Write a failing source-level or compiled test for the opt-in C++ serializer, then implement it. Run adjacent causal-adapter and old journal tests, Ruff and diff checks. If the host is above the existing 900,000 KiB guarded ROS-build reserve and no competing work is active, compile from the exact Git-blob source tree and run a typed synthetic publisher for CDR/JSON parity and failure injection. If resource conditions fail, report C++ as implemented only and keep the build gate open. A later separately frozen unarmed owned Agent/PX4 study must bind DDS publisher identity, session/reset and clock epoch before camera/EGO association. No held-out scene or training data is used to tune this journal.
