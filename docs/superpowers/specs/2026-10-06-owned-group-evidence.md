# Owned process-group evidence

Continue existing authorized scope; only subprocess harness tests this stage, no PX4/Gazebo/estimator. The previous native refusal evidence cannot be backfilled. Reuse standard Linux/Python APIs rather than new middleware.

The real supervisor spawns a fresh session and records leader pid/pgrp/session/start_ticks from /proc while the child is still unreaped. Wait with waitid(WEXITED|WNOHANG|WNOWAIT), preserving the leader (and its PID) until cleanup finishes. Never call poll/wait before cleanup. Before each group signal require the same leader identity and own group/session, distinct from the supervisor. This prevents targeting a reused leader identity; no name-based ownership.

Enumerate group members with /proc/pid/stat, record pid/start/state/group/session. Parsing/permission/enumeration errors remain unknown, never an empty successful scan. Disappeared entries are logged races. Zombies/dead states are explicitly retained and distinguished from executing members. Initial, polling and final observations have monotonic timestamps; successful killpg means dispatch to at least one member, not confirmed termination. After grace3s, send SIGKILL only if executing membership persists or cannot be determined; wait bounded2s. Preserve every intended signal, return/ESRCH/permission/error, leader wait and final snapshot. No-SIGKILL, no-executing-members and group-absent are separate fields.

A checked exclusive JSONL journal records actions before/after signals; short writes/flush/close failures mark evidence incomplete but must not prevent safe owned-group cleanup. Keep the in-memory event record in terminal supervisor.json as fallback. Cleanup failures must not prevent attempting terminal result/ULog retention. Ownership verification failure refuses group signals and remains a visible failure, never broadens targets. Scope is this owned process group; processes escaping through setsid/setpgid are not comprehensively tracked or certified. No universal all-descendant claim.

Normal exit and timeout both use this path. Synthetic spawn/terminate injection stays available for existing unit tests but cannot produce real qualification. Existing capture return code must also reject an unqualified supervisor cleanup. Final worker.wait reaps after group cleanup, then record an after-reap scan; distinguish zombies still awaiting init from executable survivors. The original parent's unarmed/fault capture result is not rewritten as completed.

Research: CPython3.12.3 PSF license source and official subprocess/os docs, Linux kill/proc_stat/waitid manuals. Installed Ubuntu Python3.12.3/GCC13.3 kernel6.6.87.2; distribution-patch equivalence is not assumed. No new libraries/installations; polling adds only bounded cleanup CPU/IO. psutil/new daemon/cgroup management rejected for this bounded evidence need; source/licensing/maintenance snapshots retained.

Test synthetic missing group, identity replacement, malformed/protected proc records, ESRCH/EPERM, grace and escalation, monotonic time, journal short/flush/close, terminal handling. Then freeze and run real short independent process groups: ordinary exit, live child after leader exit, and TERM-ignoring descendant requiring KILL; verify side-channel child identity, signal records and post-run non-execution. A separate unrelated sentinel must remain alive. These are process-lifecycle tests, not new physical flight evidence.
