# Raw sensor profile and causal OpenVINS input contract

Purpose: prepare truthful live image/IMU delivery to the pinned native estimator. This stage implements and tests the transport-independent input contract on sealed PR34 capturev2; it does not replay OpenVINS or simulate another flight. Standing authorization covers design/plan/execution without renewed approval. Existing isolated worktree, basec02b20c.

Research first: Gazebo sensors8.2.2 tag9348f9fe8a11b9d50381819f51e17e136aedab8a GaussianNoiseModel samples per-update white noise with the SDF standard deviation, adding separately configured bias terms. Pinned OpenVINS6948812 Propagator divides continuous measurement noise variance bydt; ROS1Visualizer releases a camera only after a strictly later IMU measurement has arrived (offset-adjusted). Reuse that condition without ROS or new estimator dependencies. Agent/DDS remains100Hz default and absent runtime; do not switch source silently. Research/license/version/resource/choice evidence retained.

Profile is explicit and immutable: raw Gazebo250Hz FLU measurements converted once to FRD; no EKF subtraction, integration, orientation or pose input. Store source per-axis sample stddev, dimensional conversion density=sample_stddev*sqrt(.004), and a scalar max-axis envelope as a **model-derived candidate**, not calibrated covariance or an automatically applied estimator config. Keep bias-noise calibration unknown; no synthetic quality. Preserve current optical-to-FRD extrinsic [.12,0,-.002] and cyclic axis matrix with provenance,160x120 intrinsics, zero modeled timestamp offset not dynamically calibrated. Pin source hashes and profile digest. No noise tuning against this captured trace.

CausalInput accepts only valid imu/rgb/info records plus explicit fixed session_id and clock_id and a strict consecutive sequence index. Input clocks: sample simulator ns, callback monotonic ns and consumer wall watermark=max(arrivals already seen). Process recorded submission order, not global sorting by acquisition time; buffering cannot access future records. Native delivery events preserve original IDs/times and transformed vectors, with no output pose or fusion permission. Every input IMU is delivered once. A camera requires matching CameraInfo at the same sample stamp and an actually consumed IMU with timestamp strictly greater than camera. Matching does not synthesize missing info. Deliver oldest pending camera first; no duplicate image refresh. Only a finite source-defined camera offset0 is supported in this development profile.

Bound queues to8 RGB/8 info messages, max pending wall wait250ms, max image-to-latest-IMU sample lag200ms, maximum consecutive IMU gap4ms (first observed startup interval3ms accepted). These are explicit development transport refusal limits, not estimator latency/safety acceptance thresholds or test-set tuning. Reject invalid shapes/units, intrinsics changes, nonfinite values, forbidden truth fields, duplicate/regressed streams, sequence gaps, clock/session changes, stale waits, sample gaps and overflow. Rejection is latched; later input cannot continue under the same object. Do not invent reset counters; a new session requires a new instance and estimator reset evidence later. Expose an explicit wall-clock tick so a silent source can expire pending input; no wall-clock extrapolation from sim time.

At EOF, retain unfinished RGB/info with reason; last25s camera is expected to lack a later IMU in a25s capture and must not be forced through. Dispatch schedules and unavailable entries have fusion=false. Fixed-input timing reports causal wait from recorded arrivals and local conversion runtime separately; neither is native estimator or online end-to-end latency. Feed API does not assume thread safety; one owner is required.

Validation: analytic density units/anisotropic envelope and transform; causal no-future/no-duplicate tests; camera/info arrival permutations; session/clock/sequence/sensor failures, silent-source tick and EOF; immutable profile and defensive copies. One conversion of sealed capturev2 after archive/per-member hashes checked, every relevant input indexed, failed/pending records preserved; separate synthetic fault matrix. Full regression and one independent whole-branch review before publishing. Next gate is native consumer integration plus a new disarmed online estimator shadow; public initialized/quality remain unchanged.
