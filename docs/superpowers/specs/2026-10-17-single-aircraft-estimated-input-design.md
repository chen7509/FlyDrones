This design covers the first software change, not the entire flight qualification.

## Defect addressed here

NativeGazeboPx4Backend.observe currently derives controller position, velocity, yaw and camera pose from Gazebo model truth. Its score_sample path is already separate. Add an opt-in estimated-state source to this actual backend; preserve the explicit historical truth mode and its labels. No real source producer or command-line mode exists yet: this step is backend API integration, not a completed flight runner.

The source supplies an immutable EstimatedControllerState and implements require_ready(sim_ns) and snapshot(sim_ns, frame_ns). It owns calibrated sensor/clock/EKF2 health admission; the backend does not authenticate a supplied Python object. The source must support serialized reads from the control and setpoint threads. A caller's labels or successful callback are not measurement evidence. No new source/calibration/fusion/flight qualification flag is granted.

Estimated mode requires an explicit goal in the estimator's local ENU frame; it never silently reuses the Gazebo-world goal. It reads current simulation time and synchronized RGB-D directly, without reading model pose/history or differentiating truth. The source supplies camera pose at the exact image timestamp and body state with nonfuture sample time at most 100 ms old. Vectors must be finite, camera quaternion unit length, session stable and reset counter unchanged. On a reset, stop and re-establish the goal frame in a new run; no hidden realignment or truth fit. Check readiness before both initial and retried takeoff, before physics advancement and again at the final raw setpoint send boundary. Use the existing latched stop/LAND request path on failure; LAND return is not confirmed landing.

No callback makes an arbitrary MAVLink connection simulation-only; this change does not create a new command-line or hardware launch path.
