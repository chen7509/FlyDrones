# One-shot internal learning-role comparison producer

The next substantive learning gap is running the three existing learning roles through the actual curriculum under one explicit comparison procedure. Separate ad hoc invocations currently do not enforce a shared initialized model, validation denominator, dataset and training settings before training each variant. This phase adds that producer and its CLI route. Standing autonomous authorization applies; there is no staged approval or new chat.

Use a fresh experiment directory and sequential fresh actual sessions, in the fixed order descending-only-v1, sensory-readout-v1, shared-dynamics-v1. Every variant calls the existing run_curriculum for real forward/backward/Adam, stage gates, checkpoint and reports. Require one positive integer per-variant batch cap. Do not resume or restart a comparison root. Claim the new root exclusively before constructing any model. Release each session before constructing the next; retain JSON descriptions, not models.

Capture the first session's shared baseline before training: complete structure identity, mapping and dataset digest, feature profile, actual device, topology and dynamics format, all four initialized coefficients, initial losses, truncation, loss weights and Adam options excluding its intentionally different parameter membership. Subsequent sessions must match before their first update. Each keeps its independent role/model identity and ordinary checkpoint joins. Record complete config, cap, role metadata, actual committed counters, reports and final per-stage validation. Report early COMPLETE/FAILED separately from experiment FINISHED. Different promotion trajectories can change exposure and actual work; the same cap is not an equal-effort claim. Session counters called updates are epoch counters, not a measured optimizer.step count.

Retain RUNNING progress before each session and after each finished variant. On any exception retain the partial experiment and error, rethrow, and stop without later variants. A training exception can follow real optimizer updates before state commit; no rollback or complete effort count is promised. FINISHED means all three procedures returned, including ordinary curriculum FAILED states, not verified training success. No winner, fair upstream baseline, scientific experiment certification, source authentication, full MaleCNS, latency, memory or flight qualification is inferred.

CLI adds --compare-learning-roles mutually exclusive with --learning-profile. Comparison requires --max-batches and rejects --restart before configuration/output/session effects. Existing single-session behavior remains. Both explicit topology/dynamics options continue unchanged; defaults remain COO and clipped Euler with its known zero tau gradient at 20Hz.

Alternatives considered: shelling out to three CLI processes would obscure partial ownership and violate software test boundaries; retaining three concurrent sessions would undo corpus/model memory work. A sequential in-process producer uses the actual production path and makes failure and baseline differences inspectable.

New verification recorder must prospectively append an owned absent --basetemp to effective pytest argv, keep all created fixture files under the new raw directory, and hash that payload after every run, including failures. It must preserve streams, source before/after, clocks and timeouts. This does not repair old membrane fixture payloads. Tests default to actual inert process/resource/CUDA fixtures and run only tiny CPU neural software, never full model or target/native observer work.

All existing consumed attempts, refusal, stale old release, original resource and scope budgets, truth restrictions, false qualification flags, histories and retention correction remain binding. No resources queried, SDK command, old test rerun or native admission is part of this phase.
