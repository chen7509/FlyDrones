# Loader-selected path identity and admitted static v4 design

## Purpose and scope

This is the independent production design required after static-v3's unadmitted harness escape and lexical-path failure. The outcome is a complete typed entry/dependency bill and fixed study, reached only through a reviewed standalone coordinator. It is not permission to repair/rerun v3 or change a directory to retry it. All production in this design is **pending**. Standing autonomy covers design/plan/review/implementation without per-step approval. Use inline implementation and a fresh independent reviewer before each native dispatch decision.

Read TARGET_BEARING_STATIC_V3_HARNESS_FAILURE_REPORT.md and TARGET_BEARING_LOADER_SELECTED_PATH_RESEARCH_REPORT.md. The latter binds retained queries63/64 and pinned glibc2.39 sources. `dl-load.c` keeps a selected spelling through path construction/open and file identity; `dl-object.c` also derives shared-object origin from that spelling. Canonical inode equality alone therefore does not prove equal loader context. No current target symlink, inode, map, relocation or library success was measured by this research.

The alternative of allowing `..` globally merges caller-declared and loader-selected authority. Pure lexical normpath loses component/symlink semantics and possibly origin. Keep the old declared-path invariant, and introduce a separate typed trace-selected identity with the original spelling and exact query provenance. No global LD/RPATH/install/cap/swap change, line skip or candidate-leaf ldd.

## Typed selected-path identity

Create `tools/benchmark/native_loader_paths_v4.py`. Interface `record_selected_path(raw_path: str, *, trace_origin: dict) -> dict` is used only for an exact successful, bounded query's selected path token. `audit_selected_path(record: dict, *, trace_origin: dict, baseline_files: dict) -> None` joins it to the bill and canonical baseline. TraceOrigin contains producer-selected entry identity, role, raw argv/cwd/env, tool/input pins, query index, retained stdout SHA and exact line/token byte span. The auditor rederives token bytes and compares query outcome/limits; a caller-supplied pathname or origin label is insufficient. Declared roots/tools/recipes/outputs/candidates continue using the existing strict no-`..` contract.

Selected spelling is retained as UTF8 bytes/decoded text without replacement decoding, stripping, expansion or lexical collapse. Reject NUL/control characters, relative paths, leading `//`, unresolved/malformed/error/partial/extra-output traces and absent provenance. A Linux-path spelling is bounded to1..4095 UTF8 bytes, at most4096 component events including symlink expansion, at most40 links; exceeding a bound is a retained refusal, not truncation. POSIX unsupported spellings fail closed rather than being silently normalized.

The file observer walks original components in order, retaining directory/lstat/readlink identities and each absolute/relative symlink target. A `..` step occurs after prior link expansion and only from a traversable directory; regular-file/`..`, missing prefix, dangling link, loop, permission/encoding errors or nonregular final file refuse. Preserve repeated separators and `.` in raw spelling, though their canonical result has neither. Follow Linux component semantics; no standalone `Path.resolve`/normpath result is authority.

Open the **original** selected spelling read-only/CLOEXEC, require a regular fstat object, and stream SHA256 in64KiB chunks. Compare path-walk identities with the descriptor, canonical path stat with the same descriptor, byte count/size and fstat before/after. Repeat the original walk/readlink/path checks after hashing. Retain raw and canonical requested/resolved identities, all link/directory events, descriptor identity, size/times/hash and local clock. Any mutation or inconsistent alias refuses with partial facts. This is a controlled-static-directory check, not protection against a hostile rename race or process authentication. It uses ordinary owned file descriptors, never pidfd_getfd fallback or permission escalation.

Keep every selected line/SONAME/requested alias; a unique canonical file may have many spelling records. Canonical paths enter graph:dependencies once, with the complete alias table in a separate role. Never deduplicate entries solely by inode or SHA: hardlinks and different load spellings may have different `$ORIGIN`. Duplicate producer entry aliases with conflicting invocation/origin contexts refuse before querying; only an identical explicit producer invocation/context may share one actual query. Candidate-only paths remain fresh-hashed candidates and are never independently queried or promoted to mapped/loading evidence.

Create a distinct `static_v4_bootstrap.py` for the SDK launch boundary. Before importing project/JSON/SDK modules or creating SDK output folders, use audited primitive framing to validate the literal existing coordinator claim, recipe, full validated preidentity receipts, nonce, exact entry argv/env/cwd and current owned scope/Invocation/CG facts. Enforce this at the alternate import boundary too: prepare_calibration_capture_v4.py and calibration_capture_study_v4.py have no module-level project/JSON/SDK imports, file reads/writes, subprocesses or directory effects; only primitive definitions and sys inspection are allowed there. Their direct `__main__` paths refuse before further imports or effects, regardless of supplied argv/ticket. Importing either module defines the API without loading JSON/SDK; prepare_v4 and publish_study_v4(ticket: dict) validate the actual bootstrap ticket before deferred JSON/project/SDK imports or output effects. Auditor/verify helpers remain side-effect-free at import and cannot start preparation. This does not certify a caller interpreter's prior site/import activity or stop arbitrary Python/FFI; the authorized SDK starts with Python-S through the audited bootstrap. Test direct-main and direct-import under inert import/file/process traps before treating the intended bootstrap route as sufficient. No test dispatches a real interpreter child or SDK to prove denial.

The callable dict is an **untrusted reference**, never a truthy authorization flag or a Python-object origin certificate. Its exact fields are schema=`static-sdk-ticket-reference-v4`, nonce (64 lowercase hex), unit, InvocationID, ControlGroup and the claim/recipe/preidentity/SDK-start receipt digests; no caller-selected path is accepted. The bootstrap writes that marker exclusively after validation and before deferred imports. It then enters preparation in that same PID; preparation and in-scope study publication revalidate the reference against those actual receipts/state before effects. Windows only audits the finished study; it does not invoke a generic publisher. A manually manufactured matching-shape dict, lost/changed marker, another PID, fixture receipt, stale scope or reused nonce refuses. This is a controlled-file lifecycle with observation/race limits, not an anti-forgery sandbox against arbitrary in-process mutation. In-scope firstfacts/control code also uses audited primitive imports until the bootstrap gate, rather than importing a JSON scope helper before it.
