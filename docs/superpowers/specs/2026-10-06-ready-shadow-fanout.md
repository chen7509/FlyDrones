## Interface and failure contract

Opt-in `ready-shadow-v1` adds contiguous source_sequence to journaled source rows only in this mode. Strict existing row schema/derived transforms plus monotonic per-kind samples/arrival and writer clock checks; sequence gaps, duplicate, booleans and unrecognized fields fail. Exact immutable RGB bytes must match the already closed bounded local PPM; CameraInfo bytes/hash/path must match the recorded closed local protobuf. Native receives bytes, never a path or truth. Old capture schemas and modes remain unchanged.

One writer owner, no parallel native calls. For each source row: journal a source identity+intent; deliver an independent copy to ShadowInput; inspect its latched failure even if it returns normally; record consumer completion; then under the shared gate lock deliver a copy to readiness and record completion. Consumers may explicitly ignore depth/heartbeat where inapplicable; evidence says callback returned, not estimator update. Partial consumption cannot roll back: retain accepted/failed/not-attempted dispositions and original sequence/hash. No retry or replay after failure. A second callback or wrong writer thread is refused.

Separate short lock serializes failure latch, readiness commit and the whole physical pre-step callback. Native work occurs outside this lock; force checks can run while a source is in flight using previously committed readiness, until a prospective2s per-source delivery deadline. This is new explicit development guard, not a claim of zero latency. Once failure is latched, no subsequent gated pre-step can invoke force. A pre-step already executing when failure is discovered may finish before the latch; log the latch time and do not claim retroactive cancellation. Non-real-time file I/O/OS scheduling can add latency; this stage does not grant real-time performance. Existing source watchdog2s operational/10s startup and8s readiness remain. Pre-step checks also inspect actual writer/source errors, not only fan-out exceptions. Capture result always fusionfalse.

Opt-in CLI requires all of shadow binary/config, native reference/hash, supported-ready-v1 and substep-ready-v1; disallow reference-fault mode with online composition. Merely supplying old combinations still refuses. One native estimator process; native reference module is not another estimator. Failure/close logs are retained; finalization ordered after writer drain but before readiness/shadow/native summaries. Closure failure invalidates capture and still releases owned resources.
