## Cause and choices

The old runtime_catalog appends runtime:dependencies paths to its entry-root list. These are previous mapped leaf candidates. Sorting then checks standalone HlmsPbs before the renderer root, without the renderer's RUNPATH/direct dependency list. New readelf metadata shows the renderer entry directly needs Main/Pbs/Planar/Unlit/Overlay and carries RUNPATH /usr/lib/x86_64-linux-gnu/OGRE-2.3; Pbs lacks a RUNPATH and needs Planar/Main. Current named files exist with stable six-file before/after identities. Fixed glibc source first reuses loaded SONAMEs and traverses direct dependencies breadth-first; fixed Gz loader opens the renderer plugin as an entry library with RTLD_LAZY|RTLD_LOCAL. This explains the integration failure; successful current renderer loading/ldd from that entry remains UNTESTED. Do not claim inherited RUNPATH or change RTLD flags.

Reject global LD_LIBRARY_PATH/RPATH edits or installation: they change the collector search environment and can shadow other libraries. Reject ignoring leaves or accepting an unresolved entry: every old candidate remains in the fresh file inventory and every selected entry must return a complete dependency trace. Select an entry dependency bill: actual entry-root commands plus fresh identity coverage of their resolved dependency tree and all explicitly retained candidate leaves. No Python emulation guesses the dynamic linker's search result.
