# VIO 输入失效时的 PX4 自主指令门控

## 范围

在现有 PX4/Gazebo 视觉扰动试验中，视觉转发器向每台控制进程发送仅限本机的逐帧发布元数据。控制进程在读取 MAVLink 位姿和估计器状态后，还检查最新视觉帧的发布间隔和输入排队延迟。超过固定阈值时，停止生成和发送自主速度目标，向 PX4 请求降落，并保存触发、最后一次自主命令和降落命令的时间线。保持当前策略权重和飞行几何不变。

此元数据只是视觉**输入流**健康证据，不是 EKF2 已融合视觉的证明。PX4 的真实融合与惯性推算状态继续从 ULog 独立核对。120 ms 延迟不应触发 250 ms 阈值；400 ms 断流应在断流期间触发。随机漂移和错误位姿无法仅凭新鲜度发现，仍依赖估计器创新检验和后续真实 VIO 质量信号。

## 接口及失效处理

- 转发器在成功发布 Gazebo 视觉帧后，向 `127.0.0.1` 上的车辆专属 UDP 端口发送车辆号、源时间戳、接收/发布时间和序号。消息只用于本地仿真验证。
- 控制进程接收非阻塞数据报，验证格式、车辆号、时间范围和序号；启动时缺帧及流停顿均不视为健康。端口启用仅由压力试验入口显式指定，避免改变其他运行模式。
- 健康门控位于规划器和 `drone.send` 前；一旦失效，记录原因，执行已有的安全降落路径。发生失效后绝不再发送自主速度目标。记录最后发送、失效检测和降落请求时间。
- 试验汇总保留全部失败，并将“及时门控/请求降落”和“机体安全降落/PX4 EKF 连续性”分开判定。

## 验证边界

先写针对 120 ms 延迟、400 ms 断流、损坏/错车数据报及无数据的测试，再做单机 PX4/Gazebo 基线、延迟和断流回归；最终用 ULog 与转发日志复核时间线。当前 GZBridge 将旧位姿重新标成接收时刻，不能宣称已修复 PX4 内部 `timestamp_sample`。本阶段若无可用的 ROS 2/uXRCE-DDS 时间同步通道，只记录该限制及真实相机+IMU VIO 的后续接入条件。
