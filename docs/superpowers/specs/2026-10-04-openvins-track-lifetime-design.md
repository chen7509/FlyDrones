# OpenVINS 起飞前轨迹寿命诊断设计

## 目标与边界

解释固定预解锁窗口中为何只有 9/9 条轨迹满足静止初始化器的两个半窗观测要求。沿用 PR #25 的 608 帧图像、15,203 条 IMU、上游 OpenVINS 提交 `69488123ed9362dd44b6f28e7f4680abbff1442b`、runner、配置和 PR #26 的只读初始化日志；不改估计器参数、图像、飞行控制、安全层或初始化判定，不启动新的 PX4/Gazebo/训练回合。该研究是开发数据上的离线诊断，不是 VIO→PX4 闭环证明。

## 来源与选型

OpenVINS [上游仓库](https://github.com/rpng/open_vins)、[TrackKLT 官方 API](https://docs.openvins.com/classov__core_1_1TrackKLT.html)和 [ICRA 2020 论文](https://pgeneva.com/downloads/papers/Geneva2020ICRA.pdf)说明该前端用 OpenCV KLT 和 RANSAC，并向 FeatureDatabase 写入通过的稀疏轨迹。仓库 GPL-3.0、未归档，2025-11-30 有最近推送；本项目继续固定上述已验证提交，不因最新分支变化而改变回放。接口是隔离的 ROS-free `libov_msckf_lib.so` 和现有 runner；资源需求为 WSL Ubuntu/g++/OpenCV 与约 293 MB 构建库，不增加 PX4/Gazebo 常驻需求。直接在固定上游源码加仅写日志补丁的适配成本低且可核验。现阶段拒绝更换特征跟踪器、调低 15/15 阈值、采用未核实的学习型前端，因为那会混淆短轨迹成因和先前输入对照。

## 数据与方法

独立上游源码副本依次应用已封存的逐帧初始化补丁、半窗合格数补丁及新的 `TrackKLT.cpp` 只读补丁。单目帧记录上帧保留 ID 数、上一图像补点后的数量、KLT 成功数、RANSAC 成功数、两者交集、实际写入数据库的 ID，以及首帧/无点返回。保留逐 ID、相机号和时间戳，使解析器能计算相邻帧存活、连续寿命和预解锁两半窗的轨迹分布。记录观测位置可区分“匹配已失败”和“后续边界/掩码剔除”；日志不能影响返回路径。

解析器严格验证帧/匹配日志一一对应、各级计数单调约束、ID 唯一性、时间递增、实际写库数与逐 ID 行数一致，并保留所有失败或异常帧。以 PR #26 的初始化轨迹计数作独立交叉核对；新回放的 `states.csv` 必须与 PR #26 字节级哈希相同，否则停止作不扰动结论。输出逐帧 CSV、预解锁汇总及明确的归因边界：若 KLT/RANSAC/后筛选有明显流失，只报告观测到的阶段，不从单次日志推断视觉纹理或标定的唯一根因。

## 交付与通过标准

保存上游提交、许可证、补丁、构建与 runner/配置哈希、原始 stdout/stderr、资源与退出码、逐帧审计、全部异常、报告及逐文件 SHA-256 索引；不得覆盖 PR #25/#26 证据。解析器正常、缺失、畸形、边界、重复和计数不一致测试先红后绿；执行针对性测试、Ruff 和必要回归，独立复核后提交草稿 PR。若本机不能构建或状态奇偶校验失败，记录阻碍，不将诊断冒充修复。
