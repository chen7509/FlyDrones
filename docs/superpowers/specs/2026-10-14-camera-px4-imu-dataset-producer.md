# Recorded camera / PX4 IMU dataset production

Implement a low-memory, file-consuming calibration-input producer, not another geometry audit. It consumes the actual SHA-bound RGB manifest and every listed P6 image, the actual bound ULog sensor_combined instance0, and a byte-loaded camera rig candidate. It produces lossless RGB PNGs, an exact camera CSV, a complete raw IMU provenance journal and, only when all IMU rows meet the structural timing/data contract, a candidate seven-column IMU CSV. No ROS bag, Kalibr, OpenVINS, simulator, model, training or control runtime is launched.

Use fixed PX4 d6f12ad1 SensorCombined.msg: timestamp is gyro time in microseconds; accelerometer time is timestamp + signed accelerometer_timestamp_relative, except INT32_MAX invalid. Measurements are FRD body-frame interval averages, not invented instantaneous samples. Preserve both time fields, integration periods, clipping and calibration counters in every raw row. Do not synchronize by nearest-neighbor, interpolation, stamp shifting or discarding failed rows. Separate sample times must never become a same-time CSV row. Observed calibration counter changes latch dataset structural refusal; no implicit recovery. Nonfinite data, invalid/zero/backward/overflow sample times, invalid/zero integration periods and clipping refuse the candidate IMU CSV, while raw rows/reasons remain. All rows must meet the same-time structural contract before emitting any native IMU CSV. Integration periods must be positive integer microseconds, at most1s, and must not start before the boot epoch. This is not calibrated temporal qualification.

Candidate IMU CSV additionally requires the private attribute-frozen byte-reader result with initially read-only columns from load_imu, carrying the actually verified file digest and copied selected columns. Plain constructed columns remain unbound and cannot emit candidate CSV, even with a null epoch or a supplied SHA label. This API origin contract is not protection against arbitrary in-process reflection/mocking and is not runtime authentication. The private dict/owned arrays are not an adversarial immutable seal. Use one copied column set at dataset entry for raw journal/CSV consistency. The rig/ULog/frame-sequence epoch declaration is optional and remains caller-only. Without the exact declaration, preserve raw streams but withhold the combined candidate IMU CSV. All runtime source, clock, calibration, training and flight eligibility stay false. No covariance/orientation/host receipt/firmware authenticity is synthesized. A format-compatible directory is not proof that Kalibr/OpenVINS accepted it or measured calibration succeeded; camera RGB color and interval-average IMU semantics remain explicit.

Bounds: 16MiB ULog,100000 selected IMU rows,64MiB selected numeric columns,1MiB RGB manifest,1..512 frames,160x120x3 RGB/64KiB per PPM. Each exact recorder P6 header/pixel length is checked, then encode PNG losslessly without grayscale/resize. IDs/dimensions and intrinsic/mount bytes bind via the existing CameraRigBinding; selected files must be caller-controlled static directories. Existing portable SHA/stat/path checks do not protect hostile concurrent path replacement. Reserve a new output directory, retain input ULog/manifest/rig/evidence snapshots and failures, stream frames/raw rows, flush/fsync files without claiming power-loss durability. Do not overwrite old runs or rerun the previous camera geometry producer.

The real integration may use only existing development27201 images/ULog, preserving all original hashes. Mount remains the old static simulation candidate, CameraInfo bytes have matching same-capture content, and the epoch relation remains an unqualified assertion. No held-out tuning, full NN or heavy resource gate changes. Upstream research sources: fixed SensorCombined.msg (PX4 BSD-3-Clause); official OpenVINS supported-datasets description and Kalibr bag-format documentation. Reuse pyulog1.2.4 and standard-library PNG/zlib/CSV; no new global dependency or upstream calibration tool execution. Native CSV/image preparation supplies a concrete next calibration dependency without pretending that source ownership or independent spatiotemporal calibration is solved.
