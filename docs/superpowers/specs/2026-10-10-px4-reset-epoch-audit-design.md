# PX4 EKF2 reset-epoch audit for future student capture

## Purpose and boundary

The checked v3 recorder accepts a claimed PX4 EKF2 source, but there is still no live producer. Its preceding development ULog has position, velocity, heading and attitude resets near 1.2–4.0 s. A future producer must never splice pre-reset and post-reset coordinates into one sequence or silently rebase a global goal. This stage adds a **read-only reset-epoch audit** over pinned PX4 topic arrays. It does not construct `Observation`, claim camera calibration, certify clock epochs, start EGO/PX4/Gazebo or write training data.

## Source choice

Use the already retained development instance-0 `vehicle_local_position` and `vehicle_attitude` arrays from `results/ekf2-sample-time-dev-1701/consumed-topics.npz`. That extraction is bound to ULog SHA-256 `55428c6d37e75d7fa2d53ab67a6527b4350fa020dca4a761a44fa7aec68d1028` and PX4 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`. The source snapshot and BSD-3-Clause PX4 [local-position](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/msg/versioned/VehicleLocalPosition.msg) and [attitude](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/msg/versioned/VehicleAttitude.msg) definitions supply the six coordinate-frame and attitude reset fields audited here. The terrain-distance `dist_bottom_reset_counter` is deliberately out of scope; the eight reported transitions are not every counter change in the ULog. [PX4's current EKF2 guide](https://docs.px4.io/main/en/advanced_config/tuning_the_ecl_ekf) confirms the estimator's source/heading distinctions; the pinned message files, not today's guide, define this run's field semantics. Existing official BSD-3-Clause pyulog 0.9.0 extraction is reused; no parser installation or new flight stack is needed. Prior research observed non-archived upstream repositories and last pushes on 2026-10-08 (PX4) and 2026-08-06 (pyulog), which are observations, not maintenance guarantees. A DDS live subscriber would need an Agent/ROS runtime and actual receipt clocks; it is deferred. MAVLink local position lacks these six reset fields and is not substituted.

## Contract

Consume original frame times and exact arrays for `timestamp`, `timestamp_sample`, local `xy/z/vxy/vz/heading_reset_counter`, and attitude `quat_reset_counter`. Require one-dimensional equal-length integer arrays, non-boolean bounded microseconds, strictly increasing publication and sample times, positive samples no later than publication, and unsigned-byte reset counters. A malformed topic refuses the entire audit. Select the last publication at or before each frame; never use a later message or invent a missing topic.

Observe **every** counter transition from the first topic sample, including changes between camera frames or a wrap. The first transition permanently latches `reset_epoch_unresolved` for this single capture session. Merely seeing stable values later is not evidence of a fresh coordinate frame or transformed goal. A future independently authenticated new session may start a new tracker after an explicit policy, but this audit has no rebase operation. Return each frame, selected row identity and counter tuple, transition evidence and refusal reasons. Do not emit an eligibility grant: `eligible_for_live_capture=false` even when no transition is seen, because receipt time, clock calibration, camera extrinsics, source health, actual EGO teacher and process identity are absent.

The companion `audit_state_sample_times()` continues to assess publication/sample age. Do not change it or previous evidence. Use only the development seed 27201; do not inspect held-out runs or tune any threshold. Retain all frames and failures. Test normal/missing/transition-between-frames/wrap/malformed/future-publication cases, then audit the frozen arrays and report counts. Do not start simulation, training or Docker containers while host free RAM is below the physical/full-model gates.
