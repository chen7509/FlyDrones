# OpenVINS 预解锁旧特征淘汰原因诊断设计

## 目标与输入冻结

[PR #27 轨迹寿命审计](https://github.com/chen7509/FlyDrones/pull/27)的本地封存结果已显示开发世界 1701 的预解锁 40 帧中，每帧 18 个旧 ID 仅在 `perform_detection_monocular` 保留 9 个，另 9 个新 ID 各只写库一次。要确定旧 ID 实际在哪条上游规则被剔除，避免仅凭结果猜测纹理或 KLT。只复用 PR #25 的固定图像/IMU、PR #26/#27 的 runner、配置和上游固定提交；没有新的 PX4/Gazebo、训练或飞行控制回合。保持场景、物理精度和 15/15 门槛不变。

## 来源与适配选择

沿用 [OpenVINS 上游固定提交](https://github.com/rpng/open_vins/tree/69488123ed9362dd44b6f28e7f4680abbff1442b)（GPL-3.0；GitHub 2026-10-04 查询未归档、最近推送 2025-11-30）、[TrackKLT 官方 API](https://docs.openvins.com/classov__core_1_1TrackKLT.html)和 [ICRA 2020 论文](https://pgeneva.com/downloads/papers/Geneva2020ICRA.pdf)。`perform_detection_monocular` 在已有轨迹上顺序检查边缘、近邻栅格索引、提取网格索引、近邻栅格占用与掩码，然后才提取新点。这些分支互斥，适合直接记录每个旧 ID 的首次剔除原因。继续使用隔离 ROS-free 动态库及现有回放器，构建库约 293 MB；不引入替代跟踪器，也不变更 GPL 上游源码在 MIT 飞行栈中的边界。

## 日志与审计

新补丁只在固定上游 `TrackKLT.cpp` 的单目检测路径加入日志和局部计数：每个被剔除的已有 ID 输出原因及原图坐标；每次检测输出输入旧 ID 数、各原因数、存活数、FAST 候选数、新增数。对不需要提取的提前返回也输出一次汇总。下游 PR #27 `FD_KLT_FRAME` 的时间戳按源码调用顺序与检测汇总一一配对，防止无时间戳的内部日志被误并。解析器拒绝缺失/重复/未知原因、重复 ID、计数不守恒、旧 ID 与上帧写库 ID 不匹配、检测汇总与帧日志不匹配。窗口中每个旧 ID 的剔除原因可追溯到逐帧证据，不以候选角点数代替最终写库数。

在隔离上游副本按顺序应用前两轮初始化补丁、PR #27 轨迹寿命补丁和本轮日志补丁，构建并核对 runner 实际加载的库。对相同 608 帧/15,203 IMU 仅重放一次；新 `states.csv` 必须与 PR #27 字节级相同。保留构建/回放命令、退出码、原始日志、逐帧/逐 ID 审计、配置与软件哈希、所有失败及完整测试结果。若因日志使状态不同或解析配对失败，记录失败，不给出根因结论。

## 解释界限与交付

此诊断只能证明**固定开发回放中哪条代码分支淘汰了 ID**，不能由此直接断言图像纹理、标定、曝光或真实飞行中的唯一原因。下一步修正必须用单变量开发试验再验证初始化、实际延迟和安全失败，正式未见场景仍不可调参。完成正常、边界、缺失与故障日志测试，独立只读复核，封存逐文件 SHA-256，提交基于 PR #27 的草稿 PR。物理闭环、故障注入、5/20 机、HITL 和实飞继续按各自门槛推进。
