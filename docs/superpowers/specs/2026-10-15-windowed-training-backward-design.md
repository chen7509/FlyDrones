# Windowed backward for the existing connectome trainer

Standing authorization covers independent production work without resource polling or staged approvals. The v4 first decision remains REFUSED_UNCONSUMED; its six files, private originals,382 source snapshots and stale request/release stay immutable. No old static/metadata/SDK/physical attempt is resumed. No live resource/process/Linux query is needed for this software task.

The current trainer calls forward_sequence for the entire input, collects every command graph, then backward once. Detaching recurrent state every truncate_steps bounds cross-window recurrence but does not release each window's saved activations: all outputs remain referenced until the final backward. This is a substantive production training-memory gap for the complete connectome, independent of the already completed compressed data decode fix.

Preserve the public train_epoch/evaluate_sequences APIs, sequence-local reset, feature profiles, original dt_s=.05, all four loss terms and original per-sequence objective/gradient semantics. Keep one zero_grad, one final gradient clip and one optimizer step per sequence. Parameters must not change between windows. A pair crossing a recurrent-detach boundary still differentiates with respect to both predictions, exactly as the original full loss does. Do not detach the loss term wholesale, omit boundary smoothness, average unequal windows equally, or introduce an optimizer step per window.

Use two adjacent prediction windows, each at most truncate_steps. Each new window starts from the prior final state detached. Backward the older window before constructing the third. Normalize frame terms by full sequence frame count and smoothness by its full pair count. For a boundary a,b, backward (a-b.detach())^2 in the older window and (a.detach()-b)^2 in the newer; these are the two partial derivatives of the original pair. Report the scalar boundary value only once. No retain_graph=True is needed. Explicitly release old losses/predictions before advancing. Evaluation uses the same weighted window accounting under no_grad. Whole input features and original eager sequence storage remain; this is bounded saved-activation lifetime, not a constant-memory dataset or measured full-model peak/latency qualification.

Tests use only small deterministic CPU tensors/tiny models and the actual adjacent tiny connectome trainer. Compare objective, every parameter gradient and clipped SGD updates against an independent original full-sequence calculation for unit/unequal/oversize windows, nonzero saturation and risk weighting, batches, multiple sequences and resets. Record autograd saved-tensor lifetimes through pack/unpack holder objects, without destructor monkeypatches, and verify longer sequences do not retain a proportional number of activation objects at fixed window size. Verify late invalid input and forward failure do not step the optimizer. No full MaleCNS initialization/forward/train, real corpus, target SDK, simulator or sensor task is authorized by these software results. Host package initialization imports NumPy/SciPy/Torch.

Alternatives rejected: keeping all predictions preserves the gap; per-window optimizer updates change the algorithm; dropping or one-sided boundary smoothness changes gradients. Two-window partial-derivative accounting preserves the original deterministic model mathematics with ordinary floating summation tolerance. Full real training/source/calibration/fairness eligibility and all original budgets remain false/pending. The old v4 release was already stale after dataset evolution and is not rewritten here.
