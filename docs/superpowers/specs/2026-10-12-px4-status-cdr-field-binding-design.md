# PX4 EstimatorStatus CDR field binding

The current journal auditor verifies envelope/schema, sequence, timing, JSON field domains and CDR digest. Its `completed` result means structurally complete plus observed writer exit zero; it does not mean independently decoded fields or live source authentication. A prior fixed ROS synthetic harness independently checked its three normal samples. Generalize that useful check into a separate offline companion without changing the historical auditor, collector, firmware, frozen source tree or evidence.

Input is a regular journal path, optional observed writer exit evidence, and exact message-definition bytes SHA256 `44cba4424c224753b8249729e9bf7e530d0b34e04d5299fcf94f2677c8f50bd5` from PX4 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`. First use the existing structural auditor, then bound-read the journal and require the exact same SHA before independently parsing those bytes. Changed input, duplicate keys, unbounded/truncated lines, malformed definitions and decoder errors refuse. There is no caller-supplied decoder callback.

Reuse optional `rosbags==0.11.5`, Apache-2.0, already listed in project `cdr_audit`/dev dependencies. Its previously downloaded wheel and isolated `results/ego-cdr-field-audit-dev-1701/deps` are reused; Windows and WSL global Python lack the package, so tests must bind the existing private dependency path rather than silently skip or install/upgrade. Register the SHA-fixed primitive PX4 `.msg` in an empty type store. The official type-system API supplies `.msg` parsing and CDR deserialize/serialize; no hand-written lookalike message layout is used. Current maintenance beyond the pinned package is not newly established. Fixed PX4 source is BSD-3-Clause. No paper is claimed as proof of clock calibration or flight safety.

The named profile `px4-d6f12ad-status-cdr-fields-v1` accepts only the observed little-endian CDR1 header with zero options. The three sealed rclcpp callbacks have 140-byte payloads and exact rosbags round trips. Require exact canonical byte reserialization, including rejecting extra tails and unobserved representation/options. Compare **every logged sample**, not only the first: publication/sample timestamps, four bitmask fields, two accuracy fields, seven ratios plus their finite/unknown availability, and five reset counters. Scalar float claims compare their float32 encodings, respecting the producer's nine-digit float32 JSON representation. Unknown ratios stay null/false; they are not healthy zeros. Unlogged message fields remain outside the claim.

Return journal/message hashes, sample identities, raw/canonical CDR hashes, field-binding result, writer-completion state and unavailable ratios. `live_source_authenticated`, `upstream_loss_qualified`, `clock_epoch_qualified`, `camera_calibration_qualified`, `fusion_qualified` and `training_eligible` remain false. A zero-sample failed journal preserves its structural failure with no positive field-binding claim. A failed writer may have correctly decoded prior samples; report these facts separately. A malformed partial-write journal is refused, preserving the original file.

Verification: first implement exact decoder/format checks; then behavioral RED/GREEN for valid, rehashed CDR with misleading timestamp/fault/reset/ratio/accuracy metadata. Include mismatch in later samples, unavailable ratio relabeling, message-definition drift, input changing between reads, dependency/version refusal, malformed bytes and no authority grants. Reuse the existing sealed normal/fsync/close/partial-write journals after ZIP and consumed-member hash checks; do not rerun ROS, Docker, PX4, Gazebo or training. Record exact import origins/dependency wheel/module identity, pre/post code hashes, targeted/adjacent regression, independent review, new evidence ZIP/hash/CRC, report and PR65 publication. Historical results remain intact.

Sources: [PX4 fixed EstimatorStatus](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/msg/EstimatorStatus.msg), [Rosbags official type-system API](https://ternaris.gitlab.io/rosbags/topics/typesys.html), and the previously sealed rclpy parity checker `tools/connectome/status_synthetic_cdr_check.py`. Adaptation cost is one offline companion and bounded journal decoding; it does not require a firmware rebuild or physics memory budget. Live receipt still depends on the separate fixed firmware, Agent/PX4/GID/ULog identity, clock and unchanged resource gates.
