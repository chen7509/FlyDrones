# Disarmed live sensor provenance before online VIO

Purpose: establish a trustworthy live input path for the already-tested native OpenVINS/message adapter. This prerequisite is a sensor-only online shadow capture, not an online VIO result. Standing user authorization covers the plan and execution; no new task or repeated approval.

Research: pinned PX4 d6f12ad has uXRCE compiled, client2.4.0 (submodule711aef4); generated sensor_combined publication uses default10ms polling. Agent/ROS runtime is absent. Installing an agent alone cannot prove equivalence to the existing250Hz ULog input. HIGHRES_IMU subtracts EKF bias; SCALED_IMU quantizes/integrates and uses another timestamp. Gazebo's existing x500_base IMU publishes250Hz; pinned GZBridge rotates FLU→FRD and replaces message timestamp with hrt_absolute_time at callback, then PX4 integrates/calibrates before sensor_combined. Therefore no byte/time equivalence is assumed. First choose existing Gazebo transport for a paired sensor/ULog provenance experiment; DDS remains an alternative requiring runtime plus rate-profile changes and separate qualification.

Copy the sealed board-development world and textures to a fresh evidence directory. Keep fixed PX4 binary, vehicle/camera models,1ms physics,10Hz160x120 RGB-D and250Hz IMU. No arm/offboard/setpoint/ODOMETRY commands, no Gazebo pose/orientation input to the recorder or estimator, no gravity or motion override. Run one25s simulated disarmed capture, wall cap300s. Save every RGB frame/camera-info, raw FLU accelerometer/gyro plus explicit FRD transform, sample timestamp, callback monotonic arrival, latest observed simulation time and write timing; actual ULog and read-only heartbeat evidence. Sensor orientation is excluded. This is not a capacity or algorithm-success benchmark.

Use bounded asynchronous file writing; reject bad shape/units/nonfinite data, duplicate/regressing per-stream stamps, queue overflow or writer failure. Preserve partial evidence and failure reason. A unique transport partition/private PX4 runtime and exclusive output directory prevent collisions. Refuse to run if known PX4/Gazebo/training/test/replay processes exist; terminate only the PX4 process group started here. Record hashes, source versions and all failure attempts.

Audit cadence/gaps, heartbeats and ULog arming state, integral periods/calibration/clipping, and paired values/timestamps. A nearest-neighbor comparison is diagnostic, not proof of temporal identity. Do not retime or smooth samples to force agreement. Report callback-to-write wall delay separately from simulation sample age; neither is end-to-end estimator latency. Online estimator, clock synchronization, reset/quality producer and EKF2 injection remain blocked until input provenance is understood. Existing collision/latency/5-camera RTF failures remain unchanged.

Tests: analytic FLU/FRD vector axes, invalid/missing fields and clocks, duplicate/regression, queue/IO failures, read-only entry point isolation from armed gateway, and synthetic paired comparison with known offset/differences. Then one actual25s physical capture with all outcomes retained, regression and independent review. If input mismatch occurs, keep it as a failed equivalence result and resolve before connecting VIO.
