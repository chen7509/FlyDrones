# 单机图像+IMU 数据预检规格

目标是在现有单机 PX4/Gazebo **开发世界**采集可追溯的模拟 RGB 帧和 PX4 ULog IMU，为真实 VIO 接入前验证采样时间、帧完整性与计算负载。此项不替换定位源；当前控制器仍使用 Gazebo 真值里程计，并在结果中明确标记。既有 20 个冻结正式世界不重跑。

相机入口为 `/benchmark/rgbd/image` 的 Gazebo `Image` 消息，仅保存原始 RGB 字节、宽高、消息头仿真时间和 SHA-256；不写入 Gazebo 位姿或障碍真值。每回合输出独立目录、按时间戳命名的无损 PPM、清单、丢弃/错误计数，禁止覆盖旧证据。IMU 使用同回合私有 PX4 runtime 保存的 ULog `sensor_combined` 加速度、角速度与时间戳。分析脚本以仿真时间为假设计算帧到最近 IMU 的差值分布及覆盖率，记录假设与边界，不能通过人工移动时间轴掩盖不匹配。

开发门槛：单机能正常终止并保留所有帧/ULog；图像大小和哈希匹配；帧时间严格递增；IMU 时间单调、包含加速度和角速度；报告首末时间、帧率、覆盖和最近邻时间差。正式 VIO 门槛仍关闭，直到提供相机内参、相机-IMU 外参、统一时间基准、图像+IMU 推算位姿及协方差，并在 PX4 EKF2 中验证故障处理。五机容量 0.873 RTF 的失败不能因本预检而改变。

实现顺序：先测试帧记录的正常、重复、逆序和非法形状；再接入可选开发采集与失败留证；最后只跑一个开发世界并做 ULog 时间分析。采集开销单独记录，不用于与未采集配置比较策略性能。
