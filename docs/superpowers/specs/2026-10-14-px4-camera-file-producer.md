# PX4 camera file production interface

Build a read-only production interface for recorded PX4 state and file-bound camera mounting/intrinsics. This is a new interface/composition stage, not a repair of numeric validators and not a new simulator probe. Execute under the user's explicit continuing autonomous authorization.

## Deliverable

`CameraRigBinding.load(path, expected_sha256, body_id, camera_id)` reads an exclusive schema-v1 rig document and its intrinsic/extrinsic evidence files, bounded to64KiB each. It binds the actual bytes, expected body/camera IDs, explicit body-FRD-from-optical-camera transform, actual camera-info width/height/frame/K and evidence SHA values. Pre-existing linked/escaping files, ordinary detectable file changes, wrong IDs or reflection/nonrigid transform refuse. Inputs/results must be caller-controlled static directories: the portable pre-check/stat/open sequence does not resist hostile concurrent symlink/junction or ancestor replacement. SHA binds bytes, not a race-proof path or source owner. A hashed record is content binding only: no caller bool or SHA label grants calibration qualification. Domain distinguishes simulation candidate from hardware candidate; both remain unqualified until separate independent calibration work.

`Px4UlogCameraSource(path, expected_sha256, binding)` parses one bound ULog byte read with existing pyulog1.2.4, selecting only instance0 vehicle_local_position, vehicle_attitude, estimator_status and estimator_status_flags. Bounds:16MiB file,100000 rows per selected topic,256 numeric scalar columns per topic,64MiB total selected-column copies,4096 requested strictly increasing frames. Parser-internal memory is not certified by the selected-column bound. No parser path reopen. It uses existing EKF2 health/sample-time contracts (100ms state/status age,2s source-flag publication age,50ms state skew) and all six reset counters, latching any observed transition without automatic recovery. It never substitutes nonexistent VehicleOdometry, quality, covariance or host receipt fields.

For each camera-frame timestamp supplied in the PX4 publication/sample epoch, produce a structured row with source indices/times, exact ULog/rig/evidence identities, reasons and optional camera geometry. Geometry uses NEDâ†’ENU and body-FRDâ†’camera-optical composition, retaining source quaternion coefficients separately from the normalized rotation copy. No interpolation/extrapolation, model truth or score data is consumed. A refused row has no usable camera pose; original topic health/timing/reset reasons remain. A missing explicit epoch declaration refuses every geometry row. The optional exact schema-v1 declaration binds rig SHA, ULog SHA and canonical frame-sequence SHA to the caller assertion same-px4-boot-epoch. Even a matching declaration is unqualified, never a measured clock relation. A diagnostic geometry result is not an Observation or CaptureInputEvidence and cannot pass the recorder's exact source labels.

A small file-only CLI reserves a new result directory, persists inputs/command plus one row per frame and a completion summary, retaining every refusal and failure. It never publishes, subscribes, starts a model/backend or retries existing results. The CLI is an interface consumer, not a qualification auditor. No legacy bridge, frozen collector/build profile or existing adapter is changed.

## Why this interface

Existing CameraExtrinsic accepts numeric values and an artifact SHA label without reading the calibration file. Existing ULog audits report health but do not produce a bound camera pose. The new composition supplies actual file loading plus pose production, while retaining the distinction between byte identity, source authenticity and measured calibration. Reusing pyulog and existing NumPy/SciPy avoids a new runtime service or ROS build. ULog file availability cannot prove a live DDS source; no callback/receipt time is inferred from sample/publication time.

Alternatives rejected: copy Gazebo camera_pose as estimator output; supply calibration_verified=True from a file label; reuse ULog times as network receipt; substitute missing VehicleOdometry fields. All would weaken the original goal's evidence boundary.

## Scope and safety

All output live_source_authenticated, clock_epoch_qualified, camera_calibration_qualified, training_eligible, flight_eligible remain false. Body/camera IDs and ULog SHA bind declared content, not physical ownership or firmware equivalence. Old development optical results may create an explicitly unqualified simulation candidate, never hardware calibration; missing real calibration remains missing. The historical development27201 ULog is allowed for a new producer integration, not retuning. No held-out source/scene is used, no new formal scenes generated, and all historical failed source/reset/RTF evidence remains. Full MaleCNS and real physical/PX4 builds retain the original4GiB gates.
