# OpenVINS 预解锁静止窗口开发诊断（2026-10-03）

**结论：4 秒预解锁静止传感器窗口已在真实 PX4/Gazebo 单机进程中采集并验证，但 OpenVINS 没有在该窗口初始化；本次完整果蝇策略回合越界，VIO 仍严重发散。**不能将此结果解释为 VIO、安全闭环、果蝇策略或多机表演通过，也不能单凭这一对不同路径的开发回合判断措施的因果效应。

开发场景 1701 的 JSON/SDF 与两张纹理图像均与此前封存夹具的 SHA-256 一致。PX4 源码提交 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`，仿真二进制 SHA-256 `e8af7cbcac255ec3c79bb5fa278459fd0b130b4b189de9269e3689cb9789f4cb`。在默认 240 次估计器等待之后、PX4 起飞之前，开发开关增加 4 秒模拟时间的静止设定值发送；策略仍只通过原速度/航向接口，飞控负责姿态和电机。正式冻结配置默认 0 秒，不能打开该开关。审查同时修复了回合输出保护：任何已存在目录都拒绝复用，正式批处理日志另存，开发纹理从明确来源复制并逐文件哈希。最终全套 507 项测试及 Ruff 通过。

本次**仅一次**新的 PX4/Gazebo 采集保留在 `results/openvins-prearm-static-dev-1701/episode-run/`。仿真 67.5 秒约用墙钟 445.4 秒，粗略 RTF 约 0.152，远非实时。完整 `fly_raw` 果蝇控制器做了 691 次决策，墙钟决策中位数约 0.473 秒、P95 约 0.517 秒；物理步在决策期间暂停，因此不能将此结果当成机载实时闭环。终局为 **`out_of_bounds`**；进程退出码为 0 只表示证据流程完成，绝非任务成功。676 张 RGB、676 条相机信息和一份约 19.5 MB 的 PX4 ULog 的采集核验通过，退出后没有残留该回合的 PX4/Gazebo 进程。

预解锁窗口记录为 15.622–19.644 秒，实际 4.022 秒，发送 79 次悬停设定值。复核后的逐样本审计确认**完整窗口**有 40 帧 RGB、1,006 条 PX4 `sensor_combined` IMU；末两秒（17.644–19.644 秒）有 20 帧 RGB、500 条 IMU。两段的帧最大间隔均为 0.100 秒，IMU 最大间隔均为 0.004 秒。末两秒 PX4 EKF2 `vehicle_local_position` 的 251 条速度样本有效、无重置、最大间隔 9 ms；速度模长中位数 0.0150 m/s、P90 0.0167 m/s。**这只支持“PX4 融合估计在该段低速”，EKF2 不是独立物理真值。**

冻结的上游 [OpenVINS](https://github.com/rpng/open_vins) 提交 `69488123ed9362dd44b6f28e7f4680abbff1442b`（GPL-3.0），同一 ROS-free 运行器 SHA-256 `bf811d145e82a0b70b7eb242349d429e56261212dc5e6986491720b9fd460899`、诊断动态库 SHA-256 `31e8a063018f256a32fe4027de37c146e49e2a3859a117e897f7eee6339921ae`，以及原 v2 配置 SHA-256 `eaa40224f0de2f4c5b0f1d33504d215670544b9cc000252a0e92f404478360e6`，对这次新采集只回放了一次。离线导出保存 16,254 条 IMU、650 张落在 IMU 时间域内的原始图像。没有把 Gazebo 位姿或 EKF2 输出输入 OpenVINS；Gazebo 轨迹只在估计完成后离线评分。相机–IMU 外参和时间偏移仍是未实测标定的开发配置。

OpenVINS 以**静止法在 30.3 秒才初始化**，初始速度设为零；这个时间比预解锁窗口结束晚 10.656 秒。其前两秒（28.3–30.3 秒）仍有 21 帧 RGB 和 500 条 IMU，EKF2 速度样本有效且无重置，但速度模长中位数 0.362 m/s、P90 0.413 m/s，初始化时约 0.422 m/s。因而[上游静止初始化器](https://docs.openvins.com/classov__init_1_1StaticInitializer.html)所需的实际初始化时静止前提没有得到此份数据支持；预解锁窗口被正确记录，却没有解决初始化时机问题。

固定版本[上游入口](https://github.com/rpng/open_vins/blob/69488123ed9362dd44b6f28e7f4680abbff1442b/ov_msckf/src/core/VioManagerHelper.cpp)在开启零速度更新时不等待加速度突变，但[惯性初始化器](https://github.com/rpng/open_vins/blob/69488123ed9362dd44b6f28e7f4680abbff1442b/ov_init/src/init/InertialInitializer.cpp)仍要求初始化窗口的前后半段各有至少 15 个可计算视差的特征。此次原始回放日志在成功前反复出现前半段 `0,n < 15`，随后才记录视差 `1.553,9.430`（阈值 10）。这与**特征覆盖门槛推迟初始化**相符，并解释了为什么单靠更早的 IMU 静止数据不够；但缺少逐帧归因试验，不能宣称这是唯一原因。下一步应先检查预解锁相机视野/曝光、特征追踪和上游初始化实际窗口，再设计固定配置的独立开发验证。

初始化后的 373 张图像中，13 帧记录到非零 MSCKF 更新、共 20 次特征窗口更新；仅有视觉更新不等于估计可用。离线无缩放刚体对齐的轨迹 ATE RMSE 为 **368.08 m**，末端误差 **878.58 m**，VIO 位移约 1,298.8 m，而同重叠段的评分真值位移约 21.27 m。单次回合与先前起飞后悬停回合的路径/时序不同，不能用误差数字变化声称改进。需要先从真实上游初始化逻辑、传感器时间关系和可观测运动分析“为何初始化推迟”，再在独立开发场景检验固定的新初始化配置；不能直接把低速片段当成已验证的 VIO，亦不能绕过 PX4 和安全监督器。VIO 状态/协方差/重置健康、PX4 EKF2 外部视觉融合、故障降级、五机与二十机安全门槛、原生 Linux 容量、HITL 和实飞仍未通过。

原始结果、所有 676 张图像、ULog、相机信息、完整失败轨迹、两次审计尝试（首次仅因独立 CLI 导入路径失败）、离线 IMU/帧导出、唯一一次上游回放状态和日志、逐样本速度及采集日志保存在 `evidence/openvins-prearm-static-dev-1701.zip`，相邻 SHA-256 索引逐文件核验。独立审查指出初版归档遗漏了离线回放器和配置，因此保留初版不覆盖，另存 `evidence/openvins-prearm-static-dev-1701-reviewed.zip`：其中补入原 runner 源码/二进制、完整 v2 配置目录、复核后的全窗口审计，以及相同的原始输入和失败结果。两版 ZIP 各有逐文件 SHA-256 索引和完整读回校验。第一次审计失败未造成仿真或回放重跑；两次成功审计都只重算相同原始数据。两版归档均未内含本机约 293 MB 的上游诊断动态库，保留其精确 SHA-256 和上游提交/既有插桩补丁来源；因此**仅凭归档仍不能逐字节重建或重新执行该动态库**。此研究结果属于单机 PX4/Gazebo 物理仿真加离线 VIO 回放，不是 VIO 驱动的 PX4 闭环、更不是 HITL 或实飞。

GitHub 对约 11 MB ZIP 的上传持续返回 HTTP 408。两个原始 ZIP 在本机保持原样；供草稿 PR 审查的分支把每个 ZIP 无损分成十片（已上传的前两片每片 2 MB，其余至多 1 MB），保留原 `.sha256.json`，再用 `evidence/*-parts.json` 记录逐片大小和 SHA-256。运行 `python tools/benchmark/reconstruct_evidence_parts.py --manifest evidence/openvins-prearm-static-dev-1701-reviewed.parts.json --output <新目录>/openvins-prearm-static-dev-1701-reviewed.zip` 可以复原 reviewed ZIP；原始版本用对应的无 `-reviewed` 清单。工具拒绝覆盖并验证每片、完整 ZIP 和全部成员。两版重组文件分别与原始 SHA-256 `049669802ce921d2c1975651a665795b9faf008279ee89b5677679a230cbe172`、reviewed SHA-256 `8f6757908119f987dbc402d231885073783f55287f173a0a194b6fb786aac485` 一致；分片只是传输形式，不是新实验数据。
