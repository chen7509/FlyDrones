# Depth-study import closure on Windows

The prospective raw-depth study preparer must bind the collector's imported project modules before it permits a physical capture. Its previous scan strictly resolved `__file__` for **every** module in the Python process, including modules outside the collector. On Windows, an unrelated relative `_ops.py` entry did not exist under the working directory, so three depth-preparation tests stopped before creating their intended evidence. This was a preparation failure, not a PX4, VIO, or fruit-fly policy result.

The scan now first determines whether a module's lexical or resolved path belongs to `tools/benchmark` or `src/flydrones`. It strictly resolves and binds files in either project scope; a missing in-scope module still rejects preparation. Missing unrelated modules no longer block the closure. Two new focused tests established this boundary: the unrelated-file test failed before the change and passed afterward, while the missing project-file test passed as a fail-closed control.

The first full-library run, invoked with `PYTHONPATH=src`, returned 4,264 passed, 37 skipped and five failures in 865.66 s. Three were the Windows import-closure problem. Two inference-subprocess tests failed because the command omitted the repository root from `PYTHONPATH`; rerunning those tests with `PYTHONPATH=.;src` passed them. After the code fix, the focused/adjacent run yielded 39 passed and one Windows symlink-permission skip. A fresh full-library run using `PYTHONPATH=.;src` yielded **4,271 passed, 37 skipped, four warnings, zero failures** in 868.51 s. Changed-file Ruff and `git diff --check` passed. The warnings concern duplicate test ZIP members, sparse Torch serialization/CSR support, and unmatched MaleCNS groups; they are not new PX4 or VIO validation.

No PX4, Gazebo, Agent, OpenVINS estimator, trainer, or drone was started for this code fix. It does not qualify the raw-depth study, an owned DDS source, sensor calibration, VIO fusion, or flight. The v4/v5 synthetic DDS attempts remain separate prelaunch memory refusals documented in [PX4_ROS2_FULL_ODOMETRY_JOURNAL_REPORT.md](PX4_ROS2_FULL_ODOMETRY_JOURNAL_REPORT.md).
