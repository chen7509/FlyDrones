# PX4 diagnostic logger v13 offline preparation (2026-10-12)

`study-v13-retry` is a new, **unactivated** development study for the opt-in `source-diagnostic-v1` PX4 logger. It was prepared from the separately sealed v12 Agent study, not by changing that study or any historical capture. The source v12 ZIP has SHA-256 `0b87812d0dca6c1dfbb01ffeb732046040c668ff8d3fd6e6438325fa8de2689f`; its CRC and ten consumed members were compared with the original files and member hashes. The new study has seed 27603, an owned Agent and exact logger file/command selection, and retains 25 s, 1 ms physics, 250 Hz raw IMU, 10 Hz 160×120 RGB-D, the original motion, safety and timeouts. It does not authorize live activation.

The successful preparation declared 648 files, compared with 640 inherited from v12. The eight additions are four Python dependencies, the new gauge-policy and wire-configuration copies, and the two canonical logger files. The former 640 paths were checked against the prior baseline: only five repository Python files changed, while no previously selected external dependency was silently rebaselined. The five changed files were independently compared byte-for-byte with `git show dcb45cd:<path>` on Windows; the new working-tree bytes and their declaration hashes match those Git blobs. This proof is limited to those five changes. The inherited v12 file identities remain exact runtime file hashes, but their aggregate Git-blob byte identity has **not** been qualified.

The fixed Agent v2.4.3 selection was unchanged. The new logger declaration selects the 230-byte topic list with SHA-256 `0bb9a3d9b57c6a73c73e8fee75569b9e690857654c4631b6f6cd5b6654328994` and profile SHA-256 `ddfd6304165cb4fbbcb6c893d02d14beb45d84a0371796cdac8c7b0d90395b9a`; the child override is `PX4_PARAM_SDLOG_PROFILE=0`. The resource check observed 8 SDF documents, 46 resource edges and 40 read-only native queries. Actual v3 file-adapter validation and the one-attempt executor preparation passed. Eleven negative declarations, including missing or changed logger files, wrong command, seed, clock, Agent role and dependency omissions, all refused.

The first `study-v13` is retained as an **invalid provenance claim**. Independent review found that `capture_disarmed_sensors.py` was CRLF in the Windows worktree while the declared commit stores LF bytes. The old preparation accepted the worktree hash as committed source without comparing the Git blob. It did bind the actual runtime bytes, but its `accepted_committed_source` label was too strong. The file was restored to the exact Git blob bytes, the preparer was changed to require matching declared commit-blob hashes for changed sources, and `study-v13-retry` was generated under a new path. The first output, its audit and the reviewer finding remain in the evidence. No first-attempt file was overwritten.

The independent retry audit rechecked the v12 archive, source hashes, real v3 file adapter, executor binding, all 11 refusal cases and absence of `activation-request`, `dispatch`, `completion`, `capture` and `audit` outputs. A separate Windows Git audit verified the five changed files against the actual commit blobs. The preparation and audit ran without constructing PX4, Gazebo, OpenVINS or Agent instances. No ODOMETRY was sent, no EKF2 parameter changed, and no drone was armed.

Focused v3/logger regression reported **19 passed, 75 deselected**; both preparation/audit scripts passed Ruff and `git diff --check` found no content error. Independent code/evidence review confirmed the CRLF provenance gap was closed and found no remaining reproducible Critical or Important issue. This is a focused check plus two independent offline audits, not a full repository regression or a physical validation.
