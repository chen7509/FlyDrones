# PX4 启动日志与状态联合门禁：固定输入阶段（2026-10-10）

**已实现受管状态回复与新创建 PX4 日志成功行的联合门禁，尚未接到现有捕获回调或真实 PX4。** 它属于[两阶段计划](superpowers/plans/2026-10-10-px4-startup-phase-gate.md)任务 2。上一阶段的只读探针只证明一次受管命令回复；本阶段要求日志与状态在同一个受管进程身份和有限时钟窗口内同时成立，才能向调用者返回“可构造冷 TIMESYNC 会话”的阶段证据。门禁本身不构造会话、不发送 MAVLink、不给 EKF2 注入或飞行授权。v10 的首次 TIMESYNC 未发布和原 2 秒拒绝仍是失败。

调用方须在 PX4 spawn **之前**独占创建零长度日志，记录设备号和 inode；本模块在每次查询核对文件类型、路径/描述符身份、长度上限、已有前缀及完整换行。它记录新字节、SHA-256、首次看见成功行的时间和行号；同一批次若有启动失败行则拒绝。源看门狗、受管进程身份、单调时钟和从 spawn 锚定、不超过 60 秒的上限在观察及转换前后均检查。状态侧只接收上一阶段真实 `OwnedMavlinkStatusProbe` 的完整证据，复核原始 stdout/退出码与固定 PX4 Onboard UDP 14588→14548 解析结果；空输出/退出 1 仅是待就绪，不会授权转换。成功结果仍为 `authority=false`、`fusion_qualified=false`。现有 10 秒源启动看门狗必须由调用方原样提供；本模块不能自行证明生产日志确实在 spawn 前绑定。

测试先在缺少接口时 RED，合成正常、部分日志行、待就绪状态、换文件、截断、同 inode 改写、失败行、时钟/身份/源/日志错误矩阵通过。复核发现失败行出现时日志摘要未入阶段证据，添加行为 RED 后修正。随后发现转换时间戳原先取在 journal 返回之前，故意延迟 journal 的测试 RED 后改为返回后取时。最终相邻测试 **58 passed、4 skipped**，改动 Ruff 和 diff-check 通过。完整套件在最后一个时间戳修正**之前**运行，**4383 passed、38 skipped、4 warnings**；修正后已重跑受影响相邻测试，不将早先完整结果冒称为修正后的完整重跑。Windows 上 symlink 建立受权限限制，该用例跳过并保留；其他替换/截断用例已验证。

WSL 中另用普通受管 Python 子进程真实打开 AF_UNIX、写入新建日志并回复 `mavlink status`，联合门禁返回 `phase=ready`、日志第 1 行、状态退出码 0，子进程正常退出。它没有 PX4/Gazebo/OpenVINS、没有创建冷会话，也没有检验真实 25 秒物理负载。该夹具对同 UID 恶意进程、内核/文件系统 hostile ABA 和异步文件写入实时中止不提供证明；外层 supervisor 仍须负责进程、阻塞 I/O、后代清理与失败封存。

下一依赖是计划任务 3：在 `fixture.finalize()` 前注册同一条 1 毫秒 PostUpdate 时钟/运动回调，但把 `ObservedWireSession` 延迟到联合门禁成功之后才构造；startup 阶段的每一步仍计入原 25 秒轨迹。接入时须事前冻结新 wire 配置、进程启动时钟、预创建日志身份、有限查询频率和源健康；保持原 8 秒冷 bootstrap、2 秒进度、10 秒源启动与未解锁安全门槛。真实 PX4 状态、TIMESYNC 及 VIO/EKF2 闭环都还未测试，不得因本固定输入结果重跑或改写 v10。五机相机 0.873 RTF 对 0.95 门槛的失败也不变。
