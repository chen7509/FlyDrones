# EGO diagnostic journal reconciliation: offline candidate

Date: 2026-10-11. This stage adds `src/flydrones/benchmark/ego_diagnostic_reconcile.py`, a pure parser/join for **proposed** bridge publications and the versioned EGO v2 diagnostic journal. It cannot enable a teacher label. `runtime_source_verified`, `clock_domain_verified`, `planner_numerical_parity_verified`, and `teacher_qualified` are hard-coded false in every successful result.

The bridge record schema requires one run/session/PID, consecutive message sequence, an exact serialized ROS message SHA-256, sample time, steady-clock event time, claimed source kind/profile digest and `truth_used=false`. The planner and trajectory-server journals require independent consecutive per-process sequences, separate PIDs, the exact event fields of `ego_causal_readonly_v2.patch`, and monotonic steady clocks. The reconciler binds the selected command back through its serialized digest, the server's B-spline digest and lossless `int64 → int → uint32` ID, the planner's plan record, completed map revision and distinct depth/pose and available odometry sources. It checks selected node-clock ordering and rejects source publication after receipt, ambiguous repeated bytes, journal gaps, counter jumps, unknown fields, nonfinite starts, cloud map writes and the unbound depth-odometry extrinsic. A previous-trajectory start needs a same-session parent plan. An old plan command after newer bridge observations remains a historical identity/control reference with `current_observation_match=false`; it does not become a fresh target.

The full fixed patch's event-name and field-name sets are checked against the code. The first test run failed collection before the module existed; a deliberate stub then failed the exact-chain test. Subsequent targeted tests exposed permissive schema booleans, unknown fields, counter gaps, malformed event types, single-plan-only matching and an unselected map application with no matching depth receipt; these were corrected. Final adjacent EGO tests: **94 passed**, changed-file Ruff passed, and `git diff --check` passed for source/plan/spec changes. These are synthetic unit tests. They do not establish that the current bridge actually journals serialized ROS bytes, that its JSON observation comes from PX4 EKF2 and a calibrated camera, that the patch compiles against Humble, that CDR bytes match across Python/C++ processes, or that `/clock` and Linux steady clocks share the assumed domains. The offline `EgoCausalJoin` remains a separate conservative same-observation check, and no real source sequence is invented to satisfy it.

Before any corpus use, implement and test the bridge's exact serialized-message producer with source/ULog/calibration and session identity; bind its records to the patched planner/server binaries; demonstrate clock-domain and CDR parity; compare patched and unpatched trajectories on identical development input; then perform an owned unarmed single-drone capture. Keep all failed joins and previous PX4 TIMESYNC/WSL2 capacity failures. This stage did not run Docker, ROS, PX4/Gazebo, training or a physical comparison.
