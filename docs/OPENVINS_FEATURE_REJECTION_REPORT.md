# OpenVINS 视觉特征淘汰阶段诊断（2026-10-03）

**结论：前一轮人工纹理开发场景中的 OpenVINS 并非没有任何候选轨迹；它在
361 个已初始化的图像窗口里尝试了 961 次候选特征更新，但没有一个通过
三角化及其细化阶段，因而没有视觉约束进入滤波器。**这些是“特征×窗口”
尝试次数，不能当成 961 个互不重复的特征。轨迹仍是惯性漂移，VIO 和
PX4 EKF2 视觉融合门槛均未通过。

本次只重播 [人工纹理开发世界报告](OPENVINS_TEXTURE_DEV_REPORT.md)已保存的
604 张 RGB 与包含 15,107 条的 PX4 ULog IMU 输入（适配器实际喂入
15,096 条）；没有再次启动 PX4/Gazebo，
也没有改完整果蝇控制器或封存的正式对照场景。配置、图像、IMU、
适配器程序均与原运行相同。OpenVINS 使用上游提交
`69488123ed9362dd44b6f28e7f4680abbff1442b` 的独立工作树，
仅增加输出日志的补丁。先记录 VioManager 送入更新器的候选数，
再在 UpdaterMSCKF 内记录有效克隆量测、三角化和卡方筛选后的数量。
第二版日志进一步读取上游 [FeatureInitializer 的拒绝条件](https://docs.openvins.com/structov__core_1_1FeatureInitializerOptions.html)。
上游 [MSCKF 更新源码](https://github.com/rpng/open_vins/blob/69488123ed9362dd44b6f28e7f4680abbff1442b/ov_msckf/src/update/UpdaterMSCKF.cpp)
会修改候选向量，所以原先 `MSCKF update (0 feats)` 是最终数量，
不能单独指出淘汰环节。

| 361 次更新窗口内的阶段 | 特征尝试次数 |
|---|---:|
| 送入 MSCKF 更新器 | 961 |
| 保留至少两条有效克隆量测 | 183 |
| 线性三角化失败 | 178 |
| 线性三角化成功但细化失败 | 5 |
| 进入卡方筛选 / 视觉更新 | **0 / 0** |

178 次线性失败中，167 次求出的深度小于 `min_dist=0.1 m`，
96 次条件数超过 `max_cond_number=10000`，5 次深度超过
`max_dist=60 m`；这些条件**可以在同一特征上同时成立**，不能相加。
5 次细化失败中，4 次同时超过最大深度和基线比 `40`，1 次仅超过
基线比。上游代码即使在线性三角化失败后仍调用细化，因此随之产生的
178 条“深度零/NaN”日志属于**次生输出**，未重复计入 5 次独立细化失败。
另有 401 条拒绝日志来自 MSCKF 调用窗口之外的当前轨迹可视化重建，
审计器根据调用前后标记排除了它们。

两次仅加日志的重播与原版运行的 `states.csv` SHA-256 完全相同：
`f0f1966527c80bc49a5d219053a3e9c282aeb04eab7439dccd0fe3d265f8740f`。
这支持插桩没有改变本次估计轨迹，但不证明上游算法本身正确。
原版离线轨迹对 Gazebo 真值的无缩放刚体对齐 ATE RMSE 仍为
**65.82 m**。Gazebo 真值只在估计结束后评分，从未送入 OpenVINS；
原任务控制器则仍使用 Gazebo 真值里程计。相机–IMU 动态时间偏移、
暂定外参和沿用上游示例的 IMU 噪声尚未标定。低克隆量测数与负深度
表明应检查轨迹寿命、相机/IMU 坐标与时间及真实几何激励；本证据
**不能判定具体哪一项是根因**，也不授权放松三角化门槛来冒充通过。
