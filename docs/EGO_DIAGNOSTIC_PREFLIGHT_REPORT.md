# 固定 EGO 运行时诊断接入前检查

**状态：仅完成上游源码与接口预检，以及一个可选的桥接会话门禁；没有上游 C++ 插桩、补丁镜像、真实教师标签或新的物理对照。**固定上游仍是 [EGO-Swarm 提交 `23a8d5a`](https://github.com/ZJU-FAST-Lab/ego-planner-swarm/tree/23a8d5a191711dd65633df689bd00f55d4dea8f9)，GPL-3.0。六个新增源码/构建文件的 Git blob 和 SHA-256、先前的固定源码 ZIP 均经 `source-preflight.json` 核对；旧检出的 WSL 上游工作树停在相同提交且无本地修改。本轮没有启动 Docker、PX4、Gazebo、OpenVINS 或训练。

固定 `ego_planner_node.cpp` 调用 `rclcpp::spin(node)`；该节点内的 FSM 与地图回调按单线程执行，但 `traj_server` 是另一进程，不能从同一节点的顺序推断服务端已经接收或采样了新轨迹。`GridMap::depthPoseCallback` 只写待处理图像/位姿并置 `occ_need_update_`；`updateOccupancyCallback` 才执行投影、射线更新与清理。近似时间同步还可能把图像和相邻时刻的位姿配对，诊断必须分别记录两者来源，不能只记图像时间戳。地图另有 `cloudCallback` 可修改占用与膨胀区；现有 `ego.launch.py` 将云订阅重映射至 `/benchmark/ego/never_published_cloud`，但只有后续实际 ROS 图与运行日志才能证明那次试验没有外来云消息。

首次规划从最新里程计取起点，后续重规划可能从上一轨迹采样。因而只在规划成功后读取“最新里程计”不能证明该里程计生成了起始状态。真正可用的只读诊断需要记录起点模式、父轨迹及采样时刻，规划前后地图修订，实际已应用的图像与配对位姿，地图历史窗口，以及成功发布的轨迹号/开始时刻。还需显式覆盖云写入、地图重置、任务目标/集群输入，或在固定单机运行中证明这些路径未活动。原始 `Bspline.traj_id` 经 C++ `int` 再到 `PositionCommand` 的 `uint32`，必须在独立进程间核对，无损且会话内不复用。消息来源摘要应在接收的原始图像/状态字节上计算并与桥接日志绑定；当前 `plan_env` CMake 没有 OpenSSL 链接，若选择 SHA-256 须先记录新依赖、许可、构建资源与编解码约定，不能只按时间戳冒充字节身份。

为了让将来的诊断会话不混入前一场景地图，桥接新增**可选** `--causal-session-id`。启用后同一桥接进程只接受第一次合法 reset；再次握手在任何新观测发布前拒绝，要求重启受控规划器。默认旧模式及历史测试语义不变。此门禁仅在合成桥接测试中验证；现有批量 launcher 尚未启用该参数，提供字符串本身也不证明 EGO 规划器与轨迹服务的进程身份。会话须在后续受控启动中与两进程 PID、二进制哈希、启动日志和重置证据绑定。

可选门禁先 RED 后 GREEN；连同现有 EGO 输入、因果关联和适配测试共 **70 项通过**，改动 Ruff 与 diff-check 通过。首次复验漏设 `PYTHONPATH=src`，两个模块在收集阶段导入失败；保留失败日志，设置项目路径后的 70 项复验通过。这不是算法失败。当前宿主空闲内存约 **0.646 GiB**，低于既有完整 MaleCNS 的 4 GiB 探测门槛，本阶段没有尝试 ROS 镜像重编译或物理场景。下一步仍是按[计划](superpowers/plans/2026-10-10-ego-causal-provenance.md)完成版本化的上游只读插桩与桥接来源日志，在固定开发输入上验证补丁可编译、真实图像入图/起点血缘/指令链和原版轨迹数值等价；未见评测集保持封存。旧 PX4 启动、五机 RTF 和 VIO→EKF2 未完成项均不因本报告改变状态。
