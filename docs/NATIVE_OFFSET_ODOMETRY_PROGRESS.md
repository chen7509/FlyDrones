## Native source and time consumption

New openvins_online_probe_v2.cpp/openvins_fast_probe_v2.h implement the target-native input consumer, with a distinct CMake target under native_offset_reset_v2. The caller passes a fresh64hex session nonce and exact integral-nanosecond calibrated offset; native configuration's actual offset and fixed camera/IMU calibration flags are checked, and the native writer includes actual PID/session/profile/offset/reset lifecycle fields on every acknowledgement and fast row. The nonce is correlation, not authentication or a binary build receipt. The selected future binary must be newly built and admitted; no old binary is silently accepted or fallback run performed.

Camera input retains its original camera timestamp. The actual ShadowInput's causal scheduler is replaced before its first input with OffsetCausalInput. Release requires retained raw IMU history strictly after camera+offset, within existing200ms lag,250ms pending and4ms IMU limits; unsupported offsets/arrival histories refuse rather than expand limits. Managed configuration consumes signed nonzero offsets, but refuses fractional-nanosecond artifacts, wrong160x120 sensor size or mutable IMU calibration in this profile. Old managed-v1 continues rejecting nonzero offsets.

Unique fast outputs stay on the physical IMU20ms grid. Each native call invalidates the upstream fast cache before propagation, calls with target_IMU-offset in camera time, then invalidates again. The actual IMU boundary is strictly past physical target and the filter's shifted state must be bracketed by actual history. Camera filter state/covariance are compared before/after. This avoids the pinned upstream cache changing its time basis after the first call; it incurs additional recomputation, not a speed/RTF claim. Actual state/covariance are emitted, no duplicated camera frames or retimed IMU samples.

## Native lifecycle and source ownership

The new native single-manager lifecycle retains state/IMU/propagator handles, initial initialized epoch and last state time. It checks them after every input and fast call, including lost initialization, changed startup/state objects, regressed filter time, nonfinite time or changed fixed offset. A discontinuity increments a terminal native reset_total, writes its actual lifecycle failure to stderr/native log and exits before another successful acknowledgement/output. No automatic reset/restart/rebase is supported. Stable fresh lifecycle emits reset_total0/reset_counter0 because this native instance constructed and monitored that generation; Python does not invent a zero for legacy null output. This covers the declared lifecycle transitions, not arbitrary pose jumps, tracking quality, all internal state mutation or producer authentication.

The concrete OffsetResetNativeClient validates actual native PID/nonce/offset/reset on every acknowledgement and prediction, using the original transport and managed2s total deadline. A reset/session/child failure latches client and source, blocking later delivery and wire state. Source stores the actual native lifecycle fields and raw state/covariance alongside the atomic calibrated image-time/current-state snapshot. Registration failure closes the newly owned v2 child through existing bounded cleanup, preserving primary and secondary exceptions. Existing old NativeClient transport/cleanup code and limits are not rewritten.
