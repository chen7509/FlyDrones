# PX4 启动门禁接入采集流程（2026-10-10）

本阶段将[已验证的联合门禁](PX4_STARTUP_PHASE_GATE_REPORT.md)接入现有未解锁采集流程，属于[两阶段计划](superpowers/plans/2026-10-10-px4-startup-phase-gate.md)任务 3。**接入代码与合成流程验证通过，真实 PX4/Gazebo、TIMESYNC、VIO→EKF2 仍未运行。** v10 在模拟时间 3 ms 时首个 `timesync_status` 未发布、原 2 秒看门狗拒绝的失败证据不变。

新配置 `capture-wire-startup-v2` 显式冻结从 PX4 spawn 起算、不超过 60 秒的启动观察上限。采集器在 spawn 前独占创建零长度 `px4.log` 并记录 device/inode，spawn 后核对源与进程身份，在 `fixture.finalize()` 前注册唯一 PostUpdate 时钟回调；启动期间每一步仍进入原 25 秒、1 ms 轨迹和独立时钟日志。只有新鲜完整的 PX4 启动成功行与同一受管进程的只读 `mavlink status` 精确 Onboard 14588→14548 证明同时成立，才记录转换。转换后等待**下一条已提交** PostUpdate，再创建并启动冷 `ObservedWireSession`；其 8 秒冷窗口从原转换时刻计，2 秒进度/源新鲜度与 10 秒采集源看门狗均未放宽。转换等待期间仍检查日志追加失败、进程身份、源健康和时钟；已完成启动证明不被 60 秒启动上限重新拒绝，但受原 8 秒冷窗口约束。旧 `capture-wire-v1` 路径保持原行为，新配置误入旧 `bind()` 路径会拒绝。

合成测试覆盖配置边界、回调在 Finalize 前注册、启动前全部时钟样本保留、日志/状态门禁之前无冷会话、转换后没有新样本时拒绝启动读取、源超时和进程身份变化、晚到启动失败行、冷窗口边界、采集结束而门禁未通过，以及启动前后注入错误时不能报告完成。独立只读复核指出并已修正两个时序问题：立即启动读取线程会先于新时钟样本，以及转换后误继续套用 60 秒启动上限。最终完整回归 **4395 passed、38 skipped、4 warnings（916.24 秒）**，改动 Ruff 与 `git diff --check` 通过。Windows 下依赖 POSIX 的既有用例被跳过；本轮未把合成接入测试称为真实飞行动力学证据。

本次只读资源核查：Windows 空闲内存约 1.1 GiB，低于既有 4 GiB 物理试验探测门槛；未发现相关 PX4/Gazebo/OpenVINS/训练进程。WSL 的固定 `/tmp/px4-sock-8` 路径仍存在，但未发现匹配的监听进程；未清理该路径或启动竞争试验。先前普通 Linux 子进程的真实 AF_UNIX 联合门禁测试仍仅支持门禁本身；本阶段接入使用受控夹具和合成流程，未声称一次新的端到端 POSIX 或物理通过。

状态区分：**已验证** opt-in 配置、联合门禁逻辑、采集回调顺序和失败拒绝（合成/固定输入）；**仅实现** v2 实际捕获接线及启动日志/状态生命周期；**未测试** v2 真实 PX4 启动、TIMESYNC 500 接受样本、基线恢复、完整 25 秒物理轨迹、VIO→EKF2 注入；**仍失败** 封存的 v10 首次 TIMESYNC 与五机相机 0.873 RTF <0.95。下一步须事前冻结新的研究 ID、v2 配置与完整 runtime 文件/资源、原始负载与失败保留规则，检查内存和固定 socket 路径占用，再决定是否允许一次未解锁物理开发试验；不能回填或覆盖 v10。
