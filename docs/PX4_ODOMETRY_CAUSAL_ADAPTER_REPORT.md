# PX4 VehicleOdometry causal adapter — development boundary

The project now has a read-only, single-session callback adapter for the fixed PX4 `VehicleOdometry` message. It records sample, publication and monotonic receipt times, selects no future state for a camera callback, and permanently refuses an observed reset-counter transition, changed source session or instance, source clock regression or a long source gap. It converts NED position/velocity and body-FRD attitude/angular velocity into the existing ENU/optical geometry convention. **Every candidate remains ineligible for live capture**; the adapter does not construct an `Observation`, call the checked recorder, publish PX4 messages or train a model.

The retained development ULog (`55428c6d37e75d7fa2d53ab67a6527b4350fa020dca4a761a44fa7aec68d1028`) was inspected read-only with installed WSL pyulog. It contains instance-0 `vehicle_attitude` (5,511 records) and `vehicle_local_position` (3,038), but **no logged `vehicle_odometry` dataset**. That absence does not show whether DDS publishes the topic; logger selection and DDS are different boundaries. The ULog also cannot recover host callback receipt times, so we did not invent them or feed it through the new adapter. As a separate convention check, 2,755 local-heading samples had a preceding attitude sample within 20 ms: the quaternion-derived NED heading absolute error median was 4.45e-8 rad and P95 1.31e-7 rad, but one sample at 3.992 s differed by 1.675 rad. This is near a recorded attitude reset at 3.996 s, without proving that reset caused the mismatch. The outlier is retained; this parity check is not a VIO or camera-calibration result. The previous six-field reset audit still refuses 221 otherwise complete camera frames. The adapter's synthetic successes do not supersede that failure.

Initial RED collection failed because the module did not exist. The first 18 synthetic tests then passed. A camera-order test failed before the adapter tracked camera high-water time, and the first larger adjacent run passed 359 tests with one skip before review changes. Independent review identified a real provenance defect: an accepted `(0.98,0,0,0)` callback quaternion was normalized in the retained event. The reproducing test failed; geometry now normalizes a separate copy while the diagnostic event keeps the received numeric coefficient. This callback adapter does not yet retain original DDS wire bytes; the next subscriber must. Review also requested an isolated `255→0` reset-wrap case and a noncommuting camera/body rotation check. All 22 focused tests pass after these additions. The final adjacent suite passed 362 tests, skipped one and emitted one PyTorch warning; changed-file Ruff and staged diff checks passed. A final standalone test invocation initially omitted `PYTHONPATH` and failed during import; its output is retained, and the corrected invocation passed all 22 cases. The review further noted that a complete 8-bit counter wrap between observed callbacks is not detectable; the spec now states this limit. The input/session strings are not an authentication mechanism, and a SHA label is not camera calibration.

The next integration must bind the callback to an owned DDS Agent/ROS 2 process, retain original message bytes, topic instance and both clocks, independently verify EKF2/heading health and calibrated camera extrinsic, and establish a fresh goal frame after any reset. Only then can an actual camera/teacher frame be considered for `append_capture_checked()`. No network ODOMETRY, EKF2 injection, unlock, training run or new physical simulation occurred in this stage.
