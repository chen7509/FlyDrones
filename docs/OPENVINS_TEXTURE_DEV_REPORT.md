# 人工纹理开发世界的 OpenVINS 闭环前检查（2026-10-03）

**结论：图像前端有了可检测特征，OpenVINS 可以静态初始化；但没有一次视觉特征进入 MSCKF 更新，轨迹严重发散。本次仍未通过 VIO 门槛，更没有接入 PX4 EKF2。**
任务控制器沿用完整果蝇原始版和 Gazebo 真值里程计，终局为
`out_of_bounds`。本试验只用于排查相机/IMU/估计器接入，不评价果蝇学习或
与 EGO-Swarm 的胜负，不触碰封存的 20 个正式世界。

## 场景与采集

从单机开发世界 `1701` 的原始 JSON/SDF 建独立副本。JSON 字节不变，
SDF 物理、碰撞、机体、传感器及插件不变，仅在地面和树干的 visual
材质中引用确定性生成的 PBR albedo PNG。其纹理是**人工、高对比**的
接口测试资产，不是假装自然场景的真实性证据。用同一机体/相机姿态的
Gazebo 相机探针拍摄：原世界第一帧 FAST-20 全图角点 4 个，纹理版
49 个，渲染图像确实显示贴图。首次探针准备脚本误添了第二个机体，
在静态 SDF 检查时发现、未启动仿真；错误输出和修正后的 v2 探针都保留。
Gazebo `gz sdf -k` 命令行检查无法解析此仓库的 `model://` 资源路径，
实际 Python `TestFixture` 载入并成功渲染；这不改变上述错误探针记录。

完整单机开发回合采集 629 张 160×120 RGB、PX4 ULog 中 15,107 条
`sensor_combined` IMU。已有核验器对原始 RGB 清单、帧文件 SHA-256、
相机信息、ULog 关联与数值/时间单调性重新检查后，604 帧位于 IMU
2.416–62.848 s 范围内，前 25 帧启动图像在范围外。604 帧按冻结
FAST-20 设置的角点中位数为 11，168 帧至少 15 个；这只是**逐帧角点**，
不等于足够长或几何上可三角化的轨迹。相机内参和速度/动力学设置
保持前一回合原样。PX4 ULog 基本主题门槛通过，滤波故障和 failsafe
标志样本为 0，外部视觉位置融合样本也为 **0**。任务仿真计时
33.85 s、状态 `out_of_bounds`；整个 Gazebo 时钟约 62.85 s，
`/usr/bin/time` 墙钟 414.02 s，粗略 RTF 约 0.152，不能当实时运行。
`run_episode.py` 内部墙钟 398.08 s；两种计时范围不同。

PX4 HEAD `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`，但其工作树
非干净状态；运行时修改的 `VehicleIMU.cpp` SHA-256 为
`a73997eaf14a5c1b224dcb4f13648874a02863d63608c60b73d8d3dc01a983a1`。
Gazebo Sim 8.15.0。OpenVINS 固定上游提交
`69488123ed9362dd44b6f28e7f4680abbff1442b`，工作树干净，
ROS-free 库 SHA-256 为
`ef649cc55d9d4471dbf9e549561a877752a48ae08d568a3433e157cb8e747b45`。
OpenVINS GPL-3.0 保持隔离的研究适配器；程序内无 Gazebo 真值输入。
纹理生成仅用项目已有 Pillow（本机 12.0.0、MIT-CMU）。

## 两次固定输入的估计

| 同一 604 帧/15,107 IMU | 初始化帧 | 实际视觉更新 | 结论 |
|---|---:|---:|---|
| v1：前一阶段冻结配置，等待 IMU 突变 | 0 | 0 | 上游日志反复显示激励低于 1.5 等初始化条件，失败保留 |
| v2：仅启用 `try_zupt=true`、`zupt_only_at_beginning=true` | 361 | MSCKF **0/361** 帧，SLAM 地标始终 0 | 静态初始化后只有惯性推算，不能称为 VIO |

v2 配置的两处差异在独立配置文件保存，仅针对该**开发**数据。
[OpenVINS 官方静态初始化说明](https://docs.openvins.com/classov__init_1_1StaticInitializer.html)
指出启用零速度更新时可在静止阶段不等待加速度突变；本试验不能据此
证明其零速度分类或视觉约束正确。上游调试日志的 `MSCKF update
(0 feats)` 记录数恰为 361；对应源码的计数是完成候选筛选后保留的
特征数。另用仅增加可视化输出的 v4 适配器重播，轨迹 CSV 哈希与
v2 完全相同：29 s 和 52 s 画面有活跃 KLT 点，而 37 s 和 61 s
几乎没有；未能确认候选在轨迹长度、三角化还是卡方检验的哪一步被
清空。不能只凭逐帧 FAST 角点数推断视觉更新。

离线评分器只在**估计器运行完毕之后**读取 `result.json` 的 Gazebo
位置真值，按时间插值，以无缩放的刚体对齐消除任意 VIO 世界坐标系：
29.0–62.8 s 的 339 个重叠状态，位置 ATE RMSE **65.82 m**，
末端误差 **170.63 m**。OpenVINS 全状态首末位移 **248.89 m**，
重叠区真值首末位移 **20.89 m**；OpenVINS 逐帧速度 95 分位
**18.40 m/s**，真值为 **0.779 m/s**。这远超 0.8 m/s 的控制约束，
无任何安全接入依据。比单看“初始化成功”更严格的自动审计把该运行
标为 `inertial_only_after_init`。误差原因尚不能归结为某一个参数；
时间偏移、相机–IMU 外参/噪声、KLT 跟踪持续性、三角化和量测拒绝
都要独立诊断，不能通过试错调封存评测集。

`evidence/openvins-texture-dev-1701.zip` 与同名 `.sha256.json` 保存
失败探针、两套单帧图像、生成器资产、完整 629 帧、ULog、采集日志、
两次 OpenVINS 输入/配置/输出、上游调试日志、v4 跟踪可视化、
逐帧 FAST 计数、轨迹 CSV、离线审计及对照图。原始未贴图回合继续由
`evidence/fly-ego-camera-info-preflight-1701.zip` 独立保留。
本包有 722 个文件，ZIP SHA-256 为
`82f9377c1ad11f824064e1cbbc5feb834f77803af3ec83d00bfb0c8355072ddd`；
ZIP 中的每个文件均已与索引中的长度和 SHA-256 逐一比对。
新增两项场景生成测试与三项离线轨迹审计测试通过；连同采集相关测试
共 18/18 通过，新文件 Ruff 检查通过。全量回归本次为 321/322：
既有 Windows 四进程 UDP 压力测试中，一个子进程在 `start.json` 刚创建
但未写完时读到空 JSON，未生成其 CSV；该项定点复跑通过。此次 VIO
分支未修改 UDP 代码，因此不宣称全量回归全绿。
后续应先在**开发**数据上查清视觉特征为何没有进入更新，并验证
相机–PX4 IMU 动态时间与噪声/外参；只有得到连续、可定量通过的
VIO 位姿和协方差，才考虑 EKF2 接口和失效注入。五机 WSL2
0.95 RTF 门槛、HITL、实飞和公平正式对照均未因此通过。
