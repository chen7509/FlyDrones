# Read-only PX4 ROS 2 source journal — implementation boundary

The project now has a bounded, read-only ROS 2 `VehicleOdometry` subscriber and an independent JSONL audit reader. The subscriber preserves the ROS serialized CDR returned by RMW, callback receipt time, available RMW metadata, PX4 sample/publication times, frame/reset fields and a local source-continuity decision. A decoded source invariant failure is retained as a failed fault row with a CDR hash; an oversized CDR is rejected before deserialization and retains only its length and hash. No source journal grants live capture, changes PX4, publishes ODOMETRY, unlocks a vehicle or trains a policy.

The journal has exclusive-create output, bounded duration (120 s), samples (8192), line reads (32768 bytes) and accepted CDR (4096 bytes). It refuses observed GID, reset, sample/publication clock, callback clock, RMW clock/sequence, frame or quality changes. It records unsupported RMW sequences as unknown rather than inventing values. These checks do not detect a complete unobserved 8-bit reset wrap, prove Agent/PX4 ownership, or relate RMW clocks to PX4 HRT. The source fault row preserves bytes only within the accepted CDR bound; an oversized CDR's retained digest cannot be independently recomputed from the journal alone. A partial I/O failure may leave an incomplete JSONL file. A syntactic `complete` terminal is not proof of process exit, fsync/close success or durable storage; the reader marks `writer_exit_and_durability_not_verified` and always sets `eligible_for_live_capture=false`.

Development tests first failed because the reader module was absent. Later RED cases exposed a duplicate synthetic RMW timestamp fixture, missing zero-message failed-terminal handling, missing fault-row handling and unbounded line reading; each original output is retained. The final targeted reader and adjacent causal-adapter suite passed **59 tests**; changed-file Ruff and diff check passed. Independent read-only review identified and rechecked installed-message hash binding, callback sample-cap and RMW continuity, pre-deserialization CDR bounds, startup/fault terminal accounting and a double-terminal I/O path. The final review found no remaining concrete writer/reader parity issue. These are Python schema/failure tests and C++ source review, not a ROS 2 callback or compiled C++ test. The synthetic CDR bytes are deliberately not claimed as valid `VehicleOdometry` serialization.
