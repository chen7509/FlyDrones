# Kalibr AprilGrid production target asset

This stage builds a target that the next camera/IMU measurement study can use. It completes real asset production and software interface verification; it does not complete measured calibration or owned sensor capture. Existing sealed capture worlds, trajectories, sensor workload and qualification gates are unchanged.

## Pinned measurement interface
[Kalibr's calibration-target guidance](https://github.com/ethz-asl/kalibr/wiki/calibration-targets) recommends AprilGrid for partial visibility and avoidance of checkerboard pose flips, requires a flat rigid board and remeasurement of printed dimensions, and recommends at least one grid element of white margin. We selected this over the previous six-rectangle FAST texture and a checkerboard. Pinned source [1f60227442d25e36365ef5f72cd80b9666d73467](https://github.com/ethz-asl/kalibr/tree/1f60227442d25e36365ef5f72cd80b9666d73467) actually selects Tag36h11.h, not Tag36h11_other.h. GridCalibrationTargetAprilgrid.hpp defaults blackTagBorder=2. Its PDF generator uses the same first nine codes, 180-degree code rotation, bottom-left ID0 and black corner symmetry squares. Assuming generic AprilTag border1 or a modern alternate code ordering would be wrong for this pin.

`tools/benchmark/make_kalibr_aprilgrid_target.py` now emits an exclusive directory containing target.yaml, lossless monochrome PNG, all nine code IDs and metric corners, Collada UV mesh, static collidable Gazebo model.sdf, model.config, retained notice/LICENSE and byte hash manifest. It has no parameter tuning knobs and does not invoke capture or calibration.

Fixed target: 3x3 tags, 0.12m design tag edge, gap/edge ratio0.25. Six data modules plus two black border modules on each side yield ten modules/tag, 16pixels/module, tag160pixels/gap40pixels. Grid560pixels=0.42m; margin200pixels=0.15m on each side; final960x960=0.72m. Code bit1 is white. Raster y goes down while target y goes up; IDs increase in x then y from the bottom. Target origin is tag0 bottom-left. Mesh x/y spans[-0.15,0.57]m and face z=0, UV[0,1]; collision slab dimensions0.72x0.72x0.02m centered[0.21,0.21,-0.01]. World placement, renderer UV behavior and multi-axis target-bearing trajectory are pending; we have not guessed them into an existing sealed scene.

The nine code constants and test-only upstream drawing function retain the complete pinned root custom BSD4 license, including the ASL/Skybotix acknowledgement, in third_party/kalibr-aprilgrid and generated assets. This product includes software developed by the Autonomous Systems Lab and Skybotix AG. No Kalibr dependencies were installed or solver/detector code built. Windows cv2 was not available in the initial inventory; this is not a claim about all other runtimes.
