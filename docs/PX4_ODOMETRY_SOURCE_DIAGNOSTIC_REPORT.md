# PX4 odometry logger source diagnostic: offline stage

The exact diagnostic logger file is now an **offline candidate**, not an installed or selected PX4 logging configuration. Its purpose is to make a later unarmed DDS/ULog `VehicleOdometry` cross-check possible. Both existing sealed physical ULogs still contain zero `vehicle_odometry` samples, so this work neither authenticates a ROS publisher nor repairs those historical runs.

The design and execution limits are in [the specification](superpowers/specs/2026-10-10-px4-odometry-source-diagnostic-design.md) and [plan](superpowers/plans/2026-10-10-px4-odometry-source-diagnostic.md). It targets PX4 `d6f12ad` (v1.17.0, BSD-3-Clause), where a nonempty `logger_topics.txt` **replaces** `SDLOG_PROFILE` defaults, as verified from pinned `logged_topics.cpp` SHA-256 `33c1cd7c55dc81d4fa53153b7f269401b67c7f6edc929707ec536203096bcfe5`. The [v1.18 release notes](https://docs.px4.io/v1.18/en/releases/1.18) describe a later change to *append* custom topics; that behavior does not apply to this fixed binary. The candidate uses `SDLOG_PROFILE=0` and a 230-byte LF-only ten-topic file, SHA-256 `0bb9a3d9b57c6a73c73e8fee75569b9e690857654c4631b6f6cd5b6654328994`. Its changed logging load is diagnostic and cannot support capacity or fair-baseline claims.

[PX4 v1.17's uXRCE-DDS guidance](https://docs.px4.io/v1.17/en/middleware/uxrce_dds) recommends the [Apache-2.0 eProsima Agent v2.4.3](https://github.com/eProsima/Micro-XRCE-DDS-Agent/releases/tag/v2.4.3), commit `73622810d984349b80bbac0ef55fc0b694d62222`, for its v2-family client and warns against substituting the newer v3 Agent. The fixed PX4 client submodule is `711aef423edd1820347b866d1e4164832df35d04`. The compatible Agent has no installed, resource-qualified executable in this workspace; its dependency build and runtime cost remain unmeasured. This stage used only Python standard library for the new auditor/CLI, adding no simulator or DDS process.

The pure auditor accepts only exact topic bytes and a seven-key declaration pinned to the PX4 commit, logger source and `SDLOG_PROFILE=0`. It rejects altered/duplicated/extra topics, CRLF or truncated lines, malformed ranges, unknown declaration keys, wrong hashes, and `bool` masquerading as integer profile 0. A path-specific `.gitattributes` rule preserves LF bytes on Windows checkout. The CLI reads only regular, nonsymlink files with bounded size and stable file identity, rejects duplicate JSON keys and emits a structured result, including for missing required arguments. Even its successful result explicitly leaves runtime topic selection, DDS/ULog parity, source authentication, live capture and training eligibility false.

The implementation was test-first: the new test failed for the missing module, then 15/15 pure-profile tests passed; the CLI test failed for the missing script, then 18/18 profile/CLI tests passed. Review identified an argument-error evidence gap; one new test failed first, then the corrected CLI and ULog preflight passed 25/25 focused tests and 137/137 adjacent tests. The first Windows test command also failed from a missing `PYTHONPATH`; its output is retained, and the corrected run passed. Changed-file Ruff and `git diff --check` passed. A true fixture CLI run returned exit 0 with `logger_file_candidate=true`, while a mutated topic file returned exit 1 and a structured refusal. Both unchanged historical ULogs were parsed again with WSL `pyulog` 1.2.4: each returned exit 1 and `vehicle_odometry_not_logged`, preserving SHA-256 `2877d4d872eb187598f1b5e8312dc97757214650423754aaec6fd8e2cd435008` and `24a5f46b1bb8213b138bdd62b787e91579e8c48fb588d740c10dd716aaef4d05`. The CLI outputs, exit codes, mutated input and old-ULog audit are in `results/px4-logger-diagnostic-dev-1701`. The source, configuration, tests, report, and raw result files are sealed with per-member SHA-256 and CRC32 in `evidence/px4-odometry-source-diagnostic-dev-1701.zip`. A full-library rerun for this new stage was not started while an unrelated Python closed-loop rehearsal was consuming the same host; the prior 4,271-pass run predates this change and is not presented as its verification.

No existing 25-second result is reinterpreted or overwritten.
