# 旧 PX4 后端的位置样本推进与失联拒绝（2026-10-12）

`MavlinkDrone.telemetry()` 原来每次调用都会更新时间 `Telemetry.t`，即使完全没有收到新位置。位置缓存因此可以无限沿用。本阶段为这个旧后端建立独立的样本推进／本机观察时间门禁，并修复拒绝异常可能中断降落和清理的调用链。它属于软件保护，不能作为 PX4 EKF2、VIO、硬件或实飞资格。

## 实现与范围

PX4 的 `LOCAL_POSITION_NED` 必须来自当前连接的 system/component，位置和三维速度均有限，`time_boot_ms` 是有效 uint32 且严格推进。重复样本不更新位置或观察时间；时间回退、异常数值、身份不符、本机时钟异常和超时会锁存拒绝。时钟高水位与旧观察是否过期在更新前检查，因此新包不能掩盖已经超时的间隔。默认本机观察上限是 0.5 秒，这是本阶段的软件策略，不是 PX4 的统一 Offboard 超时；32 位计时回绕也保守拒绝。

公开 PX4 `send()` 先读取当前可用的非阻塞遥测。单机起飞在 OFFBOARD／arm 前检查位置，五机旧启动器在任何一架 mode／arm 前检查全部五个来源。飞行期间失效会尝试先发零速度，再发送 LAND，并抛出拒绝；即使零速度发送失败也会尝试 LAND。arm 请求后的等待／上升异常同样尝试 LAND，不调用强制停桨。没有可有界查询的 armed 状态接口时拒绝等待。失效后的遥测读取继续拒绝，避免陈旧缓存被用于宣称已经降落。

`run_realtime` 退出时分别尝试 stop、LAND、close；单项失败不跳过其余清理，原有运行异常保留，清理错误输出。后端的 `close()` 现在实际调用 MAVLink 连接关闭。显式重新连接先关闭旧连接、清空旧遥测／源时间／观察时间／失败状态，PX4 活跃飞行状态拒绝重连。ArduPilot 没有继承这个 PX4 位置门槛。

## 证据与测试

本阶段先进行探索实现，再记录规格／执行计划；它不是事前冻结的物理研究。最初测试误导入另一个 editable 工作树，随后用本工作树的绝对 `PYTHONPATH` 修正；初始构造器不支持新参数也只是 API RED，均不冒称行为反例。为补足可复核的原始行为证据，最终测试去掉新构造参数，在提交 `1b52457cec7565b6f0050e4c1df98edae276a1d1` 的隔离 Git 源码副本上真实运行，得到 **22 failed / 1 passed**；模块实际路径、基础源 tar SHA、测试 SHA 和完整输出保留。

独立复核发现并修复：推进样本掩盖时钟回退／NaN，过期观察被新包恢复，旧五机在位置检查前 arm，以及公开悬停发送不消费有效遥测造成误拒绝。另有巨大整数溢出、arm 等待失败漏 LAND、退出 stop/LAND 异常漏 close、重连漏关闭和活跃会话重置的实际反例。中间严格遥测契约改为在读取时立即抛出，使7个旧测试预期不匹配；原输出保留，测试改为验证更早拒绝，不作为新的生产缺陷 RED。

最终运行日志与代码预后 SHA 见 `results/legacy-px4-position-progress-dev-1701/final-run-v1`：**57 passed**（其中本阶段23项），改动四个 Python 文件 Ruff、`git diff --check` 均退出0，运行前后四份源码 SHA 全部一致。针对性测试覆盖源缺失、重复、时间回退、异常值、身份、时钟、迟到更新、悬停来源消费、五机解锁前检查、失效中止、重连、arm 等待与退出清理；同时运行控制、分布式 PX4 软件和运动学／CLI 邻近回归，不外推整库通过。独立复核最终没有遗留 Critical／Important／Minor。

封存：`evidence/legacy-px4-position-progress-dev-1701.zip`，SHA256 见同名 `.sha256` 文件。包内含基础源码 tar、所有已保存失败输出、最终源／测试／规格／计划、版本／许可证元数据、研究记录、独立复核及成员哈希清单；ZIP CRC 与成员哈希逐项验证。

## 未完成与限制

| 分类 | 本阶段结论 |
|---|---|
| 已验证 | 假连接／确定性时钟下的拒绝、清理、源码版本隔离和邻近软件回归 |
| 仅实现 | 旧 PX4 后端的样本推进与本机解码观察保护；LAND／close 调用路径 |
| 未测试 | 新门禁的真实 PX4/SITL 运行、LAND ACK与实际着陆、网络到达时刻、源时钟同步、EKF2健康／重置与相机/VIO来源 |
| 保留失败 | 原缓存接受、全部中间测试失败；历史 TIMESYNC、物理／五机容量与EGO构建资格不变 |

递增但已经延迟的网络积压仍可能通过：此处记录的是 `recv_match` 解码观察时间，不是网络内核到达时间，也没有同步源时间。未知的 EKF2 状态无法由 `LOCAL_POSITION_NED` 反推出合格。benchmark gateway 的私有 LOCAL_NED 直接发布路径仍绕过此门禁，未获得新的安全资格。LAND 成功发送不代表 PX4 接受或实际着陆；重连也不证明上一架已落地。0.5 秒策略须在事前命名的新物理条件验证，慢速仿真触发拒绝时准确归入平台／观察条件，不能称果蝇策略失败。

本阶段没有启动 Docker 容器、PX4、Gazebo、OpenVINS、训练或硬件连接。观察到宿主空闲内存约 1.9–2.1 GiB，仍低于冻结 EGO 构建 2500 MiB 和物理／完整 MaleCNS 4 GiB 探测门槛。五机 0.873 RTF < 0.95、旧 TIMESYNC 启动失败、未训练完整参数工件、EGO teacher_qualified=false 继续保留。下一依赖是把源样本时刻／真实到达与 EKF2 状态纳入已有 provenance 证据链，并评估私有设定值发布路径；资源允许后才执行独立冻结的物理验证。

## 官方资料

复用固定 MAVLink `LOCAL_POSITION_NED` 消息定义与现有 pymavlink 2.4.49 / PX4 d6f12ad；采用理由是沿用官方速度与模式接口，常量状态成本，避免新估计器或额外依赖。当前维护／许可证记录及固定文件 SHA 入包；测试 fake 不冒称实际 pymavlink 运行。[MAVLink 消息定义](https://mavlink.io/en/messages/common.html#LOCAL_POSITION_NED)、[PX4 Offboard](https://docs.px4.io/main/en/flight_modes/offboard)、[MAVLink 路由与重启](https://mavlink.io/en/guide/routing.html)支持字段和控制模式语义。研究没有把协议资料或论文当作传感器标定、策略训练或实飞结论。
