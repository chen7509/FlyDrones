# EGO 桥接原始 CDR 的真实 DDS 填充与离线核验（2026-10-12）

固定镜像 `sha256:a4dae62b38bc01a01d084be7b68db83ec804fef7673604e1a9c986a4baa88a6a` 内，两个**同进程临时 ROS 2 Humble 节点**在无外部网络的容器中，以 `rmw_cyclonedds_cpp` 匹配 `/fly_probe/depth` (`sensor_msgs/msg/Image`) 和 `/fly_probe/command` (`quadrotor_msgs/msg/PositionCommand`) 各一个发布/订阅端点。它们使用与桥接相同的 `publish(bytes)` 和 `raw=True` 订阅接口，不启动 EGO 规划器。实际 1×1 `32FC1` 深度图的 64 字节 CDR 在发布与回调处相同。`PositionCommand` 的前 169 字节相同，但回调长度为 172，末尾额外三个 `00`；原始回调 SHA-256 为 `2612f8666942b9414c1d2f94caea18df02864dc12438fad515e47a250f181d47`，发送前规范字节摘要为 `667b1a4afa5778e53947cc5e5262df9ee41a7e2ccf53703cc960309cf04078a5`。这是一项**所测镜像/RMW/消息组合的现场观测**，不能概括为所有 DDS 实现的通用行为。

原严格 `rosbags` 审计要求回调 CDR 与再编码字节完全相同，因此会误拒绝上述真实回调。现仅对 `command_received` 的 `PositionCommand` 接受**恰好补足四字节边界**的零字节；少一个、少两个、非零或多一个仍拒绝，其他消息与发布意图仍要求完全规范。日志的原始 CDR 和摘要保持不变；规范摘要只用于独立离线的**候选**规划/命令关联。返回结果明确区分 `command_raw_sha256`、`command_canonical_sha256`、填充字节数、`digest_identity_candidate=false` 和 `canonical_digest_identity_candidate=true`。这不验证未来 C++ `rclcpp` 记录的真实规范摘要，也不授予 ROS 来源、规划消费或教师资格。

运行和失败全部保留：v1 在只读根目录下无法创建 `/root/.ros/log`，没有初始化 ROS；v2 设置独立临时日志目录后，实际发现命令原始字节不等，按旧断言失败；v3 定位前 169 字节一致和三个零尾字节，仍保留失败；v4 按事前限定的该差异检查通过，退出码 0 且同名容器无残留。四次均为独立命名、有 512 MiB 内存/1 CPU/64 进程上限、无外部网络和 30 秒内部期限的开发探针。v3 与 v4 原始回调字节又进入生产离线审计器，配合**合成**规划器/轨迹服务记录验证了候选关联；不能把合成行说成真实 EGO 输出。针对性正例原先 RED；最终六个相邻 EGO 文件 **138 passed**，改动 Python 文件 Ruff 与 `git diff --check` 通过。首次相邻测试命令引用了不存在的文件，也已保留原输出。
