# EGO causal clock writer: isolated native test

Date: 2026-10-11. This tests only the diagnostic writer in the versioned v2 patch (`bcf739842f3868fb082efce4a9a82609a7d5eb0833dea6c39e80ed9c57433fe9`). It does not compile or run the EGO ROS planner.

The test harness was first compiled against the sealed v1 writer. Its shared-library client exited `7` because both journal rows lacked `event_steady_ns`, the intended RED. The same harness compiled against v2 with WSL g++ 13.3.0 and OpenSSL 3.0.13 and exited `0`: SHA-256, JSON escaping, invalid session, unwritable journal path, two dynamically loaded writer modules sharing one PID sequence `1,2`, and positive nondecreasing steady-clock values passed. The resulting `libfly_ego_trace.so` SHA-256 is `3a8acd0484fa99418aa5e1bd7baf92264d4f37b058b6d3f5e231bdeca7c02de3`. The complete stdout/stderr, exit codes, source, binaries and JSONL records are sealed in the addendum evidence. The original fixed upstream checkout remains unchanged.

This proves a small standalone writer/linker behavior only. It does not prove ROS Humble message type support, map or FSM compilation, the patched trajectory server, `/clock` binding, bridge CDR parity, numerical equivalence, physical performance, or teacher qualification. The host had about 1.26 GiB free RAM after the unrelated regression ended, below the established full MaleCNS probe gate and insufficient for a cautious new ROS/PX4 build. No such build or physical run was started. The next local step is a pure bridge-source identity adapter and fault matrix, followed by a resource-gated patched ROS build and identical-input parity check.
