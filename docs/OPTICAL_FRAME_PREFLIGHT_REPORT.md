# Gazebo 相机光学坐标预检（2026-10-02）

本阶段没有重跑 PX4 任务。先对既有开发世界作 **1 ms 静态 Gazebo
link 探针**，再从同一世界配置生成单独的彩色球目标世界，在 100 ms
抓取图像。目标位置、世界文件、运行时 link 姿态、原始 PPM、分析与哈希
全部保留。正式 20 世界、果蝇策略、安全层及五机负载均未修改。

第一次探针因未先加载 `gz.math7` Python 绑定而在 `Link.world_pose` 报
类型转换错误；修正探针后复测成功。彩色目标的 2 ms 启动图像只有灰度
场景，故保留这张图并取 100 ms 帧做投影验证。两次失败/异常均未被
当作有效标定样本。SDF 载入时的 `gz_frame_id` 扩展元素警告仍在日志中。

运行时探针给出 `camera_link` 相对 `base_link` 的平移
**(0.12, 0, 0.002) m**、单位旋转；RGBD sensor 自身相对 `camera_link`
也是单位位姿。这说明合并模型后不能把 SDF include 的
`(.12, 0, .242)` 直接当成 IMU 外参。PX4 基础模型的 IMU 在
`base_link`，`GZBridge.cpp` 把 Gazebo IMU 的 FLU 加速度和角速度按
180° 绕 X 轴旋转到 PX4 FRD；该本机文件 SHA-256 是
`8f6f1d7e450e341137be573a51674c6ffc518ef63badbdaa71667d0f462b8df`。
这属于当前源码/模型的仿真几何结论，尚非实际传感器标定。

候选 Gazebo link FLU → 图像光学轴（右、下、前）的矩阵是

```
[[0, -1,  0],
 [0,  0, -1],
 [1,  0,  0]]
```

另由 PX4 bridge 的 FLU → FRD 定义，可推导候选 PX4 IMU FRD →
图像光学轴矩阵 `[[0,1,0],[0,0,1],[1,0,0]]`，相机在该 IMU 框架中的
候选平移是 `(0.12, 0, -0.002) m`。此矩阵**未输入 OpenVINS**，后续
需核对其 `T_CtoI`/`T_ItoC` 具体配置方向、传感器时间偏移及运动时
一致性，不能只把矩阵数字复制进配置。

使用上一回合 Gazebo 实发 `camera_info` 中
`fx=fy=108.12401050876075, cx=80, cy=60`，将四个固定目标世界坐标
按 100 ms 时刻的 `camera_link` 姿态投影。图像按预先定义的红、绿、蓝、
黄颜色阈值提取目标中心；最大二维像素残差 **0.8143 px**，小于
**2 px** 开发门槛：

| 目标 | 实测 `(u,v)` px | 预测 `(u,v)` px | 残差 px |
|---|---:|---:|---:|
| 负 Y 红 | (106.64, 58.11) | (107.03, 58.66) | 0.67 |
| 中央绿 | (79.50, 58.15) | (80.00, 58.66) | 0.71 |
| 正 Y 蓝 | (52.36, 58.11) | (52.97, 58.66) | 0.81 |
| 上方黄 | (79.50, 31.08) | (80.00, 31.63) | 0.74 |

这个静态试验支持当前 Gazebo 图像的水平/竖直轴符号与相机平移。
它没有验证运动中的图像–IMU 同步、噪声、漂移、VIO 初始化或 PX4
EKF2 融合，也不能证明真实硬件外参。建模世界、两轮探针图像及所有
结果保存在 `evidence/fly-ego-optical-calib-1701.zip`，逐文件哈希在
同名 `.sha256.json`；12/12 文件核对通过，ZIP SHA-256 为
`70c28b35e3f74135fef18fd4e001376e46aa01e6648b17fff2765b9fab9f8264`。
Gazebo [SDFormat 相机文档](https://gazebosim.org/api/sdformat/15/classsdf_1_1SDF__VERSION__NAMESPACE_1_1Camera.html)
明确提醒 Gazebo 与常见视觉工具的相机朝向定义不同；此试验对当前
模型作了独立像素核验。下一门槛是从动态相机和 IMU 数据验证时间
偏移及轴向一致性，再尝试固定上游版本 OpenVINS 的离线运行。
