# Byte-bound source preparation for the next PX4 ROS 2 build

The previous synthetic callback build compiled a CRLF `src/px4_msgs` checkout while its predeclared manifest hashed a separate LF reconstruction. The interfaces matched after newline normalization, but the actual compiler input was not byte-bound by that manifest. This stage prepares the **same `src` tree that the declared colcon command would consume** from raw Git objects and verifies its bytes. It does not run colcon, Docker, PX4 or an Agent, and it does not requalify the previous build.

The source is the local checkout of official [PX4/px4_msgs at `148bdb4b8214a4d8de83029777fe8d334c74db6f`](https://github.com/PX4/px4_msgs/tree/148bdb4b8214a4d8de83029777fe8d334c74db6f), BSD-3-Clause, already researched in the [source-journal report](PX4_ROS2_SOURCE_JOURNAL_REPORT.md). The tool checks HEAD and reads each tree blob with `git cat-file` rather than copying the Windows checkout. It rejects unsupported Git modes, absent or linked local collector inputs, an existing destination, malformed paths, extra files and changed bytes. The manifest and verifier both point to `src/px4_msgs` and `src/flydrones_px4_ros2_source`; the only declared build command uses `--base-paths src`.

On the pinned local Git checkout, the final `workspace-v3` preparation wrote **259 files** (255 official plus four collector files) into `results/px4-ros2-byte-bound-dev-1701/workspace-v3`. The independent verify command returned 259 verified files; a separate `git hash-object --no-filters` audit compared all 255 prepared upstream files with the fixed Git tree object IDs and found exact equality. The actual prepared `src/px4_msgs/msg/VehicleOdometry.msg` is SHA-256 `a528b3d0b4c1a9083a71b32c367bad71a900e959efd82b9d03a9eb0e99fe6017`, matching the fixed raw Git blob; the final profile SHA-256 is `cfaca8d891fd89739236efb1a263b867e4def91775bdfb6422bc55501a4004fe`. All four copied collector files are hashed; the final README copy matches the current collector README SHA-256 `569f7ae7330262ee08a99d7266a1f3e0eb1627195c89fc9fb9d0e2c931bfb55c`.

Ten targeted build-source tests passed, including a Windows CRLF working-copy fixture, extra file/byte/profile tampering, wrong commit, Git symlink mode, real Windows root/descendant junction rejection, pre-read blob size rejection and a fail-closed path for Windows Python before 3.12. The initial six RED failures and the Windows symlink-privilege test-harness error are retained; the latter was resolved by constructing the Git link object in the index without an OS symlink. The first two valid preparations remain in the results: `workspace-v1` predates the README edit, and `workspace-v2` predates the final junction/size guard. They are not presented as the final build input. Independent review found the junction gap and early blob allocation bound; corresponding real or bounded RED cases preceded the fixes.

The read-only local synthetic callback remains the current runtime result; no source journal is eligible for training or control.
