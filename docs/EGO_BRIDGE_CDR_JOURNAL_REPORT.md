# EGO bridge CDR journal: opt-in offline integration

Date: 2026-10-11. The fixed bridge now has an **opt-in** JSONL journal. In this mode it serializes each generated `/clock`, odometry, trigger, camera-pose and depth ROS message once, records the exact bytes as base64 and their SHA-256 before the send attempt, and passes those same bytes to the Humble `Publisher.publish(bytes)` path. A raw `PositionCommand` subscription records its exact received bytes before deserialization and before it can change the control reference. The legacy unjournaled path remains the default. A new run ID, one causal session ID and a new exclusive journal path are required together; a prior or partial file cannot be overwritten. The journal identifies odometry and camera input as `unattested_socket`, command input as `unattested_ego_server`, source-profile hash as null and truth usage as unknown. It does not produce the offline reconciler's claimed `px4_ekf2` or `calibrated_rgbd` source record.

The API choice follows the official [ROS 2 Humble `rclpy.serialization` source](https://github.com/ros2/rclpy/blob/humble/rclpy/rclpy/serialization.py), [Humble publisher source](https://github.com/ros2/rclpy/blob/humble/rclpy/rclpy/publisher.py), and [Humble node source](https://github.com/ros2/rclpy/blob/humble/rclpy/rclpy/node.py): `serialize_message` returns serialized bytes; `publish(bytes)` calls the raw publisher; and `create_subscription(..., raw=True)` exposes serialized receive bytes. These are pinned-branch API semantics, not proof that the installed image has been exercised. `rclpy` is Apache-2.0 in those sources; the diagnostic EGO patch remains tied to fixed GPL-3.0 upstream commit `23a8d5a191711dd65633df689bd00f55d4dea8f9`. No new runtime dependency was added. The extra serialization and per-line flush add CPU/I/O load, so this instrumented mode needs its own capacity and numerical-parity validation; it cannot inherit the original EGO performance result.

The selected implementation reuses the Humble `rclpy` already required by the EGO bridge: one Python file for the journal, one for offline audit, and a conditional bridge hook. The source branch is maintained as part of the ROS 2 repository, but the exact installed `rclpy` package version and binary/type-support hashes have not yet been captured; no claim about its runtime maintenance or exact installed patch level follows from the branch source. The fixed EGO checkout was reported nonarchived with last recorded upstream push 2025-03-08 in the earlier source audit; current maintainer activity is not inferred. Hashing the incoming JSON or reserializing an ordinary deserialized command was rejected because neither identifies the raw CDR message delivered to the ROS subscription. A new message broker or custom CDR implementation would add more dependencies and adaptation cost without improving this narrow byte identity check.

Every publish has a recorded intent before `publish_raw` and a separate returned/failed event. The append-only sequence, one process/session, monotonic clock and a lock cover the socket thread and ROS callback. A journal, serializer, publisher, malformed command or second-reset error latches failure; later publications and reference updates are refused. A publish that returned before a journal-return write failure is retained as an **incomplete irreversible action**, never rolled back or called a completed journal. Flush is not `fsync`; a process or host crash can leave a partial record, and a publisher return is not proof of DDS delivery or planner consumption. The command callback has a raw-bytes record followed by decoded stamp/trajectory metadata, which also fails closed if decoding fails.

The separate pure `ego_bridge_cdr_audit.py` checks that one journal's retained base64 bytes reproduce its hash and length, all per-process sequences and steady times are ordered, every publish intent has a matching returned record, every command receipt has decoded metadata, and the file closes normally. It rejects failure records, altered source labels, gaps, missing returns and partial files. Its `journal_complete=true` means only internally complete framing. It always reports `source_attested=false`, `dds_delivery_verified=false`, `planner_consumption_verified=false` and `teacher_qualified=false`.

Tests used fake byte serializers and publishers, with no ROS node, Docker, PX4, Gazebo or OpenVINS process. RED included a missing journal module and then missing bridge integration methods and audit module; GREEN checked exact bytes, ordering, raw-command-before-decoding, serialization/publish/write/flush failure, irreversible return-write failure, reset lock, concurrent sequences, exclusive file creation, ROS shutdown on construction failure, audit tampering/partial-file rejection and malformed evidence types. **119 adjacent EGO/bridge tests passed**, changed-file Ruff and `git diff --check` passed; their outputs are retained in the stage logs. The host had about 1.88 GiB free RAM, below the existing 4 GiB full MaleCNS resource gate, so no resource-heavy build or physical run was started.

Remaining gates: independently attest the socket observation using PX4 EKF2/ULog, calibrated non-truth camera/extrinsic and reset/clock health; bind actual Humble type-support and CDR bytes across the Python bridge and patched C++ planner/server; prove `/clock` and steady-clock domains; compare patched/unpatched trajectories on identical development input; then run an owned unarmed single-drone capture. The present journal has **no** teacher, fairness, safety-flight, hardware or runtime-source qualification. Historical PX4 TIMESYNC and five-camera WSL2 capacity failures are unchanged.
