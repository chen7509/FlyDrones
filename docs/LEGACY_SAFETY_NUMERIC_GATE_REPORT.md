# 旧实时控制链的数值与降落锁存保护（2026-10-12）

`Pilot.tick` 将归一化的脑输出交给 `SafetyGovernor.filter`，随后才调用无人机后端。旧实现直接用 Python `min/max` 限幅：输入 `throttle=NaN`、`forward=+∞` 时，实际返回过 `throttle=0.125`、`forward=0.125` 的非零指令，且 `land_requested=false`。来自配置/YAML 或遥测的异常时间与位置值也没有有限性门禁。低电量虽会设置降落标志，同一次 `filter` 仍可返回前进指令。

现在在限幅和斜率计算前检查四个命令轴、当前遥测的所有数值字段、步长和脑输出年龄。非数值、`NaN`、无穷大和无法转换成有限浮点数的巨大整数会锁存降落请求、清除上一条运动命令，并返回悬停。负步长、负脑年龄、负或倒退的遥测时间同样拒绝。低电量或最长飞行时间触发降落后，本次和后续调用都只返回悬停；原有 `Pilot.tick` 在看到锁存标志时调用后端 `land()`。正常有限输入的限幅、地板恢复和斜率逻辑保持原样。

测试先观察到四类失败：非有限命令未触发降落、非有限遥测/时间未触发降落、负／倒退时间未拒绝、低电量仍返回运动指令。另用 `10**1000` 暴露 `math.isfinite` 的 `OverflowError`，随后改为安全拒绝。最终 `tests/test_control.py` 与 `tests/test_sim_and_cli.py` 共 **23 passed**，改动文件 Ruff、`git diff --check` 通过。没有连接硬件、启动 PX4/Gazebo、训练或飞行。

**范围边界：**这是旧 `flydrones fly` 归一化指令路径中的一道软件保护，不是已验证的 PX4 EKF2／相机来源监督闭环。`MavlinkDrone.telemetry()` 当前会在每次查询时更新本地 `Telemetry.t`，即使没有收到新的位置消息；本修复无法据此证明遥测新鲜度。后端仍可被其他调用者直接调用，真实飞行前还必须验证来源时间戳、失联、EKF2 状态、PX4 失效保护和实际设定值／ULog。它不改变原有 VIO 仿真结果、五机 0.873 RTF 失败或完整 MaleCNS 训练资格。
