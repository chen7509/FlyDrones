The retained development PX4 data cannot be joined into a single reset-coherent student sequence under the current fail-closed session policy. The read-only audit found **8 counter transitions** across six audited position, velocity, heading and attitude counters. The terrain-distance `dist_bottom_reset_counter` is outside this audit; eight is not a count of every ULog reset-counter change. Across the original **251 RGB frames**, 30 lacked at least one selected state topic; 221 had both topics, but every one was after the first unhandled coordinate reset. The audit therefore records 239 frame-level `reset_epoch_unresolved` refusals, including frames already missing a topic. These counts overlap. No training frame or EGO teacher command was produced.

The first observed transition is the local XY counter at 1.200 s; the last is the attitude quaternion counter at 3.996 s. The individual transitions are three XY position, one vertical position, two horizontal velocity, one heading and one attitude. The audit examines every source message, so a counter that changes and later returns to its earlier value between camera frames still latches the failure. A new authenticated estimator session and explicit goal-frame policy could potentially establish a usable post-reset epoch in a future producer; stable values alone cannot. This conservative refusal is an integration gate, **not evidence that the fruit-fly learner failed**.

## Verification and limits

Tests cover nonfuture row selection, missing topics, between-frame transitions, counter wrap, permanent latching, malformed shape/type/range and timestamp refusal. The final adjacent suite passed 327 tests, skipped one, and emitted one PyTorch warning; changed-file Ruff and the diff check passed. A later focused command first omitted the project `PYTHONPATH` and failed at `conftest` import before collection; the corrected invocation passed 66 tests. Both outputs are retained. An initial evidence archive was sealed before this invocation failure; a separate v2 archive retains it without overwriting the first. Independent read-only review found no Critical or Important defects and requested the terrain-distance scope clarification above. A negative counter was initially accepted; one RED case reproduced it, then the final range check passed. The audit itself has no runtime source receipt, calibrated clock, camera extrinsic, estimator-health grant, teacher process or goal-reset policy. It always returns `eligible_for_live_capture=false` and never constructs `Observation` or invokes the sequence recorder. The host's low free memory precluded a new physical/full-model run; Docker, PX4, Gazebo and training were not started.
