# EGO 累积地图来源候选审计（2026-10-12）

固定 EGO-Swarm `23a8d5a191711dd65633df689bd00f55d4dea8f9` 的占用地图会随深度帧逐次更新。原离线匹配器在选择第二次规划时，只核对最后一帧已应用深度图；较早已应用帧即使找不到桥接来源，仍会返回 `identity_match=true`。同样，若较新的地图修订已经应用，规划记录却声称使用旧修订，原匹配器仍可能接受。两种情况都不能证明规划时的地图来源。

现有 fail-closed 候选匹配增加两项条件：规划前最后一个已完成的深度地图修订必须等于规划记录的 `map_before_revision`；从会话开始到所选修订的**每次**已应用深度图，都必须能唯一关联到桥接的深度图及相机位姿消息，消息需早于对应接收事件，且沿用相同来源配置摘要。返回的 `applied_depth_history` 明确列出各修订、接收序号、图像/位姿摘要及桥接序号；`applied_depth_history_bridge_bound_candidate=true` 仅表示当前记录集合满足这些离线条件。

测试先以两次地图更新的现有夹具证明旧实现会错误接受“第一帧桥接摘要被换掉”和“第二次规划声称使用旧地图修订”；两次断言均先出现 `DID NOT RAISE`，之后实现拒绝。另检查旧位姿来源配置变化被拒，并保留此前的单帧、异步旧命令、会话/序号/摘要故障用例。第一次相邻套件运行因本机默认 Python 缺可选 `rosbags` 而有 11 个依赖导入失败，另有一项既有错误文案被新检查抢先触发；随后使用此前封存的 `rosbags==0.11.5` 隔离依赖目录，保留原错误文案并完成六个 EGO 测试文件 **138 passed**。改动文件 Ruff 与 `git diff --check` 通过。没有安装新依赖或启动仿真、规划器、训练。

本阶段只加强**候选日志的一致性**。桥接来源标签仍可能由合成记录提供，日志生产者、EGO 补丁二进制、规划器对地图的实际读取、已标定相机/PX4 来源和数值等价均未验证；因此 `runtime_source_verified=false`、`teacher_qualified=false` 不变。地图历史列表代表记录中逐次已应用的帧，不声称当前每个占用体素仍受每帧影响。云地图写入和未绑定的深度里程计路径继续拒绝。原始失败和历史证据均保留。

下一依赖仍是资源准入后的固定上游只读诊断补丁构建与同输入原版/补丁数值对照，然后才可尝试真实非真值单机来源采集。EGO 构建的 Windows 2500 MiB 门槛、PX4/完整 MaleCNS 的 4 GiB 门槛及五机 0.873 RTF<0.95 结果均未改变。
