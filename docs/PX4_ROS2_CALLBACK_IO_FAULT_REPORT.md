# ROS 2 source journal: injected error during a typed sample callback

The prior I/O experiment exercised journal writes with no publisher. This separate, predeclared development run reused the fixed ROS 2 Humble image, compiled read-only `VehicleOdometry` subscriber, typed synthetic publisher and exact journal-fd `LD_PRELOAD` shim. It injected a partial write followed by `EIO` on the **first sample row**, with a 256 MiB, one-CPU, 64-PID, network-isolated container. No PX4, Agent, Gazebo, EKF2 publication, policy training or flight process ran. Upstream commit, license, interface and adoption research is recorded in [the source-journal report](PX4_ROS2_SOURCE_JOURNAL_REPORT.md).

The immutable profile expected publisher exit 0 and subscriber exit 2. The publisher did exit 0 and reported 120 synthetic messages. The subscriber received the first typed sample, wrote only part of its JSON row, caught the write exception inside its callback, latched `journal_error`, appended a failed terminal and exited **1**. The harness therefore exited **1**: its predeclared subscriber-exit expectation **failed**. This is not a passing experiment under its own profile. Source inspection explains the mismatch: the callback catches the journal exception and the outer event loop returns 1 for a latched source failure; exit 2 belongs to uncaught outer journal errors. The evidence was retained without changing the original expected exit or rerunning to obtain a green harness.

The resulting 651-byte file starts with a real ROS callback `kind=sample` row, stops mid `rmw_reception_sequence`, then immediately contains a `kind=finish` row with `status=failed, reason=journal_error`. No complete sample line exists. The product reader rejects it as `journal JSON invalid`, and it remains ineligible for live capture. This establishes a narrow fail-closed behavior for this injected sample-write error. It does **not** prove real storage failure handling, zero lost PX4 samples, Agent/PX4 identity, ULog timing, VIO/EKF2 fusion, or an acceptable student data producer. The typed publisher is synthetic, and its `/fmu/out/vehicle_odometry` name alone does not authenticate PX4.

The independent audit checks the frozen image/binary/publisher/shim/runner hashes, child and harness exits, the raw partial-sample boundary, the product reader's rejection and the profile mismatch. Its result is in `results/px4-ros2-callback-io-fault-dev-1701/audit.json`. The adjacent journal and causal-adapter suite passed **59 tests**; the audit script passed Ruff. A post-run scan found no running container or PX4/Gazebo/OpenVINS process. All original logs, exits, the malformed journal and the failed expectation are retained in the evidence archive.

An attempted exact-Git-byte ROS rebuild was refused **before Docker or colcon**: host free memory was 873,664 KiB, below its prospectively declared 900,000 KiB start limit. The fixed 259-file source tree had independently verified earlier, but this refusal did not compile it or close its actual-build provenance gap. `results/px4-ros2-exact-build-dev-1701` retains the declared profile, runner and refusal record. The 900,000 KiB value is a local resource-start guard, not a drone performance or training threshold; the full MaleCNS 4 GiB probe gate and the five-camera 0.95 RTF gate remain separate.
