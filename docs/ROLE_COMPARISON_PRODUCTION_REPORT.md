# Actual internal learning-role comparison producer

This software phase adds an actual sequential curriculum producer for the three existing learning profiles and a mutually exclusive `--compare-learning-roles` route in `tools/connectome_training/run_curriculum.py`. It runs each fresh session through the existing training, evaluation, promotion/regression gates, checkpoint and batch-report path. This is an internal role ablation, not a completed full MaleCNS experiment or fair upstream comparison. No actual full-model CLI, GPU, resource/process/Docker/Linux query, target observer/SDK, physics, measured calibration or consumed attempt ran.

## Production behavior

The fixed order is descending-only-v1 (readout), sensory-readout-v1 (gain/readout), shared-dynamics-v1 (all four existing parameters). Before constructing a session, the producer exclusively claims a fresh experiment directory and writes progress. An existing directory cannot resume/restart or reach model construction. Each session is released before constructing the next. No concurrent three-model residence or shell child orchestration is introduced.

Before any training, the first actual session supplies a JSON snapshot of complete structure identity, parameter mapping and dataset digests, feature profile, actual device and topology/dynamics, all four captured initialized coefficients, initial validation losses, truncation and loss weights, optimizer class and actual group options excluding intentionally different parameter references, and Torch version. Later sessions must match before their first update. Each retains its independent role/model identity. This baseline comparison does not authenticate source or bind every scientific backend, clock, toolchain or stochastic condition.

One positive integer per-variant batch cap is required. Ordinary curriculum COMPLETE/FAILED can stop a variant early; different promotions change exposure/rehearsal/actual effort. FINISHED means all three procedures returned. It does not mean all curricula completed or that training success was verified. Reported global_updates remain the existing epoch counter, not an independently measured optimizer.step count. Actual batch reports, state/checkpoints, final validation on every configured stage and counters remain inspectable. A thrown exception retains ERROR and the partial directory, rethrows and stops later variants. A failure may follow real optimizer updates before state commit; there is no rollback or full effort reconstruction.

CLI comparison rejects --restart and missing --max-batches before configuration/output/model effects. Argparse rejects combining an explicit --learning-profile with comparison. Existing single-session routing, roles, topology/dynamics defaults, kernels, trainer/window/corpus/codec/loss and original gates remain unchanged. Default clipped Euler still has the known zero tau derivative at 20Hz/20ms; choosing exponential dynamics remains explicit. No qualification is inferred from choosing a role or a numerical mode.
