## 渲染筛选与实际采集

启动后 2 ms 的第一组两张图尚未显示贴图，图像相同，内区 FAST20 均为 0，筛选失败并保留。随后预先固定最早采样时间为 200 ms，在完全相同的场景/模型/相机姿态下重做配对：基线 16 个 FAST20 点、内区 12；变体 55 个、内区 54。图像确实改变，静态筛选通过。此修正是渲染采样时序判定，不修改图案、负载或物理精度；静态筛选不能替代 VIO 验证。

第一次采集命令因旧 venv 缺 NumPy 在导入阶段失败，未创建回合或启动 PX4；日志原样保留。系统 Python 依赖检查后只运行一次实际 PX4/Gazebo 回合（`episode-v2`）。4.02 s 预解锁静止窗口为 15.68–19.70 s；455 张 RGB、455 条相机信息、一份 ULog 的记录完整性通过。导出 10711 条 IMU、428 张落在 IMU 时间域内的 RGB；全部 IMU 样本与 ULog 逐值一致，无裁剪、无时间偏移，最大间隔 4 ms。预解锁窗口 41 张图像完全相同，1005 条 IMU；末两秒 EKF2 速度有效且无重置，中位约 0.0182 m/s。EKF2 是融合估计，不是独立真值。

回合在仿真 45.4 s、任务计时 12.4 s 以 `collision` 结束，末端 `(-0.839,0.827,1.348) m`，日志记录机体旋翼与树接触。采集退出码 0 只表示证据保存成功。248 次完整果蝇决策的中位耗时 0.370 s、P95 0.414 s，仍远超 50 ms 控制步。回合墙钟 167.2 s，粗略 RTF 0.271，包含决策期间暂停；既不是实时机载成绩，也不能由此推断 WSL2 或果蝇算法的单独性能。PX4/Gazebo 回合进程已释放。

## 固定回放与时钟解释

只回放一次，428 行状态，3.68 s 墙钟，峰值 RSS 67972 KB。3.9–4.5 s 的七次静止初始化尝试均因 IMU 窗口不足失败，4.6 s 第八次成功；八次均有 28/28 条半窗轨迹。旧审计器假定只有一条静止初始化方法日志，因此拒绝该有效的多次尝试；新增有失败测试覆盖的事件关联解析器，逐次区分尝试、失败和唯一成功，未修改估计器。未另跑无插桩版本，故不声称本输入完成了插桩/无插桩奇偶性验证。

4.6 s 是成功尝试的输入图像时间，不等于内部初始化状态的参考时间，更不是完整导航输出首次可用时间。固定上游 [VioManager.h](https://github.com/rpng/open_vins/blob/69488123ed9362dd44b6f28e7f4680abbff1442b/ov_msckf/src/core/VioManager.h) 的公共 `initialized()` 同时检查内部初始化标志与常规更新时刻；[VioManager.cpp](https://github.com/rpng/open_vins/blob/69488123ed9362dd44b6f28e7f4680abbff1442b/ov_msckf/src/core/VioManager.cpp) 在静止零速更新成功时提前返回。本次导出 CSV 到 22.0 s 才标记初始化，日志在其间已有零速更新；不能把这 17.4 s 差值解释为初始化计算耗时或线程堵塞。公共标志直到预解锁窗口结束后才出现，所以现有输出门禁仍未证明可在起飞前提供导航状态。

成功尝试前的 2.6–4.6 s 图像相同，但同期 PX4 EKF2 速度有效标志尚未通过：该窗口的 EKF2 静止交叉验证明确记为未验证，不能拿 17.7–19.7 s 的有效速度窗口代替。`completion-audit-v1` 使用浮点边界漏算端点，原样保留；v2 使用整数纳秒计算该图像窗口。旧 `prearm-audit` 的单次方法假设拒绝日志，未生成通过结果。

初始化输出后有 234 行状态，75 帧非零 MSCKF 更新、合计 159 个特征更新，SLAM 地标最多 26。只在评分时读取 Gazebo 真值，对 33.0–45.3 s 的 124 个重合帧做无缩放刚体对齐：ATE RMSE 0.1622 m、P95 0.2522 m、末端 0.0713 m。该局部轨迹指标不覆盖起飞前导航输出，也不代表陌生环境泛化；场景纹理改变了控制器图像及实际飞行路径，不能与上一回合误差直接做算法优劣归因。
