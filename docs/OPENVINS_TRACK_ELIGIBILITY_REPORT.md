# OpenVINS 起飞前轨迹合格数只读诊断（2026-10-04）

**结论：纹理板确实提供了很多可检测的数据库特征，但绝大多数在初始化器相应半窗内只有 0 或 1 次观测；各半窗只有 9 条轨迹达到计算视差所需的两次观测，达不到固定的 15/15 门槛。**这解释了上一个开发回合“约 207 个数据库特征却无法预解锁初始化”的直接计数差异，**尚不能解释为什么跟踪寿命短**，更不能声称飞行或 VIO 闭环已修复。

## 固定来源与方法

完全复用 [PR #25](https://github.com/chen7509/FlyDrones/pull/25) 校正版证据的唯一 PX4/Gazebo 单机采集：608 张可用 RGB 图像、15,203 条 PX4 ULog IMU、相同 ROS-free runner SHA-256 `bf811d14...` 和估计器配置 `eaa40224...`。本阶段**没有启动新的 PX4/Gazebo、训练或控制策略回合**。输入清单 SHA-256 `dfea7a90...` 与 PR #25 封存索引吻合，之前的状态 CSV SHA-256 `1ccb4cd2...`。

在独立的 [OpenVINS 固定提交](https://github.com/rpng/open_vins/tree/69488123ed9362dd44b6f28e7f4680abbff1442b) `69488123ed9362dd44b6f28e7f4680abbff1442b`（GPL-3.0）副本中，先应用原逐帧日志补丁，再加入本次只读半窗观测数日志补丁；上游 [FeatureHelper API](https://docs.openvins.com/classov__core_1_1FeatureHelper.html) 的 `compute_disparity` 对每个相机轨迹需要两次有序观测，`InertialInitializer.cpp` 对前后半窗各要求至少 15 条。没有更改数据库、特征筛选、参数、初始化判断或 PX4。[静止初始化器说明](https://docs.openvins.com/classov__init_1_1StaticInitializer.html)和 [OpenVINS ICRA 2020 论文](https://yangyulin.net/papers/2020_icra_ov.pdf)分别提供静止前提及前端架构背景；这些来源不能替代本次实际计数。

独立构建库 SHA-256 `a89787d4...`，Ubuntu g++ 13.3、OpenCV 4.6.0。使用固定 runner 对**同一输入仅重放一次**，退出码 0，墙钟约 6.55 秒、峰值常驻内存约 68,004 KB。新旧状态 CSV SHA-256 均为 `1ccb4cd2eb55294e5130f052800d0bf83a962538ecba68c00c97e28c22af8975`，逐字节相同；因此本次插桩没有改变已记录的估计状态。此奇偶核验只涵盖保存的状态，不证明所有线程内部时序都完全相同。

## 严格逐帧核算

OpenVINS 共尝试初始化 255 次；首次特征时间缺失的尝试按上游代码提前返回，其余 **254 次**均有且仅有一条新增轨迹分布日志。解析器拒绝缺失、重复、畸形行、半窗合计与上游视差合格数不一致以及清理期间数据库反常增长。预解锁 15.618–19.642 秒有 **40/40** 次有效轨迹分布记录。该窗口的逐帧中位数如下，精确的每帧数见 `audit-v2/counts.csv`：

| 指标 | 中位数 |
|---|---:|
| 清理前特征 ID | 207 |
| 初始化窗口清理掉的 ID | 9 |
| 清理后被扫描的相机轨迹 | 198 |
| 旧半窗：0 / 1 / ≥2 次观测 | 99 / 90 / **9** |
| 新半窗：0 / 1 / ≥2 次观测 | 108 / 81 / **9** |
| 两半窗均 ≥2 次观测 | **9** |

新日志计算的旧/新半窗 `≥2` 数在所有 254 次尝试中均与上游 `compute_disparity` 的 `num_features0/1` 完全一致。40 个预解锁帧的两半窗合格数最大也只有 9/9，固定门槛为 15/15。清理前的 207 与清理后的 198 不能当作同一指标；`FD_INIT_FRAME` 在清理前计数，`FD_TRACK_COUNTS` 在上游 `cleanup_measurements` 后计数。窗口内第一帧 207→198，最后一帧 216→198，说明清理差额也会随时间变化。

这个结果只能直接定位为**轨迹在对应半窗内的观测次数不足**。它没有指出短轨迹来自暗板纹理、KLT 跟踪丢失、特征 ID 重建、图像预处理、相机标定或其他因素；不要仅凭数据库总数调低 15/15，亦不要归咎于果蝇策略训练。上一个回合仍在 19.642 秒预解锁结束前未初始化，OpenVINS 内部在 28.0 秒才静止法初始化、回放器在 28.5 秒才首次输出已初始化状态，果蝇控制飞行仍为 `out_of_bounds`。这一阶段没有验证 VIO→PX4 EKF2 融合、健康降级、5/20 机或实飞。

## 可复核证据与下一依赖

本阶段保留隔离源码补丁、配置/构建日志与退出码、库哈希、命令脚本、完整一次回放 stdout/stderr、状态 CSV、资源、初版与严格版逐帧审计，以及 `provenance.json` 对前次封存输入的完整 SHA-256 引用。库约 293 MB 不打入证据 ZIP；重跑需要根据固定上游提交和两份补丁重新构建。下一步应继续在同一保存图像上观察**跟踪器自身的特征 ID 存活、丢失和补点时机**，然后才能决定是否有必要调整纹理、相机/IMU 标定或前端配置；任何修正都须先在独立开发输入验证，正式未见场景仍不可调参。当前 WSL 仿真性能和原生 Linux/HITL/实飞门槛均未改变。
