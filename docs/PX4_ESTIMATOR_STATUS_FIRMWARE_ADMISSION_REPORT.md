# PX4 status firmware build admission, without dispatch

The isolated fixed-commit source passed a fresh read-only WSL audit, but the actual build admission **refused**. The final snapshot recorded 3.039 GiB free physical memory on Windows, 6.654 GiB available in WSL and about 926.6 GiB free on the WSL destination. Windows remained below the frozen 4 GiB threshold. The process scan completed with no competing test, PX4, Gazebo, OpenVINS or build process at that snapshot. Because an earlier gate failed, the admission probe did not launch another systemd scope; `scope_unverified` and the two absent scope-value errors are expected secondary refusals. The earlier harmless cgroup probe showed the system can enforce the requested limits, but it cannot substitute for a fresh build-dispatch check.

The new `--admission-only` command has no build-dispatch path. It binds the committed source profile and verifier hashes, sealed prepared-source audit, current WSL source re-audit, exact one-job `make -j1 px4_sitl_default` command, result path, 4 GiB Windows/WSL and 15 GiB disk thresholds, process scan, scope values, one-attempt count and 90-minute timeout. The audit never grants compiled, live-source, fusion or training authority. A future dispatch implementation must repeat these observations immediately before launching and retain any failed or partial attempt under a new name.

RED tests exposed the absent module, an overbroad `process_scan_incomplete` decision and a hidden empty-command-line launcher case. Read-only diagnosis found 175 Windows processes with missing command lines, mostly protected system services, versus no malformed WSL `ps` rows. The correction allows opaque non-launcher system services, queries a missing process name once, and still rejects opaque Python/build/simulator launchers. The final fixed-input suite passed 20 tests; changed Ruff passed. The first admission observations (`v1` and `v2`) and later `v3`/`v4` refusals are all retained in `results/px4-status-firmware-source-dev-1701`.

This stage is **only implemented and tested admission logic plus a real refusal snapshot**. It is not a firmware build, successful cgroup-scoped compilation, live DDS receipt or PX4/Gazebo physical simulation. The build executor, post-build binary/header/dependency audit and later unarmed source study remain unfinished. No gate, workload or acceptance threshold was reduced.
