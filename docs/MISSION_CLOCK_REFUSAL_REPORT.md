# Mission caller-clock refusal (2026-10-14)

MissionAgent now stops and remains stopped when its caller supplies a malformed or backward timestamp. This closes a real local decision/division defect: step converted bool/string time, accepted negative and backward time, and ingest_messages had no corresponding finite/monotonic boundary. Regressions could delay depth-hold escalation, lease renewal, completion timing and relay decisions; malformed values could raise before producing any stopping decision. A separate communication-only ingest could also merge work at an invalid time.

Both entry points share one finite nonnegative Real timestamp admission, excluding bool/string and numeric overflow, with nondecreasing observed values. Equal time remains accepted so communication and decision may share a tick. A bad call latches emergency and cannot overwrite the last accepted time. Faulting step returns zero velocity, no target and no outbound records; it does not ingest, expire, release, bid, complete or create detection/relay work. Faulting ingest refuses the batch and latches the same stop.

When a later timestamp is admitted, inbound merge and lease expiry precede the existing release of a locally owned active task. Movement and new local work never resume after the latch. The faulting call does not fabricate a receipt time or release timestamp. A peer can otherwise use its existing lease-expiry rule; actual network delivery/reassignment time is not measured. The next accepted call does not release a task whose ownership has already transferred.

## Qualification limits

This is a check on observations supplied by the caller, not continuous time health or calibration. It cannot detect a forward jump, a frozen caller, or a jump and return between calls, and cannot authenticate telemetry or establish sample-generation time. Existing timer/lease arithmetic remains float-based; refusing an exact input regression is not arbitrary-precision duration measurement. There is no new watchdog. Mission stress's elapsed caller uses time.monotonic(); its own periodic sends and acceleration-limited motion remain outside this MissionAgent boundary. A software zero intent is not proof of immediate physical stop, LAND acknowledgment or landing. Direct external mutation of a supplied TaskLedger is also outside this boundary.

The existing public return type and task-message schema remain; invalid step time intentionally changes from exception/coercion to an emergency decision, and invalid communication time changes to refusal with a persistent latch. No source freshness, camera calibration, teacher qualification, sensor quality/reset/covariance, full MaleCNS training or physical result is promoted. Existing depth, lease, velocity and physical thresholds are unchanged. The original full goal and blocked panel status remain, with independent low-memory work continuing.
