# Gazebo 五机相机错峰稳定性报告

日期：2026-09-27
结论：**rejected（当前平台与实现不通过）**

## 结论

相机错峰机制本身已经工作：五路深度相机保持约 10 Hz，目标相位为
`0/20/40/60/80 ms`，五路 p95 相位误差均为 8 ms，最终开发轮没有丢失或
未匹配的触发/图像。单机 PX4 任务也能完整起飞、进入 OFFBOARD、执行任务并安全着陆。

五机闭环没有达到进入正式实验的前置门槛。最终五机开发轮的全程 RTF 只有
`0.5266`，起飞窗口 RTF 约为 `0.452～0.454`，明显低于冻结的 `0.95` 门槛。
四架机在 12 秒墙钟期限内实际只得到约 5.4 秒仿真时间，虽然爬升
`1.17～1.22 m`，PX4 仍处于起飞过渡状态，因此安全层以
`actuator-response-timeout` 拒绝任务；另一架机在一次允许的临时拒绝重试后仍未能解锁。
五架机最终全部安全落地并释放资源。

这不是策略权重、损失函数或训练量不足造成的失败。自主策略尚未进入任务循环；失败发生在
PX4 起飞准备和仿真实时率门槛。继续训练不会解决当前五路触发式渲染、Gazebo Transport、
PX4 SITL 与本机调度组合的实时率不足。

由于开发门槛失败，未运行三轮 smoke、十轮正式配对实验以及 120 ms 延迟和 400 ms
丢帧回归。这些结果不能通过增加轮次、延长起飞期限或降低 RTF 门槛来补齐。

## 冻结判据

- 机体、传感器、动力学、任务几何、策略权重和安全监督器保持不变。
- 五机相机目标：10 Hz、`0/20/40/60/80 ms` 相位、p95 相位误差不超过 8 ms、
  相邻中位间距误差不超过 8 ms。
- PX4 起飞：12 秒内连续三个新鲜状态样本达到至少 0.5 m 增量，PX4 明确报告离地，
  随后确认 OFFBOARD。
- 五机正式运行必须 `5/5` mission-ready、`5/5` 着陆、RTF 至少 0.95，并具有完整
  渲染、执行器、ULog、相位和清理证据。
- 调度器故障必须在工作者启动前被保存，或在启动后触发陈旧深度安全着陆。

## 故障与修正记录

开发期间保留了所有失败轮次，先写修订再改变行为：

1. 将调度轮询由 10 ms 改为 1 ms，解决 12 ms p95 相位误差。
2. 强引用 Gazebo Python 回调，避免订阅回调被回收。
3. 按 4 ms 物理步长提前分发，仍以图像头时间戳评分。
4. 完成标记后等待 1 秒安静窗口，避免末尾触发/图像竞态。
5. 显式销毁执行器探针 Transport 节点，消除 pybind11 退出错误。
6. 观察器在每路实际出图后才允许启动工作者，并排除预热帧。
7. 每架机使用独立 Transport 订阅节点，隔离连接生命周期。
8. 首次解锁前要求明确的 disarmed+landed 状态；临时拒绝最多安全重试一次。
9. 渲染证明复用永久观察器的 11 帧证据，移除临时订阅；观察日志按 250 ms 批量刷新。
10. 调度日志也按 250 ms 批量刷新。

修正 1–10 后，相机完整性问题已经消失，但五机 RTF 仍不足。因此不再继续降低安全标准或
用开发环境调参掩盖结果。

原始失败和成功目录均保存在 `results/camera-phase/`。最终紧凑证据位于：

- `docs/results/camera-phase/dev-phased-single-20260927-11/`
- `docs/results/camera-phase/dev-phased-five-20260927-9/`
- `docs/results/camera-phase/dev-phased-scheduler-fault-20260927-1/`

每个目录包含可审阅 JSON 和 `raw-index.json`；索引记录原始文件路径、字节数与 SHA-256。
ULog、CSV、JSONL 和控制台原始日志没有提交到 Git。

但它足以否决在这台主机上继续进行要求实时性的正式对照实验。

## 后续建议

下一次工作应把性能问题作为独立实施包处理，并在任何策略训练之前完成。优先选择：

1. 将五路相机触发与证据记录移入同一原生 Gazebo/C++ 系统插件，避免 Python Transport
   回调与跨进程调度开销；接口仍输出同一不可变相位证据格式。
2. 在 Linux 原生 NVIDIA/Vulkan 或受支持的硬件渲染路径上复测，先用固定五机空任务证明
   RTF `>=0.95`，再恢复 PX4 起飞和正式实验。
3. 若单机主机仍不足，将渲染与五个 PX4 实例分离到可核验的多进程/多主机布局；保持同一
   仿真时钟和独立传感器信息边界。
4. 只有新的五机开发轮同时达到 RTF、`5/5` mission-ready、相位和清理门槛后，才从 smoke
   第 1 轮重新开始；不得复用本报告中的失败轮。
