## Interpreter context and prospective correction

[CPython dynload_shlib.c](https://github.com/python/cpython/blob/f6650f9ad73359051f3e558c2431a109bc016664/Python/dynload_shlib.c#L78) gets the current interpreter's dlopen flags, calls `dlopen`, then resolves the initializer with `dlsym`. [importdl.c](https://github.com/python/cpython/blob/f6650f9ad73359051f3e558c2431a109bc016664/Python/importdl.c#L144) calls the initializer and applies module checks; execution of module slots is a further stage. `pycore_import.h` chooses RTLD_NOW when available, otherwise LAZY; actual flags can be changed through sys.setdlopenflags, so source defaults do not attest actual runtime flags. `_json.c` exports the initializer and returns a module definition. This chain explains why standalone dependency enumeration and interpreter import/initialization are different evidence roles. No RTLD_GLOBAL change is proposed.

The new production design specifies a narrowly typed zero-direct-NEEDED Python-extension record instead of globally ignoring a line. It requires an independently known current interpreter/module origin, ABI identity, ET_DYN/PT_DYNAMIC/no-PT_INTERP facts, expected defined initializer, complete raw queries, stable pre/post inputs/tools, and exactly the known zero-dependency diagnostic. It retains every undefined symbol, selected dependency list genuinely empty, and explicit `runtime_import_verified=false` at static preparation. Missing context, nonzero NEEDED, malformed ELF, arbitrary empty output, extra diagnostic, unresolved ordinary dependencies or missing final coverage still refuse. Actual runtime mapping/module-origin checks remain mandatory separately at all original phases. See the new production spec/plan; no new source module, study or native attempt is frozen by this research.
